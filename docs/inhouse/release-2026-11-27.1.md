# 사내 Camera HAL 반입 · 11월 27일 개정판

첫 연동 가이드를 만들 때 설계 질문과 소스 발췌를 미리 작성하지 않아도 됩니다. 제품 소스와 빌드를 연결한 뒤 `generate --sections vendor-contract`를 실행하면, 생성기가 비어 있는 LLM 주제의 질문과 같은 커밋의 발췌를 준비합니다.

1. `camera-hal-sdd-inhouse-2026-11-27.1.zip`과 같은 이름의 `.sha256` 파일을 받아 체크섬을 확인하세요. 새 폴더에 압축을 풀고 `python tools/verify_import.py`로 파일을 검사합니다.
2. `START_PROMPT.txt`의 **문서 생성·번역 CLI** 입력란에 `hermes`, `opencode`, `claude`, `codex` 중 하나를 적고, 사내 경로와 승인 설정을 채워 에이전트에게 전달하세요. 이번 프롬프트는 새 템플릿의 `vendor-contract` 기본 주제로 첫 원고를 만들도록 바뀌었습니다.
3. [첫 실행 안내](02-first-run.md)에 따라 `generate --sections vendor-contract --plan-only`로 준비할 주제를 확인한 뒤 실제 생성을 실행하세요. 입력 준비에도 모델 호출이 필요하므로 `review.max_calls`와 `review.max_seconds`를 먼저 정합니다.

이번 ZIP에서 바뀐 점은 다음과 같습니다.

- `first_run_inputs: true`: 사내 템플릿의 기본값입니다. 근거를 지정하지 않은 LLM 주제에만 적용하며, 선택한 질문과 발췌는 `build/first-run-inputs.json`에 기록합니다. 기존 설정에서 직접 고른 근거와 고정 계약은 그대로 사용합니다.
- 단일 원고 실행: `--sections vendor-contract`로 생성하면 아직 만들지 않은 다른 페이지는 `build/document-health.md`에 남고, 전체 생성과 사이트 게시 단계에서 다시 검사합니다.
- 스킬 v16: 첫 실행 절차를 위 명령 하나로 시작하도록 바꿨습니다. v15의 [설계 이유 연결 절차](design-rationale.md)도 포함합니다.
- 첫 원고의 계약 대조: 첫 실행으로 만든 완료 주제와 요청 흐름·제출 실패 그림을 원문과 다시 대조합니다. 큐 수락과 함수 반환 시점, 상태별로 유효한 필드와 그렇지 않은 필드, 제출 시도와 성공을 구분하는지 검사합니다.
- 반입 ZIP 안의 문서 링크: 패키지에서 제외한 과거 실행 기록을 가리키는 링크를 같은 소스 커밋의 공개 저장소 주소로 바꿉니다. 바꾼 파일은 `IMPORT-MANIFEST.json`의 `pinned_public_links`에 있습니다.

생성된 질문과 발췌는 사내 파생물이므로 사내 설정 저장소에서만 관리하세요. 문서 생성 성공은 의미 승인이나 실기기 시험 결과가 아닙니다. 패키지 무결성과 공개 시험 결과는 첨부 파일 `release-validation.json`에서 확인할 수 있습니다. 공개 저장소 시험은 사내 HAL 검증을 대신하지 않습니다. [11월 27일 초판과 비교](https://github.com/TTolsun/camera-hal-sdd-generator/compare/inhouse-2026-11-27...inhouse-2026-11-27.1)
