# #141 구조 개선 검증 기록

설정 해석, 생성 판정과 실행, 비교·재생·과거 정책 호환의 책임을 분리합니다. 이 기록은 공개 입력을 이용한 생성기 검증이며 사내 HAL 검증이나 사람 승인이 아닙니다. #138의 복구 기능, #139의 의미 판정, #140의 무효화 정책과 #107은 변경 범위에서 제외합니다.

## 고정 기준과 진행 상황

- 기준 생성기: `45609e46c6d76806003e9dd75702a8b7ddab9e5e`입니다. 착수와 공유 파일 변경 전 최신 main 및 열린 생성기·공개 SDD PR을 확인했으며, 당시 열린 PR은 없었습니다.
- 전용 작업 트리의 구현 브랜치는 `codex/issue-141-structure`이며, 병합 후 공개 검증 기록은 `codex/issue-141-publication`에서 관리합니다. 다른 세션의 변경이나 미커밋 파일을 가져오지 않았습니다.
- Windows 로컬 검증은 uv 0.12.15, Python 3.14.7과 잠금 파일의 pytest 9.1.1·libclang 18.1.1을 사용합니다. 시스템 Python은 3.12.10입니다.
- 기본 uv 캐시 권한·네트워크 실패는 작업 트리 전용 캐시와 의존성 설치로 해결했습니다. 샌드박스는 테스트용 로컬 bare clone을 거부하므로 전체 회귀는 실행별 제한 해제와 독립 임시 경로를 사용합니다. 원래 SHA는 Git archive로 고정하여 검증합니다. 소스 수정과 겹친 중간 기준 실행은 기준 결과로 계산하지 않습니다.
- 착수 시 공식 libcamera HEAD는 `182307a772ebebf173ee84911906da707718485f`였으며, 재개 시 새 HEAD `e117198c015057761bb0bbaa85f963c41ce412d7`도 별도 추출했습니다. 공개 SDD `8f93666`의 입력 `2c4b67c0792f88f69bcdf9cbf73e81b3d8cf4b6f`와 고정 비교·새 upstream 검증을 구분합니다.
- 초기 실제 LLM 시험은 사용자 지시로 `sdd.claude.local.yaml`의 `cli/claude/claude-haiku-5-5`, `args: [--effort, high]`를 사용했습니다. 후속 지시로 신규 문서·번역·LLM 검토는 `gpt-6.1-terra`와 `model_reasoning_effort="high"`를 선택한 CLI로 실행하도록 전환합니다. 과거 기록과 공개 기본 Hermes/Qwen 프로필은 당시 값으로 보존합니다.

## 동작 보존 근거

수정 전 커밋 `1bc871d`에서 세 예제(libcamera, mini-hal, inhouse-template)의 snapshot 왕복, 지정 이름의 로컬 덮어쓰기, false·0·null과 상대 경로 계약을 고정했습니다. 네 전송 방식 × standard/focused의 요청 전체·검증 결과·resolved section·artifact·출처를 SHA-256으로 기록했습니다. 이 비교 경계에는 시간·실행 ID가 없으며 임의로 제외한 필드가 없습니다. 실제 LLM 문장에는 같은 바이트를 요구하지 않습니다.

기존 회귀는 검증 실패 시 전체 원고 보존, 사이트 stage 실패, 다른 커밋 혼합, 정책 불일치, 입력·출력·노드 한도, CLI 오류 전파, 재시도 수와 호출 순서, 손상 영수증·충돌·부분 응답, 기존 재개·이월과 사람 승인 대기를 검사합니다. 새 복구나 판정 정책을 추가하지 않습니다. grounding.py의 소스와 해시는 이동 전후 동일하며 HTTP 과거 별칭의 허용 범위를 넓히지 않습니다.

## 고정 공개 산출물 비교

공개 SDD `effdcbd558c244600c1d0c2c3d4df3c13a35fc8d`의 배포 입력을 복원했습니다. `qwen-full/publication`의 facts·원고에 `issue97`과 `issue107-partial`의 원고를 순서대로 겹치고, issue107의 sections·visuals·영어 카탈로그 및 기준 생성기의 확장 용어집을 사용했습니다. 이 조립은 기존 원고를 수정하거나 새 문장을 작성하지 않습니다. 보존된 그림 지문과 맞는 과거 Hermes 프로필은 렌더링 식별자로만 사용하며, 모델 호출은 예외로 차단했습니다. 실제 새 호출에 사용하는 Claude 프로필과 구분합니다.

기준 생성기 `45609e4`와 변경 후 `6c643b9`에서 같은 설정·facts·원고 입력을 사용하여 HTML 50개를 포함한 출력 154개의 바이트 해시가 모두 같았습니다. 두 사이트 모두 깨진 링크 0개와 manifest 검증 통과를 확인했습니다. 원고·정책·검증 판정·승인 상태를 바꾸지 않았습니다. 코드가 옮겨진 일곱 파일을 engine에 기록하므로 manifest의 build_id는 `405394c79b26f3d03ed376267ea5bd9b09c77106c423576c6f0d4a2ce65c802f`에서 `486697eb65fed14d25fc36fd40cde282b6bcf8b8a73f9e9204c9949ff5972855`로 달라집니다. 이 차이는 실행 코드 추적이며 원고 재생성 정책의 변경이 아닙니다.

구조 이동만으로 공개 HTML·자산 배포를 새로 만들 필요는 없습니다. 공식 upstream의 새 커밋에 필요한 갱신은 이 고정 비교의 동일성으로 대신하지 않고 별도로 검증합니다.

공식 upstream `182307a7`의 186-TU Meson 빌드에서 클래스 1,046개·시나리오 6개와 파싱 오류 0개를 확인했습니다. 이 중 64개 선언의 위치는 Git에 없는 Meson 생성 헤더였으므로, libcamera 예제의 기존 `source.exclude`에 `build/**`를 추가합니다. 공식 Git SHA를 가리키는 코드 링크를 지키기 위한 예제 입력 설정이며, 사내 HAL의 생성 파일을 공통 코드에서 일괄 제외하지 않습니다. 최종 공개 입력은 이 제외 설정으로 다시 추출·검증합니다.

같은 SHA·186-TU 빌드에서 제외 설정을 적용한 재추출은 클래스 982개, 함수 428개, 시나리오 6개, 파싱 오류 0개와 누락 진입점 0개를 기록했습니다. 선언·정의·호출·근거의 소스 위치 5,742개가 모두 공식 Git 트리의 파일 356개에 연결되며, 생성 헤더 클래스는 0개입니다. facts SHA-256은 `67759709917e681f60e0d3beb1ce33570b74ed6a8102137feb429211ccf9f894`입니다. IPU3·RKISP1·UVC·Virtual·VIMC 파이프라인과 IPU3·RKISP1·VIMC IPA의 빌드 범위이며 모든 플랫폼이나 장치 실행을 검증한 결과가 아닙니다. 생성 헤더를 제외한 입력에서 기존 원고 17개 섹션 중 Vendor 연동의 두 주제와 IPA의 한 주제는 재사용을 거절했습니다. 이 결과를 통과로 바꾸지 않고 지정 CLI의 새 생성 관문으로 남깁니다.

예제 입력 수정의 관련 회귀 35개와 [후속 PR #144](https://github.com/TTolsun/camera-hal-sdd-generator/pull/144)의 Windows·Ubuntu × Python 3.11·3.14 CI가 통과했습니다. 그 뒤 main에 병합된 #107의 예제 분량·번역 설정은 그대로 병합하여 보존했습니다. #107 원고 작업이나 미병합 #138~#140 구현은 가져오지 않았습니다.

실제 Claude CLI의 근거 검토 실패 기록도 기준 생성기와 변경 후 생성기에서 별도 재생했습니다. 요청·응답 해시, 호출 순서, 거부 메시지와 이전 원고 보존 결과가 같았습니다. 이 비교의 새 모델 호출은 0회이며 새 CLI 실행 성공으로 계산하지 않습니다. 실제 새 원고 시험의 형식·내용 검사 실패는 그대로 남깁니다. 새 표시 문구 번역은 지정 Claude CLI로 별도 실행했고 기존 번역 값을 보존했습니다.

## 병합 프로필과 최신 공개 기준의 추가 검증

`350a9d3`의 [병합 후 CI](https://github.com/TTolsun/camera-hal-sdd-generator/actions/runs/40537281645)에서 Windows·Ubuntu × Python 3.11·3.14 각각 1,761개 테스트 통과를 실제 로그로 확인했습니다. 이어 Ubuntu Python 3.14.4·libclang 18.1.1·GCC 15.2.0·Meson 1.10.1·Ninja 1.13.2 환경에서 같은 SHA의 실제 YAML을 읽어 186-TU 추출을 다시 실행했습니다. 제외 목록에 값을 수동으로 덧붙이지 않았고, `sdd.claude.local.yaml`의 CLI·모델·인자도 실제 로더로 확인했습니다. 추출은 모델을 호출하지 않습니다.

재추출은 클래스 982개·함수 428개·시나리오 6개·파싱 오류 0개를 기록했습니다. facts 해시는 `5ad04bcbc5e85f4969840242a105c8e30a3680090134e3dad355f1627ea5f466`이며, 앞선 `67759709…` 입력과의 모든 차이를 나열했을 때 `meta.generated_at` 하나만 달랐습니다. 두 생성기의 `src/sdd` Git 트리도 같습니다. 356개 Git blob을 직접 읽어 5,742개 위치의 줄 범위, 발췌 284개와 문맥 116개의 위치·본문·해시를 검증했습니다. 공식 HEAD와 공개 `upstream/master`의 소스 트리도 일치합니다. 원래 실패 시험의 facts는 바꾸지 않고, 새 추출본은 별도 파일로 보존했습니다.

다른 세션에서 공개한 PR #49 / `f57d9ec`의 IPA 모듈 검증·RKISP1 원고와 영어 카탈로그를 포함한 고정 비교도 수행했습니다. 원래 생성기 `45609e4`와 병합 생성기 `350a9d3`의 출력 154개가 모두 같았고, 해당 공개 산출물과도 같았습니다. 두 사이트는 HTML 50개·깨진 링크 0개로 검증을 통과했습니다. 엔진·입력 메타데이터의 build_id 차이와 출력 바이트의 동일성을 구분합니다. 최초의 `effdcbd5` / 후보 `6c643b9` 비교와는 별개의 실험이며, 둘 다 입력 소스는 `2c4b67c0`입니다. 새 upstream `182307a7`의 사이트 완료 근거로 대신하지 않습니다.

이 검증 묶음의 주요 완료 호출 기록 84개는 Vendor 시험 30개, IPA 첫 시험 9개, IPA 독립 재시험 37개와 번역 8개입니다. ## Terra 병합 후 실행 경계 검증

공통 Codex 지원 [PR #153](https://github.com/TTolsun/camera-hal-sdd-generator/pull/153)이 실제 main `572c55a7723cde52bc0de3a20d51a3b2302ec67e`로 병합된 뒤에만 전용 브랜치에 통합했습니다. 잠긴 의존성으로 환경을 동기화했으며, 이 기능이나 다른 세션의 의미 판정·재사용 변경을 #141의 점수에 가산하지 않습니다.

추가로 생성 실행의 체크포인트 식별자가 `cli_agent.arguments`를 직접 가져오던 책임을 `cli_checkpoint.execution_identity`로 옮겼습니다. runner·model·command·args·실제 인자의 기존 다섯 필드는 그대로입니다. 저장 schema·재개·재시도·호환 허용 목록을 바꾸지 않고, 생성 core와 순수 판정의 구체적인 `cli_agent`·`cli_schema` import를 금지합니다. 요청·답변·예산 처리 코드는 같은 경계를 사용합니다.

제품 코드를 옮기기 전에 실제 `_request_unit` 표현식에서 Hermes·Claude·OpenCode의 schema 유무 6개 식별자 해시를 고정하고, 변경 전 회귀 6개가 통과했습니다. 실제 병합된 `572c55a` 표현식으로 Codex 2개도 추가했습니다. 기존 여섯 기준은 바꾸지 않았습니다. `tests/fixtures/cli-execution-141.json`에 출처와 기준을 보존하며, 명시적 command 접두사·한글 인자와 schema 입력도 대조합니다. 실제 CLI나 모델을 호출하는 시험은 아닙니다.

책임 이동 전후의 검증 정책과 grounding 정책 해시는 완전히 같습니다. 첫 uv 실행은 sandbox 캐시 권한 오류로 Python 시작 전에 실패했고, 기존 `.venv`의 Python으로 명시적으로 실행한 변경 전 검사와 이동 후 생성·재개·CLI 회귀는 각각 6개와 262개 통과·2개 제외였습니다. 제외 항목은 Windows의 POSIX 시험과 이 환경에서 허용되지 않은 symlink 시험이며 통과로 계산하지 않습니다. Terra main 통합 후 고정 식별자·구조·의존성 51개도 통과했습니다. 추가 정책 호환 별칭이나 해시 고정은 사용하지 않았습니다.

실제 의존 검사 함수에 격리한 임시 소스의 CLI·schema import를 주입한 대조 70개는 직접·상대·별칭·함수 내부 형식을 모두 거절했습니다. 정상 core 대조와 순수 판정 모듈 3개는 통과했으며 운영 소스를 대조 목적으로 수정하지 않았습니다. 최신 전체 CI·최종 공개 생성과 배포는 각각의 관문으로 추가 확인합니다. 아래 다섯 항목의 점수는 91점을 유지하며, 이 작은 이동의 함수·파일·검사 수로 올리지 않습니다.

실제 로더에서 `cli / codex / gpt-6.1-terra / model_reasoning_effort="high"`를 확인하고, 이 구조 이동과 선택한 문맥을 실제 CLI로 한 차례 검토했습니다. 입력은 14,713자로 설정 한도 18,000자 이내였으며 [원본 요청·응답·stdout·영수증](https://github.com/TTolsun/libcamera-sdd/tree/a2c39c0a3f5af8e1969b528f71e4002e1a9b0957/publication/issue141/reviews/terra-checkpoint-boundary)을 보존했습니다. 제공 범위에서 수정할 결함은 없다는 결과이며 전체 저장소·순환 의존이나 사람 승인의 증거가 아닙니다. 실제 AST 검사와 네 환경 CI는 따로 확인합니다. 이 시점의 공개 증빙은 파일 해시 413개·완료 호출 86개이며, 앞선 주요 호출 84개·과거 제한 검토 1개·새 Terra 코드 검토 1개입니다. 코드 검토를 libcamera 최종 원고·번역·배포 성공으로 계산하지 않습니다.

## 위험과 복구

선택 기능의 검증은 기존 소비 시점에 유지하므로 사용하지 않는 옵션 때문에 새 명령 실패가 생기지 않게 합니다. 설정 객체는 현재 raw에서 만들어 시험 복사·로컬 덮어쓰기 뒤의 오래된 값 사용을 방지합니다. 지문 계산용 raw와 프로젝트 키는 손실 없이 보존합니다. 남은 위험은 기존 동적 프로젝트 schema와 공개 함수 import 호환에 있습니다.

복구는 마지막으로 함께 검증한 생성기 SHA·설정·facts·원고·사이트 묶음을 고정해 독립 체크아웃에서 확인합니다. 후속 병합이 분리된 모듈을 사용하므로 현재 main에서 PR #142만 단독 revert해도 안전하다고 보장하지 않습니다. 코드 되돌림은 의존 관계를 검토한 PR로 진행하며 다른 세션의 변경을 강제로 제거하지 않습니다. 공개 환경은 직전 정상 사이트를 유지합니다. 응답·영수증·원고를 수정하거나 정책 해시를 고정하여 통과시키지 않습니다. #141의 구조 이동 자체는 저장 schema와 grounding 정책 해시를 바꾸지 않으며 최신 upstream·후속 기능의 영향은 별도로 검사합니다.
