# Local Qwen 그림 자동화 검증

**2026-10-25에 공개 mini HAL과 Local Ollama의 `qwen3.5:9b`로 그림 초안 생성·검사·배치·변경 후 재생성을 시험했습니다.** 사내 HAL, 사내 게이트웨이 또는 카메라 실기기 시험은 아닙니다. 모델 digest는 `6488c96fa5faab64bb65cbd30d4289e20e6130ef535a93ef9a49f42eda893ea7`입니다.

## 재현과 증빙

```bash
python tools/evaluate_visuals.py --out <새 출력 경로> --model qwen3.5:9b
```

이 명령은 저장소와 Git 이력이 없는 반입 ZIP 모두에서 실행할 수 있습니다. 실제 모델이 있어야 하며 정답 그래프나 response-bundle을 공급하지 않습니다. 새 출력 경로에 다음을 남깁니다.

- `report.json`: 모델 정보, 단계별 명령·종료 코드, 두 소스 커밋·해시, 초안과 연결된 그림, 실제 HTTP 요청·응답 영수증입니다.
- `before/`, `after/`: 해당 커밋의 소스 원문, 원고와 사이트입니다.
- `project/build/prompts/calls/`: 재시도를 포함한 실제 원문 요청·응답·해시입니다. 최종 초안이 이 응답에 존재하는지 검사합니다.

공개 `RequestManager::onFrame`의 `ret == 0` 조건을 별도 시험 커밋에서 `ret >= 0`으로 바꿉니다. 실제 파일에서 발췌를 다시 수집하고 `impact` → `generate --from-impact` → `export-site` → `verify-site`를 수행합니다. 전체 Clang 추출이나 제품 빌드를 대신하는 시험이 아니며 발췌 기반 그림 기능을 분리해 검증합니다. libcamera upstream을 변경하지 않습니다.

반환 조건의 참 분기에서만 `sendResult`에 도달하며 `onFrameDone`은 참 분기 밖에서도 도달하는지 예제의 기대 관계와 대조합니다. 변경 후 입력 지문과 조건식이 달라지고 새 모델 응답이 사용돼야 합니다. 오래된 원고 게시가 실패하면서 기존 사이트를 보존하는지, 같은 입력의 사이트 재빌드가 같은지 검사합니다. 검사 결과는 의미 승인이나 사람 승인이 아닙니다.

## 실제 실패에서 보완한 부분

Qwen이 원문에 없는 반대 조건을 쓰거나 이전 조건을 레이블에 남기는 응답을 관찰했습니다. 생성기가 원문의 `if` 식을 복사하고 모델에는 `c0:true`·`c0:false` 같은 ID만 선택하게 했습니다. 비교식을 모델 레이블에 직접 넣으면 거절합니다. 잘못된 근거·노드 수·필수 심볼·용어 누락도 게시 전에 실패합니다.

실제 Ollama는 boolean `items`를 거절했고 배열 위치별 `prefixItems` 제약을 적용하지 않는 응답도 관찰했습니다. 필수 심볼 수가 노드 한도와 같은 질문은 생성기가 심볼과 ID를 연결한 객체를 요청하도록 바꿨습니다. 모델은 레이블과 구절·화살표를 작성하며, 원시 응답과 생성기가 붙인 심볼을 구분해 보관합니다. 노드 목록의 필수 함수 누락은 계속 검사합니다.

공개 libcamera의 `validate()` 그림에서는 Adjusted의 변경 가능성과 호출자 재확인을 빠뜨리는 초안을 관찰했습니다. PR84의 질문 분할·최소 답변 검사 방식을 참고해 그림에도 선택적 `answer_contract`를 적용했습니다. 재시도에는 이전 오답 전체를 주입하지 않고 오류와 원래 근거를 전달합니다. 모델이 계속 실패하면 직전 정상 원고를 보존합니다.

mini HAL의 자연어 답변 시험에서는 필수 완료 정리를 누락하는 Qwen 응답도 차단했습니다. 이를 통과한 원고로 보고하지 않습니다. 그림 재생성 시험은 동작 답변을 주장하지 않는 질문·소스 보기에서 수행합니다. 필수 설계 질문이나 독자 프로필이 있는 실제 사내 문서에서 이 보기로 답변 검사를 우회할 수 없습니다. 두 개요의 자연어 생성·전체 추출 갱신 시험은 [PR84의 별도 기록](../../libcamera/qwen-overviews.md)과 구분합니다.

## 사내 반입

[그림 자동화 릴리스](https://github.com/TTolsun/camera-hal-sdd-generator/releases/tag/inhouse-2026-10-25-visuals)의 ZIP·체크섬과 실제 반입본 시험 보고서를 함께 보관합니다. ZIP에는 생성기, 사내 질문 템플릿, 검증 도구와 가이드가 포함됩니다. 공개 모델의 결과로 사내 모델 검증을 완료했다고 기록하지 않습니다. 실제 HAL의 상태·소유권·실패 경로, 승인 모델·자산·코드 링크·게시 정책으로 다시 검증해야 합니다.
