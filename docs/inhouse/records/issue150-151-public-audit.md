## 소스 SHA와 입력·출력 지문

공개 다운로드 원고 23개는 모두 `2c4b67c0…`를 기록하며, manifest의 Markdown 입력 해시와 전부 일치합니다. 작성 실행·모델이 섞여 있다는 사실과 서로 다른 소스 SHA의 원고가 섞였다는 주장을 구분해야 합니다. 이 공개판에서 원고 간 SHA 혼합은 발견하지 않았습니다.

현재 공개 카탈로그 `publication/issue107-claude-part2/english.json`의 바이트 해시는 manifest 입력과 일치합니다. 언어 선택 컨트롤과 alternate 링크를 제거하여 복원한 한국어 HTML 25개의 지문도 카탈로그의 `pages`와 모두 일치합니다. 카탈로그에는 소스 SHA 필드가 없으므로, 한국어 페이지 지문과 manifest 입력 해시의 연결로 검증했습니다. 이것이 새 설정·새 소스에서의 재사용을 허용한다는 뜻은 아닙니다.

공개 저장소의 두 `facts.json`은 manifest가 기록한 facts 해시 `a8f2760f…`와 모두 다릅니다. 보관된 `qwen-full/publication/facts.json`의 해시는 `dc230198…`입니다. 해당 보관본의 소스 SHA와 available 발췌 258개는 불변 Git 원문·선택자·줄 위치·SHA-256과 일치하지만, **이 파일을 현재 사이트의 정확한 facts 입력이라고 증명할 수는 없습니다.** 입력이 손상됐다고 단정하지 않고 정확한 게시 입력 보관이 부족한 것으로 기록합니다.

같은 보관 facts에 현재 섹션 설정을 적용한 정적 비교에서는 기존 설계 원고 14개 중 12개의 페이지 입력 지문이 일치하지 않았습니다. `vendor-assurance`와 `rkisp1-dewarp`만 이 비교에서 일치했습니다. 실제 주제 재사용은 CLI·모델·프롬프트·정책까지 추가로 검사해야 하므로 두 문서의 현재 재사용 승인으로 해석하지 않습니다. 이 비교는 보관본과 현재 질문의 호환성 시험이며 과거 빌드의 완전 재현은 아닙니다.

## 번역과 알려진 설명 차이

공개 영어 HTML의 보호되지 않은 표시 문구에서 한글 잔존은 0건입니다. 코드·발췌·원문 다운로드·언어 선택기의 한국어 표시는 번역 누락으로 계산하지 않았습니다. 카탈로그의 모든 문자열과 실제 표시 쌍에서 자리표시자 누락·반복은 발견하지 않았습니다.

현재 `translation._validate_text`를 공개 카탈로그에 적용하면 고유 항목 7개가 의무 표현 규칙에서 거부됩니다. 이들은 첫 화면과 시나리오 6페이지에서 총 29회 표시됩니다. 1개는 사람 검토의 필요성을 `need`로 옮겼고, 나머지는 `확인해야 합니다`를 `check` 같은 명령문으로 옮겼습니다. 현재 규칙이 요구하는 `must/shall`이 없습니다. **이 7건을 모두 의미가 약화된 번역이라고 단정하지 않습니다.** 명령문의 의무 보존은 문맥 대조가 필요하며, 생성 담당의 새 번역·#139 검토에서 처리할 항목입니다. 규칙을 완화하거나 원고·영어 HTML을 직접 수정하지 않았습니다.

공개 `vendor-overview`에는 정지 시 모든 요청의 자동 완료가 보장된다는 표현이 남아 있고, `onboarding`에는 마지막 버퍼가 끝나도 요청이 자동 완료되지 않으며 `completeRequest()`가 필요하다는 설명이 남아 있습니다. 영어에도 두 표현이 각각 보존돼 있습니다. 앞의 소스 주석은 `queueRequest()`의 추적과 `stop()` 조건을, 뒤는 `completeBuffer()` 뒤 명시적인 요청 완료 책임을 설명합니다. 조건이 달라 양립할 수 있으므로 문장 일부만으로 확정 모순으로 분류하지 않았습니다. 조건·주체·시점을 보존한 최종 한영 감사는 #139 담당 결과에 의존합니다.

별도로 공개 `request-lifecycle`의 ‘완료 뒤 요청 접근 금지’는 영어의 `must not`으로, 요청 취소 분기와 `cancelled_`는 `cancelled`로 대응합니다. 이 표본 대조와 구문 검사는 전체 번역의 의미 승인이나 신규 CLI 감사가 아닙니다.
