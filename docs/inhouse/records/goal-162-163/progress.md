## #162 원인과 개입

과거 실패 run `fc12d1843abd4aa4910ebc9bbe1a43b2`의 불변 호출 아카이브 `9d77b48dbb8642cf9f254e165a669dea`를 대조했습니다. 014번 crop 첫 응답은 두 좌표 경로만 설명했습니다. 015번 LLM 근거 대조가 앞선 update·활성화·색온도 반환 조건의 누락을 지적했습니다. 016번 재시도는 그 조건과 커널 플래그까지 다시 썼고, 앞의 disabled-no-update 설명과 중복되어 반려됐습니다. 초회 요청에는 앞 답변을 전달하지 않으며 재시도에는 거절된 답과 오류가 전달됩니다. 이 사례에서는 LLM 근거 대조의 조건 요구와 좁은 질문 사이의 불일치가 재시도 중복을 유발했습니다. 모든 신규 실패의 단일 원인으로 일반화하지 않습니다.

최신 main 신규 3회에서 crop 자체의 최종 실패는 재현되지 않았습니다. 과거 실제 중복 응답은 현재 판정에서도 거절되는 원본 회귀로 고정했습니다. 최초 crop 답변과 최종 재시도 결과를 혼동하지 않습니다.

crop의 질문은 앞선 반환을 통과해 좌표 설정에 도달한 경우로 한정합니다. 전용 좌표 발췌는 두 대입 경로를 모두 포함하고, 전체 prepare 함수 문맥·해시도 함께 제공합니다. 조기 반환을 소스 문맥에서 숨기지 않습니다. 실제 식·조건·필수 용어와 인용을 보존하며 답변 원고를 설정에 넣지 않습니다.

신규 시험은 LSC 공통 호출 인자의 별도 문장들이 보수적인 중복 검사에 걸리는 추가 오탐을 드러냈습니다. 관측한 문장 형태를 좁게 인식하는 두 판정 시안도 독립 표본으로 시험했으나, 추가 표현과 호출자 근거 경계를 확인한 뒤 최종 구현에서 제거했습니다. 최종 판정기는 착수 main과 같습니다. 세 인자를 한 호출의 한 질문으로 묶어 순서를 보존하고, 세 실제 코드 표현을 각각 필수 용어로 검사합니다. 이는 질문·근거 개입이며 동일 질문의 코드 효과로 보고하지 않습니다.

## #163 고정 비교와 구현

여섯 경로와 대표 절·과업은 [독자 평가 절차](reader-protocol.md)에 개선 전 고정했습니다. overview의 과업은 실제 기준 페이지에 있는 요청 소유권·재사용으로 정정한 뒤 사람 평가를 시작하지 않은 상태로 고정했습니다. 작성 맥락 없는 자동 평가의 다섯 목표와 두 페이지 그룹은 기존 #107과 같습니다. 초기 캡처와 SVG 렌더 완료를 기다린 고정 캡처를 구분해 보존하며 최종 전후 비교는 같은 렌더 완료 기준을 사용합니다.

공개 vendor-integration의 명시 완료 호출 의무 중복과 configure 추가 검증 금지의 인접 반복을 확인했습니다. 완료 사실·의무를 한 질문으로 묶고, 사용자 정의 필드 질문은 검증된 입력 전제를 유지하면서 앞 의무 전체를 반복하지 않도록 합니다. 제품 개요의 기기별 문제와 계층 설명, 벤치마크 측정 경계, 요청 재사용 질문은 쉬운 동작 설명에서 기술 이름·정확한 조건으로 연결하도록 보완합니다.

제목에 `절을 확인합니다`만 붙이던 공통 시나리오 안내는 해당 절의 첫 설명 문장에서 얻습니다. 코드·표·숨긴 근거·제목만 반복한 문구에서는 안내를 만들지 않으며, backtick·tilde fence 안의 가짜 제목과 들여쓴 코드도 제외합니다. 기존 명시 routes·앵커·제목 검증 기능을 대체하지 않습니다.
