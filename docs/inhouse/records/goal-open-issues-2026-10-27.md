## 검증과 공개 반영 장부

구현·회귀·실제 신규 CLI·검증된 재사용·중단 복구·최신 upstream·공개 배포를 별도 집계합니다. 아직 새 원고·PR·병합·배포를 완료하지 않았습니다. `sdd accept`를 자동으로 기록하지 않습니다.

- 기본 Python에는 pytest가 없습니다. 작업 트리 안에 독립 uv 환경을 준비하고 있습니다. 기본 sandbox의 패키지 다운로드는 DNS 제한으로 실패했으며 권한이 허용된 동일 설치 경로로 재시도합니다.
- WSL은 기본 sandbox에서 접근이 거절되어 승인된 실행으로 읽었습니다. 기존 다른 세션의 작업본은 변경하지 않습니다.
- 사용자의 후속 지시에 따라 이번 신규 생성·번역·LLM 검토는 Claude CLI `claude-haiku-5-5`, `--effort high`로 전환했습니다. 실행별 `build/goal/claude-profile/sdd.claude.local.yaml`에 설정했습니다. 공개 기본 Hermes 프로필은 보존합니다. Claude Code 버전은 `2.1.284`입니다.
- 전환 시 Hermes 기준 시험을 중단했습니다. `vendor-integration`의 생성 호출 1회(54.313초)는 완료됐으나 문서는 미완료이며 성공률에 섞지 않습니다. 새 프로필로 개선 전후 시험을 다시 수행합니다.
- 착수 기준 전체 회귀: **1,720 passed, 2 skipped**, 945.67초입니다. 별도 권한 환경에서 실행했으며 기본 sandbox 실패와 구분합니다.
- CLI 항목 재개·손상·입력/정책 변경·예산 소진 fixture 회귀는 15개가 통과했습니다. 관련 생성/영향 분석/출처 회귀는 단계별 로그로 보존하며 최종 전체 회귀는 별도로 수행합니다.
- Claude CLI가 schema를 프롬프트로만 받던 경로에 native `--json-schema`와 `structured_output` 처리를 추가했습니다. 짧은 실제 호출이 성공했고 실제 인자/모델 영수증은 `build/goal/native-schema-smoke/`에 있습니다. 문서 생성 성공으로 계산하지 않습니다.
- 고정 입력 기준 시험은 `build/goal/claude-baseline-six*`, 대표 3문서×3회는 `claude-baseline-nine*`에 기록합니다. 초기 개선 시험 `claude-improved-six*`는 native schema 연결 전의 탐색 실행이며 최종 개선 후 시험과 구분합니다. 실패 실행을 삭제하거나 마지막 성공만 보고하지 않습니다.

## 2026-10-28 중간 검증 (미완료)

생성기 [PR #143](https://github.com/TTolsun/camera-hal-sdd-generator/pull/143)의 첫 HEAD는 `12f7c95487e53f03e5a414a3f8f5c173e4736d3e`이며 Windows/Ubuntu와 Python 3.11/3.14의 CI 네 조합을 통과했습니다. 이후 실제 CLI에서 발견한 Windows 작업 폴더 잠금, 재시도 영수증 연결, 국소 정책 재검증과 번역·계약 대조 연결을 추가 수정 중입니다. 아직 병합·공개 배포하지 않았습니다.

- 고정 입력 신규 생성 비교는 캐시를 분리했습니다. 기존 대표 3문서×3회는 **0/9**, native schema 적용 HEAD는 **3/9**입니다. 호출은 **100→184회**, 재시도 포함 시간은 **1,447.218→3,820.595초**입니다. 성공률 개선과 함께 긴 문서의 비용 증가·남은 실패도 그대로 기록합니다. 과거 실패 6문서 기준은 **0/6, 61회, 1,391.672초**, 초기 탐색 개선도 **0/6, 74회, 1,501.704초**였습니다. 최종 질문·근거 보완 후 공개 후보 생성은 별도로 집계합니다.
- 실제 CLI 중단 복구 시험은 onboarding의 앞 2/5개 검증 항목 뒤, CLI 호출 사이에 의도적으로 예외를 발생시켜 중단했습니다. 실제 CLI 프로세스를 죽인 시험과 구분합니다. 체크포인트 비활성은 중단+재개 **15회·421.984초**, 활성은 **11회·346.251초**입니다. 이미 통과한 두 항목의 불필요한 재호출은 **4→0회**, 활성 상태의 다음 반복은 **0회·9.359초**였습니다. 비활성 다음 반복은 중복 검증 실패로 기존 성공 출력을 보존했습니다. 이 표본 하나를 전체 성공률로 일반화하지 않습니다.
- 공개 소스 기반 계약 사례는 게시 원고와 분리한 **12사례·15주장**입니다. 첫 완료 검토는 13/15 정답·오탐 1건이었고, 생략된 조건을 무조건적 주장으로 해석하지 않도록 수정한 검토는 **15/15**, 중요 모순 **6/6 검출**, **누락 0·오탐 0·예상 미판정 2건**입니다. 실제 배포 후보의 한영 전체 계약 대조는 아직 남아 있습니다.
- 최신 공식 upstream `182307a772ebebf173ee84911906da707718485f`를 별도 소스에서 Clang으로 빌드하고 **178 TU, parse error 0**으로 추출했습니다. **1,017 classes, 5,279 citations/359 files**, 필수 클래스·위치·모든 설계 근거 preflight 검사를 통과했습니다. GCC compile DB와 libclang의 진단 차이로 실패한 첫 시도도 보존합니다.
- 추가 전체 회귀는 **1,753 passed, 2 skipped**, 1,955.55초입니다. 그 뒤의 작은 수정은 별도 집중 회귀와 갱신된 CI로 확인합니다. 사람 검토 시간은 측정하지 않았고 `sdd accept` 기록을 만들지 않았습니다.
- 재생성된 onboarding·vendor-overview는 통과했습니다. overview의 실제 중복은 질문·발췌 범위를 분리 중이며, vendor-integration에서는 서로 다른 함수의 ‘구현자는’ 주체를 구별하지 못한 결정적 중복 검사 오탐을 수정 중입니다. 원고·HTML은 직접 수정하지 않습니다.

다음 필수 단계는 정책별 실제 비용 비교, 최신 upstream 변경의 영향 분석·생성, 나머지 후보 검증·한영 계약 대조, 생성기 최종 리뷰·병합, 공개 SDD PR·Pages 배포·공개 build_id 검증입니다. 이슈 4개는 아직 열려 있으며 #141은 계속 제외합니다.
