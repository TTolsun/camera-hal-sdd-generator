## 원래 90건의 대응과 실제 문장 수정

원래 보고서 SHA-256은 `20138dc3c37721047cd2d721566fda81b2f7c0eb7082f27350c33b66fcc29785`, 장부가 참조한 완료 보고서는 `53282e8bc2430f873a0faf34e0055c570f31e0a5c9052977e6c2489dcbb558a4`입니다. 둘 다 이전 독립 스냅샷의 실제 바이트와 일치합니다. 병합된 [90건 장부](goal-138-140/terra-uncertain-90-resolution.json)의 원래 `(contract, claim_id)` 집합은 원본 미판정 집합과 정확히 같고, 90건 중 중복·누락은 없습니다. 원래 문장·판정·이유도 보존됐습니다.

각 대응의 최종 문장·판정·인용 근거·이유는 해당 완료 보고서와 정확히 같습니다. 90건 모두 그 보고서에서 `compatible`로 판정됐습니다. 원래 문장이 모두 옳았다는 소급 판정은 아닙니다. 초기 분류는 직접 근거 공급 누락 73건, 근거·범위 재검토 15건, 같은 한영 부정 조건 누락 2건입니다. 접근 주체 오류도 재검토 과정에서 실제 문장 수정으로 처리됐습니다.

장부에는 한 원래 항목에 여러 그룹의 후속 판정이 연결될 수 있어 최종 연결은 128개입니다. 120개는 같은 ID, 6개는 보존된 표시 문장의 `origin_claims`로 연결됩니다. 나머지 한영 2개는 `cancel-access` 질문을 `handler-access`에 합친 명시적 설정 변경으로 확인했습니다. 두 질문의 직접 근거 합집합은 그대로 유지되고, 새 계약에는 `completeRequest`, `cancelRequest`, 접근, 파이프라인 핸들러를 요구합니다. 질문 삭제로 의무를 없앤 것이 아닙니다. 기존 콜백 주장 ID 87개도 최종 제품 계약·분석 표현 그룹의 합집합에 모두 남아 있습니다.

| 실제 수정 | 독립 대조 |
|---|---|
| `request-diagnosis.md`의 `pending-head` | `ASSERT(!req->hasPendingBuffers());`를 한영 실제 표시 문장에 보존합니다. 불변 e117 소스의 `pipeline_handler.cpp:597`과 같습니다. 조사 계획을 실행 보장으로 바꾸지 않습니다. |
| `request-lifecycle.md`의 `handler-access` | 반환 후 접근 금지의 주체를 파이프라인 핸들러로 한정합니다. 취소 뒤 완료와 같은 규칙을 적용하며, 애플리케이션을 포함한 모든 호출자에게 금지를 확대하지 않습니다. 영어도 `The pipeline handler must not access`로 같은 주체와 금지를 보존합니다. |

두 수정의 원본 생성·근거 검토 CLI 기록 4건을 검증했습니다. 현재 원고 답변과 체크포인트 문장이 같고, 원본 생성 응답의 문장과도 같습니다. 두 변경의 번역 기록 2건도 원본 요청 텍스트·응답 값이 현재 카탈로그와 정확히 같습니다. 모두 독립 Codex CLI, `gpt-6.1-terra`, `model_reasoning_effort="high"`의 인자·schema·원시 완료 stdout·요청/응답 해시를 병합된 검증기로 확인했습니다. 저장 응답을 신규 호출로 계산하지 않았습니다.

## 정책·회귀·현재 재감사 경계

[PR #154](https://github.com/TTolsun/camera-hal-sdd-generator/pull/154)는 `ee776c82cfb336b6b4cb2cc36fcd34ea81d7528f`로 병합됐습니다. 해당 head의 PR·push 네 환경 CI 8개는 모두 성공했습니다. 이 세션에서도 병합된 코드의 의미·직접 근거·분석 정의·CLI 회귀 51개가 통과했습니다.

고정 사례 최종 기록의 실제 CLI 영수증 21개를 독립 확인했습니다. 원시 판정 27개는 기대 판정과 모두 같고, 모순 10개를 모두 탐지했습니다. 정상 13개, 근거 부족 3개, 모호함 1개도 그대로 보존합니다. 제품 계약을 분석 정의만으로 확정하거나 분석 표현의 직접 정의 없이 확정하는 경로는 결정적 검사로 거부합니다. 이는 검사 완화를 정당화하는 점수가 아니라, 해당 경계·부정·주체·의무를 확인한 제한된 회귀 증거입니다.

실행 환경도 구분했습니다. 이 감사 작업 트리의 `consistency.py`는 LF, 생성 담당의 실행 바이트는 CRLF이며, 새 두 보조 모듈은 양쪽 모두 LF입니다. 원시 정책 지문은 각각 `da05cc10…`, `89c9b2af…`로 다릅니다. 담당의 Python 모듈 96개 모두를 병합 Git blob과 줄바꿈 정규화 후 대조해 일치시킨 뒤, 실제 실행 바이트를 별도 읽기 전용 감사 사본으로 보존했습니다. 정책 함수를 상수로 바꾸거나 지문·검사를 고정하지 않았습니다. 앞선 Python 3.12/3.14 AST 차이도 계속 별도 환경 경계로 둡니다.

병합 후 전체 문서 재사용에서 답변 주제의 저장 순서가 바뀌어, 동일 내용의 의미 감사 요청·schema 순서가 달라지는 문제가 재현됐습니다. 담당도 이를 확인하고 [PR #158](https://github.com/TTolsun/camera-hal-sdd-generator/pull/158)에서 수정 중입니다. 문서 생성의 신규 호출 0회와 전체 의미 감사의 신규 호출 0회는 다릅니다. 담당 기록의 추가 완료 21회·진행 중 1회는 보존하며, 후자를 완료·실패로 추정하지 않습니다. 진행 중인 부분 보고서를 최종 실패·통과로 판정하거나 기존 완료 장부의 SHA와 혼동하지 않습니다. 새 정책을 병합하면 원본 완료 기록을 연결한 전체 감사와 실제 재사용을 다시 확인해야 합니다.
