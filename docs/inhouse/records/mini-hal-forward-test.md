# 새 에이전트의 공개 mini HAL 작성 시험

**2026-10-24에 기존 답안을 주지 않은 새 에이전트가 설정부터 계약 작성·검증까지 수행했습니다.** 최초 결과를 독립 평가하고, 실제로 막힌 부분을 생성기와 가이드에서 고친 뒤 다른 새 에이전트로 재검토했습니다. 사내 HAL 적용이나 실제 독자의 이해도를 검증한 기록은 아닙니다.

**역할 과제 10개 중 8개를 충족했지만 전체 내용 통과에는 미달했습니다.** 자동 검사에서 질문이 모두 `documented`여도 의미와 충분성을 별도로 대조해야 했습니다.

| 결과 | 확인한 증거 |
|---|---|
| 환경·추출 | 원시 소스의 Android.mk와 stubs로 파싱 DB를 작성했습니다. 6 TU·6 시나리오, 파싱 오류와 진입점 누락은 0개였습니다. 제품 빌드는 수행하지 않았습니다. |
| 계약·사이트 | 두 독자의 질문 10개, HTML 13개를 생성했습니다. 독립 평가에서 발췌 51건의 내용·줄·해시, 산출물 109개 해시와 로컬 링크가 일치했습니다. |

## 확인한 문제와 수정

| 관찰한 문제 | 수정한 원본 |

| 긴 질문을 제목과 탐색 표에서 반복하고 교차 링크가 페이지 맨 위로 갔습니다. | 빈 템플릿의 제목을 짧게 바꾸고 행동형 routes와 절 앵커 사용을 안내했습니다. |

영향 분석 회귀는 같은 합성 SAT 반환값 변경(`-1`→`-2`)으로 기존 스냅샷과 수정본을 비교했습니다. overview의 watch는 헤더·빌드 파일만 유지했습니다. 두 생성기 모두 이전 근거 해시를 차단했지만, 설명을 수정한 뒤 기존 생성기는 개요 이월에 실패했고 수정본은 정상 재개했습니다. 수정본의 원고 12개는 모두 대상 커밋 `3537f7ae2a96b5592356554cef25da125be0445d`와 일치했습니다.

## 재평가와 적용 범위

**독립 재평가에서 열 과제가 모두 충족됐고 최초 R1~R6가 해결됐습니다.** 소스 정확성, 역할별 답변·탐색, 상세 설명의 분담과 검증 상태 구분이라는 내용 기준에서는 비교한 공개 libcamera 문서 수준을 재현했습니다.

- 발췌 참조 123건(고유 39개), HTML의 로컬 링크 573개, 산출물 109개와 보관한 생성기 파일 92개의 지문을 독립 대조해 불일치가 없었습니다. 필수 질문 10개는 모두 `documented`이며 사람 검토는 `pending`입니다.
- 최종 generate·audit-docs·export-site·verify-site가 통과했고 두 manifest가 같습니다. HTML은 13개, 깨진 링크는 0개입니다. 원시 소스와 최초 결과의 지문도 유지됐습니다.
- 루트 에이전트가 최종 사이트를 직접 열어 390px 화면의 가로 넘침 없음, 모바일 메뉴·역할 이동·검색·절 이동·근거 펼치기, 그림 Enter/Space 열기·요소 검색·확대·Escape 초점 복귀를 확인했습니다. 의도적인 자산 로딩 실패는 재현하지 않았습니다.
- 남은 P0·P1은 없습니다. 비차단 P2는 절마다 7~18개의 근거 링크가 표시되는 읽기 부담 1건입니다. 필요한 근거는 유지하되 표시를 묶거나 접는 후속 화면 개선 후보로 남겼습니다. 실제 독자의 읽기 속도·이해율은 측정하지 않았습니다.

기록 위치는 로컬 `build/forward-test-20261024/`의 `project-a`, `project-b`, `impact-retest`, `browser-final`과 `build/forward-review-20261024/`입니다. 임시 산출물은 Git에 배포하지 않으며, 이 문서에는 공개 입력의 방법·결과·한계를 보존합니다. 재시험하려면 위 입력 격리 조건으로 새 출력 폴더를 만들고 [전체 가이드](../agent.md)를 수행한 뒤 같은 열 과제를 평가합니다.

시험 중 별도 작업의 생성기 변경이 main에 병합되어 함께 통합했습니다. 재시험의 최종 명령은 통합된 생성기에서 실행했습니다. 중간 병합 충돌 상태에서 한 번 발생한 CLI SyntaxError는 정상 코드로 재실행했으며 계약 작성 실패와 구분했습니다.

이 시험은 설치된 의존성과 공개 파싱 스텁이 있는 한 가지 환경의 사례입니다. 폐쇄망 설치, 실제 제품 compile DB·ABI·헤더·드라이버·기기, 사내 게시와 사람 승인은 검증하지 않았습니다. 실제 ADHD 독자의 이해도도 측정하지 않았습니다. 다른 HAL에 적용할 때는 [전체 실행 절차](../agent.md)와 [역할별 읽기 검증](../../concepts/reader-quality.md#역할별-읽기-검증)을 해당 소스로 다시 수행해야 합니다.
