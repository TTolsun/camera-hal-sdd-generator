# 실제 한영 감사 미판정 90건의 원인 조사

미판정 수 자체는 기존 게시 계약의 차단 조건이 아니다. 확정 모순, 현재 입력·정책·영수증 불일치는 게시를 차단하며 미판정과 `human_review: pending`은 보존한다. 그러나 이번 90건을 모두 무해한 것으로 취급하지 않는다. 원래 보고서·28원고·영문 카탈로그·facts·질문을 `uncertain90-before`에 복사해 보존하고 각 판정의 원문·이유·직접 근거·누락 근거를 기록했다.

구조적 1차 분류는 직접 근거 공급 누락 73건, 추가 범위 검토 15건, 실제 부정 조건 누락 2건이다. 이는 판정 변경이나 최종 해소 수치가 아니다. 추가 15건 중 12건은 표시 문단에 합쳐진 다른 설명의 직접 근거를 감사가 전달하지 않았고, 나머지 3건은 시나리오의 분석 표기·한계를 설명하는 동일 문단과 한영 표시다. 실제 미판정 이유와 근거를 대조해 후속 감사를 진행한다.

`consistency.request()`는 직접 근거를 모은 뒤 계약별 선택 목록이 있으면 이를 빈 사전으로 대체했다. 선택 근거를 직접 근거에 추가하도록 고치고, 실제 한영 표시 문단에는 합쳐진 모든 설명의 직접 근거를 연결한다. 시나리오의 기존 코드 인용도 같은 소스·파일·줄을 포함하는 검증된 문맥과 연결한다. 동일한 커밋·파일·줄·원문·해시의 발췌만 공유하고 별칭은 보고서에 남긴다.

배치마다 대상 설명과 모든 주 문서 설명·직접 근거, 선택된 공통 근거를 유지한다. 실제 CLI 프롬프트에는 전체 원문·위치·주장·근거 관계를 그대로 전달한다. 선택 정규식이나 이미 로컬에서 대조한 해시 같은 비의미 메타데이터는 바인딩된 보고서에 보존한다. schema까지 포함한 실제 프롬프트 길이로 배치를 분할하며, 한 대상과 완전한 주 문맥도 40,000자에 들어가지 않으면 실패한다. 원문이나 주장을 잘라 통과시키지 않는다. 현재 후보 입력 사전 검사는 303주장·76배치, 각 그룹 최대 39,989/39,792/37,404/39,744자였다. 후속 원고 수정에 따라 실제 배치 수를 다시 측정한다.

두 모호 판정은 `request-diagnosis/diagnosis/pending-head`의 같은 한영 설명에서 `ASSERT(!req->hasPendingBuffers())`의 부정을 생략한 실제 문제다. 정확한 단언 식과 검사 조건을 묻고 원문의 코드 조건을 필수 용어로 두어, 선택된 Terra High CLI로 재생성·재번역한다. 원고·HTML을 직접 수정하거나 판정 상태를 수동으로 바꾸지 않는다.

호출 집계에서도 설계 생성 691회 외에 리뷰어용 `change_impact` 호출 1회가 있었다. 이 호출은 생성 예산과 원고 보존 경계 뒤에서 실행되므로, 변경 영향 요약을 기존 `impact.json`·facts의 결정적 사실 요약으로 구성하도록 수정했다. CLI·schema 1을 유지하고 불필요한 보조 LLM 호출을 제거한다. 완전 캐시 재개가 추가 모델 호출 없이 같은 비교 SHA·영향 섹션을 보고하는 실제 CLI 회귀와 기존 예산 소진 회귀 2개가 통과했다. 과거 실제 1회는 삭제하거나 전송 확인 호출로 재분류하지 않는다.

독립 감사 #155의 후보와 당시 main 간 두 정책 차이는 통합 브랜치의 같은 Python 실행기에서 재대조했을 때 0이었다. #156의 Python AST 표현 차이도 별도 환경 차이로 기록하고, 정책 해시를 고정하거나 검사를 생략하지 않는다. 최종 main·Python 버전·정책 지문으로 게시 관문을 다시 확인한다. 모든 결과는 자동 검증이며 사람 승인이나 사내 HAL 검증이 아니다.
