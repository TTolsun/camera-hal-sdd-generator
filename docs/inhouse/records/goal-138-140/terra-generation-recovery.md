# 최신 upstream의 Terra 신규 생성과 실패 복구

공개 upstream `e117198c015057761bb0bbaa85f963c41ce412d7`의 동일한 전체 facts와 명시적 Codex CLI/Terra High 프로필로 전체 문서 생성을 실행했다. 초기 전체 실행은 **19개 문서 중 13개 통과·6개 실패**, **626회 실제 CLI 호출**, **2946.500초**였으며 재시도를 포함한다. 문서별 검증은 통과했어도 전체 생성이 실패했으므로 공개 생성 성공으로 집계하지 않는다. 실패한 응답과 성공한 검증 단위 체크포인트를 보존했다. 과거 Claude/Hermes 또는 고정 SHA 시험과 이 수치를 합산하지 않는다.

초기 실패는 다음과 같이 구분한다.

| 문서 | 실패 원인 | 수정 |
| --- | --- | --- |
| vendor-assurance | 실행 절차 답변이 앞의 측정 범위를 반복 | 질문을 측정 경계와 실행 환경·도구로 구분한다. 답 문장을 설정에 넣지 않는다. |
| ipa | 송신 메시지와 map 반복자의 역할 혼동 | 송신·실패 처리 질문과 응답 대기·완료·시간 초과 질문을 분리한다. |
| ipu3-lsc-flow | 서로 다른 실제 호출 인자를 같은 사실로 판단 | 완전한 단일 인자 설명에 한해 양쪽 실제 인용의 동일 호출·인자 순서·값을 대조한다. |
| ipu3-lsc-prepare | 한글 `거짓`과 영문 `false`를 달리 읽어 다른 분기를 중복으로 판단 | 명확한 한글 불리언 서술을 정규화한다. 참고·참조·부정 문장은 값으로 해석하지 않는다. |
| camera-model | 정지 설명이 동시성 절의 호출자 의무까지 반복 | 정지 질문의 범위를 오류·상태 전이·취소·완료로 한정한다. 동기화 의무는 기존 동시성 질문에서 유지한다. |
| camera-requests | 조건 없는 동일 `-EINVAL` 문단이 서로 다른 검사에 반복 | 네 분기의 조건 질문과 반환값 질문을 각각 결합한다. 원래 근거와 필수 조건·코드는 유지한다. |

중복 판정의 내용어 겹침 기준 0.7과 최소 공유 내용어 6개는 유지한다. 검증되지 않은 식별자 추가, 다른 인자 순서·값, 주석·문자열의 호출, 모호한 표현, 근거 변조, 여러 사실을 섞은 문단은 새 예외로 통과시키지 않는다. 결정적 검증 코드 변경은 실제 정책 해시를 변경하므로 재개 때 현재 정책으로 체크포인트를 다시 검증한다. 정책 해시 고정, 재시도 확대, 실패 원고의 수동 수정은 하지 않는다.

관련 중복 회귀는 **157 passed**였다. 원고 생성·계약·재사용·근거 정책을 포함한 집중 실행은 **424 passed**였다(일부 테스트 파일이 명령에 두 번 포함되었으므로 고유 테스트 수나 독립 시험 수로 해석하지 않는다). 신규 전체 생성 성공률과 체크포인트 재개 성공률은 별도로 기록하며, 후속 재개·번역·전체 한영 계약 검토·공개 배포가 끝나기 전에는 Goal과 초기 이슈를 완료하지 않는다.
