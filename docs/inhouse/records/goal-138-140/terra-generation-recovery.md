# 최신 upstream의 Terra 신규 생성과 실패 복구

공개 upstream `e117198c015057761bb0bbaa85f963c41ce412d7`의 동일한 전체 facts와 명시적 Codex CLI/Terra High 프로필로 전체 문서 생성을 실행했다. 초기 전체 실행은 **19개 문서 중 13개 통과·6개 실패**, **626회 실제 CLI 호출**, **2946.500초**였으며 재시도를 포함한다. 문서별 검증은 통과했어도 전체 생성이 실패했으므로 공개 생성 성공으로 집계하지 않는다. 실패한 응답과 성공한 검증 단위 체크포인트를 보존했다. 과거 Claude/Hermes 또는 고정 SHA 시험과 이 수치를 합산하지 않는다.

초기 실패는 다음과 같이 구분한다.

| 문서 | 실패 원인 | 수정 |
| --- | --- | --- |

| ipu3-lsc-flow | 서로 다른 실제 호출 인자를 같은 사실로 판단 | 완전한 단일 인자 설명에 한해 양쪽 실제 인용의 동일 호출·인자 순서·값을 대조한다. |

중복 판정의 내용어 겹침 기준 0.7과 최소 공유 내용어 6개는 유지한다. 검증되지 않은 식별자 추가, 다른 인자 순서·값, 주석·문자열의 호출, 모호한 표현, 근거 변조, 여러 사실을 섞은 문단은 새 예외로 통과시키지 않는다. 결정적 검증 코드 변경은 실제 정책 해시를 변경하므로 재개 때 현재 정책으로 체크포인트를 다시 검증한다. 정책 해시 고정, 재시도 확대, 실패 원고의 수동 수정은 하지 않는다.

관련 중복 회귀는 **157 passed**였다. 원고 생성·계약·재사용·근거 정책을 포함한 집중 실행은 **424 passed**였다(일부 테스트 파일이 명령에 두 번 포함되었으므로 고유 테스트 수나 독립 시험 수로 해석하지 않는다). 신규 전체 생성 성공률과 체크포인트 재개 성공률은 별도로 기록하며, 후속 재개·번역·전체 한영 계약 검토·공개 배포가 끝나기 전에는 Goal과 초기 이슈를 완료하지 않는다.

보존한 실제 Terra 응답 네 쌍을 원본 영수증·high 인자·소스 인용까지 확인한 결정적 비교에서 이전 검사는 4/4를 오탐했고 수정 검사는 0/4를 오탐했다. 이는 신규 LLM 호출 0회의 과거 실패 응답 재평가이며 생성 성공이나 체크포인트 재사용으로 집계하지 않는다. 별도의 자동 Terra 코드 검토는 공개 커밋의 GitHub blob 3개를 확인한 후 1회·24.078초 동안 실행했다. 같은 멤버의 앞 값을 뒤 값으로 덮어쓰면 반복된 조건을 숨길 수 있다는 지적을 반영해, 서로 다른 값이나 모호한 재언급은 문단 차이의 증거로 사용하지 않게 했다. 추가 회귀를 포함해 **161 passed**를 확인했다. 자동 검토는 사람 승인이 아니다.

첫 재개에서는 앞의 실패 다섯 문서가 통과한 뒤 LSC의 두 색온도 검사에 반복된 공통 전제가 추가 중복으로 검출되었다. 검사 예외를 넓히는 대신, 원래 색온도와 양자화 색온도 검사를 하나의 순서 질문으로 결합했다. 두 근거와 네 필수 용어·각 경계 조건을 유지하고 공통 전제는 한 번만 설명하도록 한다. 이 입력 변경도 새 질문으로 기록하며 원래 질문의 신규 성공률에 합산하지 않는다.

첫 재개는 **18/19 문서 통과**, **38회 새 CLI 호출**, **265.578초**, **286개 검증 단위 재사용·17개 신규 생성**이었다. 두 번째 재개는 **19/19 문서 통과**, **27회 새 CLI 호출**, **228.375초**, **302개 검증 단위 재사용·12개 신규 생성**으로 전체 원고 저장까지 성공했다. 두 번째 재사용률은 302/314이며, 이 실행을 캐시 없는 신규 생성 19/19 성공으로 표현하지 않는다. 처음 전체 실행과 두 재개의 합은 **691회 완료 호출·3440.453초**이다. 별도의 초기 schema 전송 실패 3건, 중단 시 완료 여부가 확정되지 않은 시작 기록 2건 및 준비 실패도 원본에 보존하며 이 합의 신규 성공에 포함하지 않는다. 따라서 이 실행 시간 합을 준비·수정까지 포함한 전체 작업 벽시계 시간으로 해석하지 않는다.

실패한 두 전체 실행 전후에는 기존 원고 28개 파일의 해시가 모두 같았다. 성공 후 번역 준비에서 새 원고의 미정의 RAW 용어가 검출되어 게시가 중단되었다. 공개 `stream.cpp`와 `formats.cpp`를 같은 Terra High CLI로 읽어 RAW 색 인코딩과 `Raw` 스트림 역할을 구분하는 용어 설명을 생성·검토했다. 최초의 역할 한정 정의와 보조 스크립트 실패도 보존한다. 최종 정의는 모델 응답을 수정하지 않고 예제 용어집에 반영했으며, **용어집 회귀 19 passed**를 확인했다. 자동 검토와 용어 설명 추가는 사람 승인이 아니다.

질문 수정 효과와 코드 효과를 섞지 않기 위해, 최종 질문·동일 e117 facts·같은 Terra High 프로필·예산·재시도로 원래 코드와 수정 코드를 각각 독립 신규 생성하는 추가 비교도 수행한다. 짧은 IPA 검증 문서와 두 LSC 문서를 각 3회 실행한다. 회차별 입력 지문·facts 해시·설정 해시·예산을 대조하고, 신규 실패도 원인과 함께 그대로 보고한다. 캐시 없는 시험과 위의 복구 실행은 별도 분모를 사용한다.

추가 비교의 결과는 **개선 전 5/9 → 개선 후 8/9**, 최초 시도 통과는 **3/9 → 3/9**였다. 새 호출은 **143 → 162회**, 누적 시험 실행 시간은 **844.016 → 973.719초**였으며 캐시 재사용은 양쪽 모두 0이다. 실패한 실행은 일찍 중단하므로 이 시간으로 전체 처리 속도 향상을 주장하지 않는다. 단계별 stdout 생성~마지막 기록의 벽시계 관측과 각 회차의 동일 입력 대조는 `terra-controlled-comparison.json`에 보존했다. 개선 후 남은 1건은 crop 질문에서 모델이 앞의 조건을 반복해 올바르게 거부된 경우다. 별도 동일 입력 재개에서는 앞 6개 검증 단위의 불필요 호출 없이 14회 새 호출·7개 신규 단위로 문서 검증·저장을 마쳤다. 고립된 시험 구성에 다른 문서가 없어 전체 CLI의 문서 수명주기 검사는 47건으로 실패했으므로, 이를 전체 CLI 통과로 보고하지 않는다. 실제 전체 공개 후보의 19/19 생성 통과와 구분한다.

영문 준비는 30쪽·1733문자열이며 이번에 새 문자열 200개를 번역했다. 첫 실제 전체 한영 감사는 53개 배치를 새 CLI로 검토한 후 정식 전체 감사에서 53개를 재사용했다. 세 그룹은 통과했지만 소유권 그룹에서 같은 메타데이터 초기화 호출의 두 언어 설명을 모순으로 판정해 게시를 차단했다. 소스의 `_d()->metadata_.clear()`와 함수 문맥에서 줄인 `metadata_.clear()`가 같은 객체·효과임을 확인했다. 명확히 동일한 객체의 수신자 약칭과 실제 다른 객체·멤버·효과를 구분하는 의미 정책을 추가했다. 새 정책은 정책 해시를 실제로 바꾸며, 전체 배치를 다시 검토한다. 확장한 실제 CLI 시험은 **15사례·20주장 모두 정확**, 중요 모순 **8/8**, 누락·오탐 **0**, 근거 부족·모호 **2**였고 원본 영수증의 high 인자까지 대조했다. 의미 정책 회귀 **17 passed**를 확인했다. 자동 미판정과 사람 검토 전 상태는 유지한다.

실제 실패 한영 문장 쌍, 명시적으로 다른 Request 객체, 다른 멤버 동작, 수신자 연결을 확인할 수 없는 외부 호출을 추가한 최종 사례 시험은 **19사례·25주장 모두 정확**, 중요 모순 **10/10**, 누락·오탐 **0**, 정상 **12**, 미판정 **3**이었다. 단순 식별자 접미사 일치로 다른 객체를 동일시하지 않는 음성 사례도 실제 선택 CLI로 검증했다. 원래 실패 보고서는 보존했다.
