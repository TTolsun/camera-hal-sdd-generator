# 4단계: 사람이 할 일

**`sdd update`가 2나 3으로 멈추면 이 문서의 해당 절을 따르세요.** 판단을 마친 뒤 같은 `sdd update` 명령을 다시 실행하면 멈춘 커밋부터 이어갑니다. 항목 하나에 5~15분 정도 걸립니다.

```
1단계 준비물 → 2단계 첫 실행 → 3단계 갱신 시스템 → [4단계 사람 검토]
```

승인은 `sdd accept`가 장부(`<sdd_dir>/approvals.json`)에 기록할 때만 성립합니다. 자동 검사의 `ok`·`mapped`·`documented`와 LLM 판정은 승인이 아닙니다.

## 범위 검토 항목 (종료 코드 2)

바뀐 파일의 클래스·함수를 다루는 문서가 없다는 뜻입니다. `build/impact-review.md`를 엽니다.

| 보고서의 절 | 뜻 | 할 일 |
|---|---|---|
| 검토할 변경 (미결) | 사람이 판단해야 할 항목. "LLM 판정" 줄이 있으면 참고합니다. | 아래 세 가지 중 하나를 고릅니다. |
| 자동 분류한 변경 | 주석·공백·`#include`만 바뀌었고 구조도 같은 항목, 분석한 빌드에서 컴파일되지 않는 파일, 설계 근거가 파일 전체를 고정한 파일, 또는 효과가 분석한 빌드에서 모두 검사된 빌드 파일. | 없음. 관문에 걸리지 않습니다. 설계 근거로 분류된 파일은 그 문서의 설명을 검토할 때 함께 봅니다. |
| 파일 감시와 수동 검토 연결 | 어떤 문서가 이 파일을 감시하는지. | 판단할 때 참고합니다. |

미결 항목마다 하나를 고릅니다.

1. **문서 범위 밖이 맞다** (예: 빌드하지 않는 코드, 문서와 무관한 도구):

   ```bash
   uv run sdd --config ../hal-sdd-project/sdd.yaml accept --finding "<보고서의 장부 키>"
   ```

2. **문서가 다뤄야 한다**: `config/sections.yaml`에서 알맞은 섹션의 `facts.classes`·`facts.functions` 패턴을 넓힙니다. 구성 요소 색인이 있으면 대부분 이 경우가 생기지 않습니다. 튜닝·설정 파일처럼 코드가 아닌 파일은 그 내용을 설명하는 설계 항목을 추가하고, 파일 전체를 근거로 고정합니다([설계 설명을 쓰거나 다시 검토하기](#설계-설명을-쓰거나-다시-검토하기)).
3. **아직 모르겠다**: `--defer`를 붙여 확인했다는 기록만 남깁니다. 관문은 계속 막습니다.

## needs-review 원고 (종료 코드 3)

자동 검사(인용·문장·근거)를 통과하지 못한 원고가 있다는 뜻입니다.

1. 원고 맨 아래 "근거와 검토 정보"에서 이유를 읽습니다.
2. 원인이 설정(빠진 클래스, 바뀐 근거)이면 설정을 고치고 `sdd generate --sections <id>`로 다시 만듭니다.
3. 내용을 읽고 그대로 받아들일 수 있으면 승인합니다.

   ```bash
   uv run sdd --config ../hal-sdd-project/sdd.yaml accept <원고 경로>
   ```

승인은 본문 해시에 붙습니다. 본문이 한 글자라도 바뀌면 다시 "사람 검토 전"이 됩니다. 인용만 재검증해 다음 커밋으로 넘어간 원고(본문 동일)는 승인이 유지됩니다.

## LLM 판정 기록 대조 (pass_gate를 켠 경우)

`review.coverage_triage.pass_gate: true`이면 "범위 밖" 판정이 사람 없이 관문을 통과시킵니다. 주 1회 정도 `build/coverage-triage.json`의 `out-of-scope` 판정을 훑어보고, 틀린 판정이 있으면 해당 섹션의 범위를 넓힙니다. 소형 모델은 이름이 비슷한 다른 기능과 헷갈리기 쉽습니다.

## 설계 설명을 쓰거나 다시 검토하기

클래스 표로 드러나지 않는 계약(책임·상태·소유권·종료·스레드)은 사람 또는 사내 에이전트가 소스와 대조해 작성합니다. 작성·발췌 고정·근거 변경 재검토 절차는 [소스에서 계약 작성하기](contract-authoring.md)를 따릅니다.

검토자는 질문의 답변과 인용 원문을 읽고 조건·예외·소유권·비동기 경계가 맞는지 판단합니다. 에이전트가 남긴 역할별 과제 답변과 미확인 사항도 확인합니다. `documented`는 근거 연결 상태이며 의미가 맞다는 승인이 아닙니다.
