# 사내 Camera HAL 반입 · 11월 27일

생성 문서가 "무엇을 하는가"에서 멈추지 않도록, 코드를 만든 커밋 메시지와 Gerrit 리뷰 코멘트를 설계 이유의 근거로 연결할 수 있습니다.

1. `camera-hal-sdd-inhouse-2026-11-27.zip`과 같은 이름의 `.sha256` 파일을 받아 체크섬을 확인하세요. 새 폴더에 압축을 풀고 `python tools/verify_import.py`로 파일을 검사합니다.
2. `START_PROMPT.txt`의 **문서 생성·번역 CLI** 입력란에 `hermes`, `opencode`, `claude`, `codex` 중 하나를 적고, 사내 경로와 승인 설정을 채워 에이전트에게 전달하세요.
3. 계약을 작성한 섹션 하나를 골라 [설계 이유를 근거로 연결하기](design-rationale.md)의 0단계 시작 조건부터 확인하세요. 소스 체크아웃이 shallow clone이 아닌지, 병합 커밋에 `Change-Id` trailer가 남는지가 핵심입니다.

이번 ZIP에 새로 들어간 기능은 다음과 같습니다.

- `sdd history-candidates`: 설계 주제의 소스 발췌를 바꾼 커밋과 현재 줄의 출처 커밋을 찾아 후보 목록을 만듭니다. 설정·facts를 바꾸지 않고 모델도 부르지 않습니다.
- `kind: commit` 근거: 커밋 메시지의 한 구간을 근거로 고정합니다. facts 커밋의 이력에 있는 커밋만 인정합니다.
- `sdd import-reviews`와 `kind: review` 근거: 사람이 저장한 Gerrit REST 응답을 스냅숏으로 가져와 코멘트 한 구간을 근거로 고정합니다. 생성기는 Gerrit에 접속하지 않으며, 같은 Change-Id로 병합된 커밋이 있어야 합니다.
- 스킬 v15: 위 절차를 작업표에 추가했습니다.

리뷰 스냅숏과 후보 파일은 사내 파생물이므로 사내 설정 저장소에서만 관리하세요. 패키지 무결성과 공개 mini HAL 시험 결과는 첨부 파일 `release-validation.json`에서 확인할 수 있습니다. 공개 저장소 시험은 사내 HAL·사내 Gerrit 검증을 대신하지 않습니다. [11월 23일 개정판과 비교](https://github.com/TTolsun/camera-hal-sdd-generator/compare/inhouse-2026-11-23.1...inhouse-2026-11-27)
