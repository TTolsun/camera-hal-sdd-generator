# 1단계: 준비물 모으기

**아래 체크리스트 다섯 묶음을 채우세요.** 다 모이면 [2단계: 첫 실행](02-first-run.md)으로 넘어갑니다. 모으는 데 반나절 정도 걸립니다(권한 신청이 필요하면 더 걸립니다).

```
[1단계 준비물] → 2단계 첫 실행 → 3단계 갱신 시스템 → 4단계 사람 검토
```

**이 절차는 아직 사내 HAL에서 실행되지 않았습니다.** 공개 libcamera와 `tests/test_ndk_hal3.py`의 재현 시험으로 확인한 내용입니다. 실행하면서 어긋난 부분을 이 문서들에 고쳐 넣어 주세요.

## 체크리스트

| 묶음 | 준비할 것 | 확인 방법 |
|---|---|---|
| 1. 소스 | HAL 저장소의 **분석 전용 체크아웃**과 시작할 커밋 SHA | `git -C <체크아웃> rev-parse HEAD` |
| 2. 빌드 | 제품 빌드와 같은 NDK(r25 이상), `ndk-build`가 PATH에 있음, 빌드 중 생성되는 헤더(있다면 한 번 빌드해 둠), AOSP 헤더(`hardware/camera3.h` 등) | `ndk-build --version` |
| 3. 실행 환경 | Python 3.11 이상, `uv`, 생성기 저장소 체크아웃 | `uv sync --extra dev` 성공 |
| 4. 모델 (선택) | 사내 LLM 엔드포인트 주소·모델 이름, 토큰을 담을 환경 변수 | 없어도 됩니다. facts 기반 문서는 모델 없이 만듭니다. |
| 5. 게시와 사람 | 사이트를 올릴 위치(웹 서버 경로나 문서 저장소), 쓰기 권한, 문서를 승인할 검토자 | 게시 위치에 파일을 한 번 올려 봅니다. |

분석 전용 체크아웃이 따로 필요한 이유: `sdd update`는 커밋마다 소스를 체크아웃합니다. 개발자가 작업 중인 폴더를 쓰면 작업이 사라질 수 있습니다.

## 빌드가 꼭 필요한가

필요하지 않습니다. 생성기는 바이너리가 아니라 **컴파일 명령(compile DB)과 헤더**만 씁니다.

- `ndk-build compile_commands.json`은 컴파일하지 않고 DB만 만듭니다.
- 다만 빌드 중에 만들어지는 헤더가 있으면, 그 헤더를 만드는 단계까지는 한 번 실행해야 합니다. 헤더가 없으면 파싱 오류로 멈춥니다.

## 사내에서만 확인할 수 있는 위험

1. **clang 버전**: 생성기의 libclang은 18.1.1입니다. 사내 NDK clang과 주 버전이 크게 다르면 파싱 오류가 날 수 있습니다.
2. **빌드 변형**: 제품마다 `-D`가 다르면 문서는 DB를 만든 변형 하나만 설명합니다. 변형마다 설정 디렉터리를 따로 둡니다.
3. **모델 품질**: 공개 libcamera에서 4B·9B 모델 모두 의미 오류가 있었습니다([모델 비교](../libcamera/records/model-comparison.md)). 모델 설명은 사람 검토 전 초안으로 다룹니다.
4. **반출 금지**: 사내 소스에서 나온 facts·원고·프롬프트·로그는 공개 저장소에 올리지 않습니다. `.gitignore`는 반출 방지 장치가 아닙니다.
