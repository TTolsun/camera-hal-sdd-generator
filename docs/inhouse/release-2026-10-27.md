## 기존 반입본에서 유지하는 주요 기능

### CLI 실행과 실패 복구

- 실제 CLI 전체 파이프라인 시험과 호출 출처 검사를 보강했습니다. 불완전한 최종 CLI 단계와 서로 충돌하는 출처 표시는 실패합니다(#98, #112).
- CLI 근거 대조에 출력 schema를 전달하고 기존 HTTP 기록의 호환성을 보존했습니다(#119). 근거 대조 JSON 형식 오류는 기존 재시도 한도 안에서 같은 후보를 다시 대조합니다(#129). 근거 불일치 판정을 형식 오류로 취급하지 않습니다.
- 승인 장부와 갱신 상태를 원자적으로 기록하도록 개선했습니다(#99, #108). 상태 파일을 삭제해 실패를 숨기지 않으며 기존 복구 절차를 유지합니다.
- Agent 교체 계약과 기능 메타데이터를 정리하고, 시험 준비·호출 기록 로딩·번역 검사·렌더링·독자 보완 판단의 중복 책임을 분리했습니다(#100~104, #113~117).

### 추출과 사내 게시

- Clang 추출의 소스 범위를 실행마다 분리해 다른 프로젝트의 범위가 섞이지 않게 했습니다(#105, #109).
- Gerrit Markdown 게시 예제에서 수동 문서와 승인 장부를 보존하고, 관리 manifest가 소유한 파일만 갱신하도록 했습니다(#106, #110). 로컬 Git 시험 결과이며 실제 사내 Gerrit 인증·훅·승인 정책은 별도 확인해야 합니다.
- 게시 시 파일 충돌, 경로 이탈, 기존 staged 변경과 해시 불일치를 거절합니다. push 실패 후 로컬 commit이 남은 상태는 원격 게시 성공으로 보고하지 않습니다. 상세 계약은 [Gerrit 게시 안내](gerrit-markdown-publication.md)에 있습니다.

### 문서 품질과 설정

- 신규 답변에서 같은 근거로 반복하는 문장을 반려합니다. 기존 설계 원고의 게시 검증에서는 반복을 경고로 보고합니다. 질문 문형이 섞인 답변을 검사하고, 이동 대상 제목 누락을 실패로 처리합니다. 문단은 최대 4문장·480자로 묶으며 문장별 근거 기록을 보존합니다(#111, #118).
- `impact --config-changes`로 소스 변경 없이 설계 질문·근거 지정이 바뀐 섹션도 재생성 대상으로 찾습니다. `statement_kind`와 타팀 독자 프로필을 지원합니다. 저장소 문서·빌드 설정을 근거로 쓰는 공개 예제를 확장했습니다(#118, #120).
- 기존 원고의 문단 형식, 원래 HTTP 근거, 구별되는 주장과 인용을 유지하는 검사를 보강했습니다(#121~124). 과거 HTTP 기록은 CLI 실행 성공 증거로 바뀌지 않습니다.
- 한국어 본문에 섞인 한자·일본어·키릴·아랍·태국 문자를 검사합니다(#126, #136). 코드 표기 밖의 설명을 검사하며 영어 혼입과 문장 의미 전체를 보증하지 않습니다. 불완전한 코드 표기 오류에는 수정에 필요한 진단을 제공합니다(#127).
- 공개 libcamera의 새 Hermes/Qwen 생성·번역·검토 프로필은 `qwen3.5:9b-ctx64k`와 `--reasoning high`입니다(#125). 사내 모델을 이 값으로 고정하지 않습니다.
- 공개 예제의 allocator 오류·수명 설명에서 `EBUSY`의 대상과 반환값을 명확하게 했습니다(#128). 이 libcamera 계약을 사내 HAL 계약으로 복사하지 않습니다.

### 사이트 탐색

- 문서를 독자 → 수행할 작업 → 문서 순서로 배치하고 allocator·IPA 진단·LSC 참조의 분류를 조정했습니다(#130, #132).
- 사이드바 너비를 드래그로 바꾸고 본문을 다시 줄바꿈할 수 있습니다(#131). 마우스·키보드 초점 표시를 개선했고(#133), 문서 이동 때 사이드바 스크롤 위치를 보존합니다(#134).
- HTML을 직접 고치지 않습니다. 사내 `sections.yaml`의 `group`·`nav_section`을 실제 독자 작업에 맞게 지정한 뒤 생성기에서 다시 빌드합니다.

| 모델 | 기본 Hermes CLI를 설치하고 승인된 제공자·모델·인증을 설정합니다. 선택하면 OpenCode 또는 Claude Code를 독립 실행합니다. 생성기 실행 에이전트와 문장 생성 CLI가 모두 사내 코드를 다룰 수 있도록 허용됐는지 확인합니다. |

| 게시·승인 | 사내 전용 설정·문서·로그 경로, 게시 대상, 검토 책임자, 접근 권한, 백업·복구 위치를 정합니다. 공개 `libcamera-sdd`에는 사내 파생물을 보내지 않습니다. |

설정의 빈 계약은 실제 소스를 읽어 채워야 합니다. `design_requirements`, `design_topics`, 질문·`covers`·근거 소스와 `generation: llm` 그림 계획을 작성합니다. 답변이나 노드·화살표를 미리 정답으로 넣어 모델 실행을 대신하지 않습니다. Vendor의 제품 이해·연동·검증과 Developer의 진입점·요청 흐름·진단·변경 후 확인을 각각 설계합니다.

## 설치와 최초 실행

1. 릴리스 ZIP과 `.sha256`을 승인된 경로로 반입하고 SHA-256을 대조합니다. 깨끗한 디렉터리에 압축을 풉니다. 설치나 수정 전에 생성기 루트에서 `python tools/verify_import.py`를 실행해 종료 코드 0과 `source_commit`·`verified_files`를 기록합니다.
2. [패키지 설치 절차](package.md#반입-확인과-설치)에 따라 wheelhouse와 별도 가상 환경을 준비합니다. `<PY> -m pip install --no-index --find-links ../wheelhouse -r requirements-inhouse.txt`로 설치합니다. `<PY>`는 해당 가상 환경의 Python 경로입니다.
3. `examples/inhouse-template/`을 생성기 밖의 사내 프로젝트로 복사하고 소스·빌드·코드 링크·모델을 설정합니다. NDK-build가 아니면 `source.ndk_build.enabled: false`로 바꾸고 제품의 DB 생성 절차를 사용합니다. `agent.kind: cli`, `agent.runner: hermes`가 기본입니다. 실행기를 바꾸면 모델 ID와 `args`도 그 CLI에 맞춥니다.
4. 생성기 루트에서 `<PY> tools/run_sdd.py --config <CFG> <명령>` 형식으로 `doctor` → `extract` → 계약 작성 → `generate` → `audit-docs`를 실행합니다. Mermaid를 준비한 뒤 `export-site` → `verify-site`를 수행합니다. `<CFG>`는 사내 설정의 절대 경로입니다.
5. 반복 빌드, 별도 소스 변경 후 증분 생성, 실패 시 직전 원고·사이트 보존, 수정 후 재개를 시험합니다. 독자 과제·화면 동작과 실제 내용의 의미를 검토한 뒤 허용된 사내 게시 대상으로 배포합니다. `verify-publication --url <사내 URL> --site <로컬 사이트>`로 원격 해시를 대조합니다.

CLI가 없거나 실패하면 해당 단계에서 중단하고 원인을 해결합니다. 다른 CLI, 모델 API 직접 호출, 저장 응답이나 수동 원고로 대체해 CLI 시험 성공으로 보고하지 않습니다. `doctor`는 실행 파일·버전 확인이며 모델 호출 검증이 아닙니다. 새 실제 호출의 receipt와 종료 코드를 남겨야 합니다.

## 업그레이드·운영·복구

기존 생성기를 덮어쓰기 전에 설정·원고·facts·호출 기록·상태·승인 장부를 함께 백업하세요. 새 반입본은 별도 디렉터리에서 검증하고 사내 설정의 공용 자산 경로를 확인합니다. 새 검사에서 이전 원고가 실패하면 원고나 해시를 손으로 고치지 않고 실패 사유에 맞춰 설정·생성기를 수정하고 재생성합니다.

`impact --config-changes`는 질문·근거 변경에 필요한 재생성 범위를 확인할 때 사용합니다. 실행 인자와 종료 코드는 [CLI 참조](../reference/cli.md)를 따릅니다. facts와 원고의 커밋 불일치·노드 한도·필수 근거 누락을 우회하지 않습니다. `update`의 범위 검토(2)와 원고 검토(3)는 성공(0)과 구분합니다.

사람의 승인은 `sdd accept`의 실제 기록만 인정합니다. 게시 전 조직 정책에 맞춰 `site.require_approval: true`를 적용합니다. 자동 검사의 `ok`, LLM 판정과 에이전트 검토는 사람 승인이나 실기기 검증이 아닙니다. 승인 장부를 복사해 새 본문을 승인한 것으로 처리하지 않습니다.

기존 버전으로 복구할 때는 생성기만 되돌리지 말고 그 버전과 맞는 설정·원고·facts·상태·승인 장부와 마지막 정상 사이트를 복원합니다. 실패 로그와 신규 산출물을 따로 보존하고 [문제 해결](troubleshooting.md)에서 실패 단계부터 재개합니다. 같은 설정을 동시에 실행하지 않습니다.

사내 예약 운영은 `automate`를 수동으로 검증한 뒤 조직이 허용한 CI·cron에 설치합니다. 이번 릴리스는 예약을 설치하지 않으며 공개 libcamera에 정기 예약을 만들지 않습니다.

## 검증 증거와 완료 범위

기능 기준 `5987a8c`의 [CI 40433730797](https://github.com/TTolsun/camera-hal-sdd-generator/actions/runs/40433730797)는 성공했습니다. 개정 반입 ZIP의 기준 SHA·재현성·무결성·실행 검사와 문서 PR의 CI는 첨부 `release-validation.json`에 기록합니다. 이번 패키징에서 새 LLM 생성 시험이나 독립 독자 평가를 수행했다고 주장하지 않습니다.

공개 SDD [PR #48](https://github.com/TTolsun/libcamera-sdd/pull/48)이 `effdcbd558c244600c1d0c2c3d4df3c13a35fc8d`에 병합됐고 Pages 빌드는 `built`입니다. 기존 배포와 달리 새 독자 문서 4편과 영어 카탈로그가 반영됐습니다. 확인한 공개 URL·manifest·대표 파일 해시는 검증 JSON에 남깁니다. 이 문서 개정 자체는 공개 원고·사이트 출력을 바꾸지 않으므로 별도의 빈 배포 커밋은 만들지 않습니다.

공식 upstream은 공개 사이트의 분석 커밋보다 앞서 있습니다. 이 릴리스는 최신 생성기 반입과 공개 시험 결과의 정리이며, 새 upstream 소스의 추출·영향 분석·문서 갱신 완료를 뜻하지 않습니다.

사내 적용 인수에는 실제 제품 추출, 승인된 CLI·모델의 신규 호출, 문서 의미·독립 읽기 평가, 화면 조작, 실패 복구, 사내 원격 게시와 사람 승인이 추가로 필요합니다. 실제 카메라 동작·성능은 별도 실기기 시험입니다. `handoff.md`에 각 단계의 입력 SHA, 명령·종료 코드, 보고서·해시, 담당자와 미완료 단계를 남기세요.

다음 단계는 [반입 패키지 시작 안내](package.md)의 시작 프롬프트를 실행하는 것입니다.


첨부 ZIP과 체크섬을 함께 받으세요. `START_PROMPT.txt`는 반입본 시작 프롬프트이며 `release-validation.json`은 이번 검증 결과입니다.
