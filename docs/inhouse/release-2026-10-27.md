- 같은 근거로 반복하는 문장과 질문 문형이 섞인 답변을 검사하고, 이동 대상 제목 누락을 실패로 처리합니다. 문단은 최대 4문장·480자로 묶으며 문장별 근거 기록을 보존합니다(#111, #118).

## 설치와 최초 실행

1. 릴리스 ZIP과 `.sha256`을 승인된 경로로 반입하고 SHA-256을 대조합니다. 깨끗한 디렉터리에 압축을 풉니다. 설치나 수정 전에 생성기 루트에서 `python tools/verify_import.py`를 실행해 종료 코드 0과 `source_commit`·`verified_files`를 기록합니다.
2. [패키지 설치 절차](package.md#반입-확인과-설치)에 따라 wheelhouse와 별도 가상 환경을 준비합니다. `<PY> -m pip install --no-index --find-links ../wheelhouse -r requirements-inhouse.txt`로 설치합니다. `<PY>`는 해당 가상 환경의 Python 경로입니다.
3. `examples/inhouse-template/`을 생성기 밖의 사내 프로젝트로 복사하고 소스·빌드·코드 링크·모델을 설정합니다. NDK-build가 아니면 `source.ndk_build.enabled: false`로 바꾸고 제품의 DB 생성 절차를 사용합니다. `agent.kind: cli`, `agent.runner: hermes`가 기본입니다. 실행기를 바꾸면 모델 ID와 `args`도 그 CLI에 맞춥니다.
4. 생성기 루트에서 `<PY> tools/run_sdd.py --config <CFG> <명령>` 형식으로 `doctor` → `extract` → 계약 작성 → `generate` → `audit-docs`를 실행합니다. Mermaid를 준비한 뒤 `export-site` → `verify-site`를 수행합니다. `<CFG>`는 사내 설정의 절대 경로입니다.
5. 반복 빌드, 별도 소스 변경 후 증분 생성, 실패 시 직전 원고·사이트 보존, 수정 후 재개를 시험합니다. 독자 과제·화면 동작과 실제 내용의 의미를 검토한 뒤 허용된 사내 게시 대상으로 배포합니다. `verify-publication --url <사내 URL> --site <로컬 사이트>`로 원격 해시를 대조합니다.

CLI가 없거나 실패하면 해당 단계에서 중단하고 원인을 해결합니다. 다른 CLI, 모델 API 직접 호출, 저장 응답이나 수동 원고로 대체해 CLI 시험 성공으로 보고하지 않습니다. `doctor`는 실행 파일·버전 확인이며 모델 호출 검증이 아닙니다. 새 실제 호출의 receipt와 종료 코드를 남겨야 합니다.

## 업그레이드·운영·복구

기존 생성기를 덮어쓰기 전에 설정·원고·facts·호출 기록·상태·승인 장부를 함께 백업하세요. 새 반입본은 별도 디렉터리에서 검증하고 사내 설정의 공용 자산 경로를 확인합니다. 새 검사에서 이전 원고가 실패하면 원고나 해시를 손으로 고치지 않고 실패 사유에 맞춰 설정·생성기를 수정하고 재생성합니다.

`impact --config-changes`는 질문·근거 변경에 필요한 재생성 범위를 확인할 때 사용합니다. 실행 인자와 종료 코드는 [CLI 참조](../reference/cli.md)를 따릅니다. facts와 원고의 커밋 불일치·노드 한도·필수 근거 누락을 우회하지 않습니다. `update`의 범위 검토(2)와 원고 검토(3)는 성공(0)과 구분합니다.

사람의 승인은 `sdd accept`의 실제 기록만 인정합니다. 게시 전 조직 정책에 맞춰 `site.require_approval: true`를 적용합니다. 자동 검사의 `ok`, LLM 판정과 에이전트 검토는 사람 승인이나 실기기 검증이 아닙니다. 승인 장부를 복사해 새 본문을 승인한 것으로 처리하지 않습니다.

기존 버전으로 복구할 때는 생성기만 되돌리지 말고 그 버전과 맞는 설정·원고·facts·상태·승인 장부와 마지막 정상 사이트를 복원합니다. 실패 로그와 신규 산출물을 따로 보존하고 [문제 해결](troubleshooting.md)에서 실패 단계부터 재개합니다. 같은 설정을 동시에 실행하지 않습니다.

사내 예약 운영은 `automate`를 수동으로 검증한 뒤 조직이 허용한 CI·cron에 설치합니다. 이번 릴리스는 예약을 설치하지 않으며 공개 libcamera에 정기 예약을 만들지 않습니다.
