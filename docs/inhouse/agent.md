# 사내 에이전트에게 맡기기

**아래 지시문을 사내 Claude(또는 터미널을 쓸 수 있는 에이전트)에 그대로 붙여 넣으세요.** 소스 경로와 제품 빌드 구성을 알고 있으면 함께 적습니다. 에이전트가 1~4단계 문서를 읽고 따르도록 짜여 있습니다.

에이전트가 반복 운영(갱신·오류 대응·설계 설명 초안)을 맡을 때는 [SDD 생성 스킬](../../skills/camera-hal-sdd/SKILL.md)을 설치합니다. 설치 방법은 [스킬 안내](../../skills/README.md)에 있습니다.

## 지시문

```text
이 저장소로 사내 Camera HAL의 설계 문서 자동화 시스템을 구축해줘.
docs/README.md 의 "사내 운영자" 순서(01 → 04)를 기준으로 진행해줘.
AGENTS.md 와 docs/reference/ 의 설정·명령 참조를 먼저 읽어줘.

환경에서 찾을 수 있는 정보(HAL 소스 경로, 제품·빌드 변형, NDK, compile DB,
생성 헤더, 기준 커밋)는 먼저 조사하고, 찾을 수 없는 필수 정보만 질문해줘.
답변과 무관하게 진행할 수 있는 작업은 계속해줘.

1. 사내 설정 디렉터리를 따로 만들고 실제 빌드로 사실 추출까지 연결해줘.
   libcamera의 클래스명·경로·빌드·게시 방식이 같다고 가정하지 마.
2. 구성 요소 색인을 켜서 빌드한 모든 클래스·함수가 한 문서에 실리게 해줘.
3. 요청 제출·완료·flush 중 한 경로부터 진입점을 확인하고, 책임·상태·소유권·
   스레드 경계·오류·종료 계약을 소스와 대조해 design_requirements와
   design_topics로 써줘. 확인하지 못한 실행 동작은 limitation으로 남겨줘.
4. 실제 코드 변경 전후 두 커밋으로 sdd update 를 돌려 영향 분석·문서 갱신·
   근거 변경 시 재검토 차단을 확인하고, 사내 CI나 예약 실행에 연결해줘.

지켜야 할 것:
- 생성된 Markdown과 HTML을 직접 고치지 말고 설정이나 생성기를 고쳐줘.
- 근거 해시만 바꿔 검사를 통과시키지 마.
- 자동 검사 통과나 LLM 판정을 사람 승인으로 기록하지 마. sdd accept 는 내가 확인한 항목만.
- 소스·facts·설정·문서·프롬프트·로그는 사내에만 둬.
- 네가 작업하는 것과 생성기가 LLM을 호출하는 것(agent.kind)은 별개야.

끝나면 설정 경로, 재실행 명령, 기준 커밋, 검증 결과, 실패 후 재개 방법,
검증하지 못한 범위를 사내 문서로 남기고, 한 경로의 초기 구축 완료와
전체 HAL 운영 적용 완료를 구분해서 보고해줘.
```

## 첫 적용의 완료 기준

| 완료 항목 | 남길 증거 |
|---|---|
| 실제 제품 구성에서 추출했습니다. | 기준 SHA, 빌드 구성, compile DB 위치, `파싱 오류 0 개` |
| 한 경로의 설계를 설명했습니다. | 필수 질문별 답변·근거·limitation과 생성된 문서 |
| 코드 변경을 처리했습니다. | 전후 SHA, `impact-review.md`, 갱신 또는 재검토 차단 결과 |
| 반복 실행을 검증했습니다. | 사이트 링크·해시 검사, 같은 입력의 반복 빌드, 실패 후 재개 결과 |
| 운영자가 다시 실행할 수 있습니다. | 설정 경로, 정확한 명령, 예약·CI 정의, 상태 보존 위치, 남은 작업 |

빌드 입력·권한·게시 대상이 없어 끝내지 못한 단계는 구체적인 미완료 항목으로 남깁니다. 로컬 미리보기만 만들었다면 사내 배포가 끝났다고 보고하지 않습니다.
