# 요청 처리 가이드 검증

요청 제출·완료·재사용·정지를 한 문서에서 읽고 실패한 단계를 찾을 수 있도록 공개 libcamera 예제를 보강했습니다. 최종 대상인 사내 Camera HAL의 적용이나 실기기 검증 결과는 아닙니다.

## 변경 내용

- `request-lifecycle` 문서는 제출 성공과 촬영 완료를 구분하고, 공통 파이프라인의 준비 대기·장치 전달·완료 책임을 연결합니다.
- Request·FrameBuffer·fence·컨트롤의 유지 기간과 재사용 조건을 표로 정리합니다. `ReuseBuffers`의 fence 주의사항은 별도의 소스 발췌와 해시에 연결합니다.
- 오류별 진단 표는 확인할 상태와 구현 위치를 안내합니다. 실제 로그나 복구 성공을 확인한 것으로 표현하지 않습니다.
- 정상 완료·정지·연결 해제의 보장 범위를 비교하고, 변경 검토 질문과 별도로 필요한 실행 증거를 명시합니다.
- IPU3 LSC 문서에 활성화·갱신·색온도 조건별 결과를 추가하고, 첫 화면에 작업별 읽기 경로를 제공합니다.

## 근거와 유지보수

설명과 표는 `examples/libcamera/config/sections.yaml`에서 관리합니다. 기존 필수 질문 검사, 소스 발췌 해시, 원고 지문과 영어 카탈로그 검사를 적용합니다. 생성 HTML을 직접 수정하지 않습니다. 표 아래의 인용은 표 전체에 연결된 근거이며, 행 단위 의미 검증을 통과했다는 뜻은 아닙니다.

가이드의 범위는 Camera와 공통 PipelineHandler의 계약입니다. 특정 센서나 파이프라인의 실행 순서를 확인한 문서가 아니므로 정적 호출 관계를 실행 시퀀스도로 바꾸지 않았습니다. 신호 수신자의 스레드·재진입·장치별 지연은 별도 검증 대상으로 남깁니다.

공식 upstream에서 이전 분석 커밋 `0f0450158f4eaa37de633520822a9c4a1c25c5ea` 이후 다섯 커밋을 확인했습니다. 대상 커밋은 `8103c3f29fba61dbd1d3bbf1a099280c5f3217e3`입니다. IPU3 LSC 초기화에서 `activeAreaSize`가 `activeArea`의 너비·높이와 `activeArea.size()`로 바뀐 내용을 대조하여 원고와 발췌 해시를 갱신했습니다.

## 검증 기록

- WSL에서 IPU3·RKISP1·UVC와 GStreamer를 포함한 최신 소스의 Meson/Ninja 빌드가 성공했습니다.
- compile DB 171개 translation unit을 다시 추출했습니다. 파싱 오류와 시나리오 진입점 누락은 각각 0개이며, 최종 클래스 1,005개와 시나리오 6개를 확보했습니다. 기존 facts 재사용이 아닙니다.
- 336개 파일의 인용 위치 5,069개를 검사했고 잘못된 위치는 없었습니다. 필수 설계 질문 32개와 발췌 88개의 연결을 검사했습니다.
- 원고 14편에서 한국어·영어 각각 15페이지를 생성했습니다. 번역 카탈로그 636개 항목이 채워졌고, 내부 링크 오류는 0개이며 manifest 검사가 통과했습니다. 동일 입력의 반복 빌드 manifest가 일치했습니다.
- Windows 회귀 테스트 249개가 통과했습니다. 데스크톱 1440px·모바일 390px에서 새 가이드 표와 가로 스크롤을 확인하고, 영어판 표시와 새 문서 검색을 확인했습니다.

소스 대조는 에이전트 검토이며 사람의 내용 승인과 실기기 시험은 수행하지 않았습니다. 공개 배포의 생성기 커밋·산출물 해시와 배포 범위는 문서 저장소의 `run.json` 및 `docs/site-manifest.json`에서 확인합니다.

다음 단계: [공개 문서](https://ttolsun.github.io/libcamera-sdd/request-lifecycle.html)의 진단 순서와 실제 구현을 대조합니다.
