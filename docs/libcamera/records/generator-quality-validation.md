# 생성기 문서 품질 개선 검증

**2026-09-26에 생성기에서 libcamera 문서 12편과 사이트 안내 페이지를 재생성하고, 설계 항목 26개의 근거 연결·시나리오 기록 보존·사이트 동작을 확인했습니다.** 사내 HAL 검증이나 사람의 내용 승인을 완료했다는 뜻은 아닙니다.

## 변경 범위

시나리오의 주요 확인 지점은 `scenarios.yaml`의 `focus`로 선택합니다. 같은 호출 지점의 가상 후보와 예약 대상을 경계 표에 모으고, 관계도에는 시간 순서를 부여하지 않습니다. 기본 설명은 LLM을 호출하지 않고 추출 facts로 구성합니다. 전체 추적 기록은 25개씩 펼쳐 볼 수 있으며 로깅과 접근자 호출도 상세 기록에 보존합니다.

모든 새 원고는 생성 방식과 검증 범위를 기록합니다. 소스 발췌 해시에 연결한 설명, 추출 구조, 추출 시나리오와 LLM 설명을 구분하며, LLM을 사용하지 않은 문서에는 생성 모델을 붙이지 않습니다. 파싱 오류·빈 compile DB·libclang 진입점 누락은 추출 실패로 처리하고 기존 facts를 보존합니다.

개요·Pipeline·IPA의 자유 생성 설명은 프로젝트 설정에 작성한 소스 계약으로 대체했습니다. 개요는 탐색·요청 생성 주체·캡처 상태·비동기 경계를, Pipeline은 구성·요청 준비·완료 순서·접근 수명·정지를, IPA는 서명에 따른 실행 방식·프록시 템플릿·프레임 인터페이스·수명·IPC 실패를 설명합니다. 설명은 실제 구현과 대조하여 작성하고 예제 설정에 둡니다. 최종 생성 실행은 LLM을 호출하지 않았습니다.

공통 생성기에 `design_requirements`와 설명별 `covers` 검사를 추가했습니다. 필수 답변이 없거나 근거가 바뀌면 생성 전에 중단합니다. `kind: limitation`만 있는 답변도 완료로 인정하지 않습니다. 각 설계 설명 아래에서 소스 원문을 펼쳐 볼 수 있습니다. 사내 HAL에서도 같은 기능을 쓸 수 있으나, 해당 소스에 맞는 질문·설명·근거 선택을 작성해야 합니다.

## 입력과 결과

공개 libcamera 커밋 `279d355ef8f7a4f98bb0a3004c0f788387814506`의 보관된 추출 결과를 사용했습니다. 기존 `libcamera-doc-updater-c178a4` 작업본의 facts를 이번 작업의 별도 출력 폴더에 복사했으며 원본 작업본은 수정하지 않았습니다. 소스 발췌는 해당 커밋에서 다시 읽어 대조했습니다. 이번에는 libcamera 빌드·전체 추출·실기기 촬영을 다시 실행하지 않았습니다.

| 시나리오 | facts의 기록 수 | 생성 문서에 보존한 기록 수 |
|---|---:|---:|
| 카메라 탐색 | 33 | 33 |
| 스트림 구성 | 208 | 208 |
| 캡처 시작 | 48 | 48 |
| 요청 제출 | 80 | 80 |
| 요청 완료 | 105 | 105 |

전체 회귀 테스트 193개가 통과했습니다. 테스트에는 뒤쪽 호출의 보존, 가상 후보·예약 경계의 유지, 잘못된 focus와 노드 한도 초과 거부, 같은 인용 위치에서 호출 대상이 바뀐 원고의 게시·이월 차단, 추출 실패 시 기존 facts 보존을 포함합니다. 설계 계약 테스트는 필수 답변 누락·빈 설명·제한 사항만 있는 답변·근거 변경·중복 ID·잘못된 목록 설정·생성 실패 시 원고 보존·사이트 차단을 다룹니다. 엄격한 파싱 검사로 드러난 mini-hal 예제의 `<utility>` 누락도 수정했습니다.

병합 전 리뷰에서는 세 가지를 추가로 수정했습니다. 설계 주제에서 LLM을 사용하면 `narration: facts`가 함께 있어도 실제 생성 방식과 모델을 표시합니다. 잘못된 소스 선택자는 Git 조회 전에 명확한 설정 오류로 중단하며 기존 facts를 보존합니다. facts 기반 문서만 증분 생성할 때는 변경 요약도 모델 없이 작성합니다. 이 조건들을 검증하는 회귀 테스트 6개를 포함했습니다.

설계 검사 결과는 개요 5개, 카메라 모델 6개, Pipeline 5개, IPA 5개, LSC 처리 5개로 모두 `documented`입니다. 소스 발췌 레코드 64개를 사용합니다. 이 수치는 설정된 질문과 답변의 연결 범위이며 전체 라이브러리의 모든 설계를 검증한 비율이 아닙니다.

최신 [카메라 모델 평가](camera-model-review.md)에서 지적한 버퍼 유효기간, 비동기 큐잉과 파이프라인의 완료 통지 계약도 예제 설정에 보완했습니다. 기존 소스 발췌와 구현을 대조하여 작성했으며, 출력 원고를 직접 수정하지 않았습니다. 평가의 나머지 개선 제안인 상태도 자동 추출, 주장별 인용 위치 세분화, fence 재사용과 연결 해제 계약의 상세 보완은 이번 검증 범위에 포함하지 않았습니다.

사이트 검증 결과는 HTML 13페이지, 깨진 내부 링크 0개이며 산출물 해시 검사도 통과했습니다. 같은 입력으로 사이트를 두 번 빌드해 manifest를 포함한 결과가 동일한지 확인했습니다. 브라우저에서는 데스크톱과 너비 390px 화면, 마지막 추적 구간 펼치기, 그림 확대와 요소 검색, 새 절 제목의 문서 검색을 확인했습니다.

설계 계약 추가 후에는 IPA의 필수 항목 표·근거 링크·원문 펼치기를 다시 확인했습니다. 모바일에서 발췌를 펼친 상태에서도 페이지 전체의 가로 넘침이 없었습니다. 기존 CSS와 JavaScript는 변경하지 않았습니다.

## 재생성 위치와 한계

이번 실행의 설정과 결과는 로컬 `build/generator-review-20260926/`에 있습니다. `validation.json`은 페이지별 상태·기록 수·반복 빌드 결과를, `build/design-review.json`은 필수 질문별 연결 검사를, `sdd/`는 원고를, `build/site/`는 사이트를 보관합니다. 이 경로는 Git에서 제외합니다.

```powershell
uv run sdd --config build/generator-review-20260926/sdd.yaml generate
uv run sdd --config build/generator-review-20260926/sdd.yaml verify-site
```

이 실행 설정은 해당 컴퓨터의 소스·자산 경로를 포함합니다. 다른 환경에서는 `examples/libcamera/sdd.yaml`을 기준으로 경로를 맞추고, 해당 환경에서 확보한 compile DB와 facts로 시작해야 합니다.

자동 검사는 사람의 내용 승인을 대신하지 않습니다. 새 설명은 소스 구현을 대조했지만 사람 승인 상태는 계속 `pending`입니다. 소스 발췌 해시 일치도 연결한 문장의 의미를 승인하지 않습니다. 공개 배포 저장소와 배포된 HTML은 직접 수정하거나 게시하지 않았습니다.
