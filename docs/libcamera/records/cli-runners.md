# CLI 실행기와 실제 Hermes 재생성 시험

**문서 생성은 기본 Hermes CLI를 경유하며, OpenCode 또는 Claude Code CLI를 독립적으로 선택할 수 있습니다.** 2026-10-26에 공개 mini HAL로 Hermes → Qwen 문서·그림 생성과 두 커밋 재생성을 시험했습니다. 사내 HAL이나 사내 모델의 검증 결과는 아닙니다.

## 확인한 실행 범위

| 실행기 | 실제 결과 |
|---|---|
| Hermes | 설치된 CLI와 `qwen3.5:9b`, `custom` 제공자로 공개 입력을 실행했습니다. 간단한 정수 반환 질문과 아래 재생성 시험을 통과했습니다. |
| Claude Code | 설치와 CLI 호출을 확인했습니다. 실제 모델 요청은 OAuth 세션 만료로 실패했습니다. 다른 실행기로 전환하지 않았습니다. |
| OpenCode | 설치하지 않았습니다. 비대화형 인자·표준입력·JSON 이벤트 처리·실패 처리는 테스트 대역으로 검사했으며 실제 모델 실행으로 보고하지 않습니다. |

시험한 Hermes는 `v0.21.3`, 설치본 upstream 표시는 `948e9706`이며 CLI 내부 Python은 3.11.16입니다. Claude Code는 2.1.284입니다. 모델·제공자는 사내에서 선택한 CLI의 설정을 사용하며 이 공개 시험의 Qwen 설정에 고정되지 않습니다.

## 두 커밋 시험 결과

공개 mini HAL의 `RequestManager::onFrame`에서 결과 전송 조건을 `ret == 0`에서 `ret >= 0`으로 바꿨습니다. 실제 모델에 현재 소스와 질문을 보내 답변과 그림을 새로 생성했으며, 최종 시험은 총 8회의 CLI 호출과 2회의 그림 호출을 기록했습니다.

- 변경 전 문서·그림 생성과 사이트 검증을 통과했습니다.
- 같은 원고의 사이트 반복 빌드에서 manifest가 같았습니다.
- 소스 변경 직후의 오래된 원고는 게시하지 못하게 막았고 이전 정상 사이트를 보존했습니다.
- 변경 영향 분석 후 문서·그림을 재생성하고 사이트 검증을 통과했습니다.
- 원응답·요청·receipt 해시와 그림 초안을 대조했습니다. 최종 문장은 0 이상의 반환값에서 결과를 보내며 완료 처리는 if 블록 밖에서 호출된다는 내용을 소스와 일치하게 설명했습니다.

receipt의 `http_call: false`는 생성기가 모델 API를 직접 호출하지 않았다는 뜻입니다. Hermes 내부에서 모델에 보낸 HTTP 호출이 없다는 뜻은 아닙니다. CLI 호출 수와 모델 내부 호출 수를 같은 값으로 해석하지 않습니다. 테스트 대역의 검사와 실제 모델 시험은 별도로 기록합니다.

## 실제 모델에서 발견한 실패

개발 시험에서 Qwen이 이전 조건을 그림에 다시 쓰거나, JSON 구문을 틀리거나, 출력 schema 자체를 반환했습니다. 실패 기록은 보존했으며 검사나 노드 한도를 완화하지 않았습니다. 질문은 조건을 유지한 채 한 문단으로 나누고, CLI 프롬프트에는 schema가 답변 자체가 아니라는 지시를 추가했습니다. 마지막 시험은 새 출력 폴더에서 실행했습니다.

공개 IPA 보완 중에는 Qwen이 생성자의 초기 상태와 이후 대입을 혼동했습니다. 자동 검사 통과 원고에서도 의미 오류와 중국어 혼입을 발견해 게시 후보에서 제외했습니다. 이 생성자 추론은 성공한 시험으로 보고하지 않습니다. 공개 보완 범위는 `loadIPAModuleInfo`에 직접 나타난 모듈 정보 오류와 서명 파일 누락의 반환값으로 확정했습니다. 모델 실행 성공, 자동 검사 통과, 소스 대조와 사람 승인은 서로 다른 결과입니다.

전체 회귀 검사는 996개 통과, 1개 건너뜀을 기록했습니다. 생성기 PR의 Windows·Linux, Python 3.11·3.14 CI 결과도 별도로 확인합니다. 공개 upstream과 미러는 같은 `2c4b67c0792f88f69bcdf9cbf73e81b3d8cf4b6f`였으며 새 커밋은 없었습니다. 공개 문서 보완에는 같은 SHA의 기존 300-TU facts를 재사용하며 새 추출을 수행했다고 표현하지 않습니다.
