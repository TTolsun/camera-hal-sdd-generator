# IPU3 LSC 문서 보강과 남은 범위 검토

**LSC 변경을 검토할 때는 구조 문서 다음에 `ipu3-lsc-flow.md`를 읽으세요.** 새 페이지는 빌드 등록, 공유 상태와 프레임별 상태, 초기화와 크롭, 요청별 제어, 파라미터 갱신 및 메타데이터 전달을 설명합니다.

분석 대상은 공개 libcamera 커밋 `279d355ef8f7a4f98bb0a3004c0f788387814506`입니다. `examples/libcamera/config/sections.yaml`의 `ipu3-lsc-flow`에 설명과 소스 발췌 해시를 함께 저장합니다. 문장은 Qwen을 호출하지 않고 생성하며, 관계 그림은 기존 facts에서 만듭니다. 사이트의 모델 표시는 설정된 모델을 나타내므로 실제 호출 여부는 `content-review.json`의 `mode: source-bound-contract`와 구분해야 합니다.

## 남은 10건의 소스 대조

기존 A/B 비교의 기준은 `0a881d263755d97d912c5fb5302c8de095cd5148`에서 위 대상 커밋까지입니다. `git diff`로 다음 변경을 확인했습니다. 아래 결과는 이 두 커밋에만 적용하며, 다른 변경에 대한 자동 제외 규칙이 아닙니다.

| 보고서 항목 | 건수 | 소스 대조 결과 |
|---|---:|---|
| IPASessionConfiguration 안의 grid·af 익명 구조체 | 4 | 각 구조체의 A/B 항목입니다. 본문은 같고 LSC 헤더 추가로 줄 번호가 이동했습니다. |
| IPAActiveState 안의 af 익명 구조체 | 2 | A/B 본문은 같습니다. LSC는 익명 구조체 밖에 별도 필드로 추가됐습니다. |
| IPAFrameContext 안의 sensor 익명 구조체 | 2 | A/B 본문은 같습니다. 헤더와 앞선 LSC 필드 추가로 줄 번호가 이동했습니다. |
| algorithms/meson.build | 1 | 알고리즘 목록에 lsc.cpp가 추가됐습니다. 새 페이지의 빌드 절에서 설명합니다. |
| ipa_context.cpp | 1 | IPAActiveState::lsc와 IPAFrameContext::lsc의 Doxygen 설명이 추가됐습니다. 실행 코드 변경은 없습니다. 필드 연결은 새 페이지가 인용하는 헤더에서도 확인합니다. |

익명 구조체 8건은 구조체 네 개의 이전·이후 위치를 별개 항목으로 세어 생긴 결과입니다. 해당 구조체의 본문 변경으로 해석하지 않습니다. 새 문서에서 두 파일 변경의 의미를 설명했지만, 범위 검사기는 소스 발췌와 이러한 검토 기록을 승인 장부로 사용하지 않습니다. **기존 범위 검사 10건과 엄격 검사 종료 코드 2는 유지합니다.** 자동으로 승인하거나 제외하지 않았습니다.

## 재생성과 확인

기존 B facts와 같은 커밋의 원고를 별도 출력 디렉터리에 복사한 검토 설정으로 생성했습니다. 새 빌드나 구조 재추출은 수행하지 않았습니다. 로컬 검토 설정은 `build/revision-validation/lsc-flow-20260923/sdd.yaml`입니다.

1. 해당 커밋의 facts와 Git 객체를 준비합니다.
2. 설정의 sections_file을 현재 libcamera 예제 설정에 연결합니다.
3. `sdd --config <검토 설정> generate --sections ipu3-lsc-flow`로 새 페이지를 생성합니다.
4. `sdd --config <검토 설정> verify-site`로 사이트를 검사합니다.

이 페이지는 B에서 추가된 구현을 설명합니다. 구현이 없는 A에서 생성하면 근거 누락을 표시해야 합니다. 예전 A/B 검증 기록을 덮어쓰거나 A의 누락을 통과로 바꾸지 않습니다.

2026-09-23 실행에서 새 페이지의 다섯 절이 자동 검사를 통과했습니다. 사이트는 안내 페이지를 포함한 HTML 여섯 개에서 내부 링크 오류가 없었고, 재빌드 전후 manifest가 같았습니다. A의 facts로 근거를 수집하면 새 페이지의 발췌 일곱 개가 검토 필요로 남았습니다. 엄격 범위 검사의 종료 코드 2와 회귀 테스트 83개 통과도 확인했습니다.

머지 전 소스 대조에서는 갱신 생략 조건의 적용 범위를 명확히 했습니다. 색온도 차이와 양자화 값 비교는 update가 false일 때만 적용하며, update가 true인 경우에는 해당 검사를 건너뜁니다. 비활성화 파라미터를 전달하는 경로도 update와 enabled의 조합으로 설명합니다.

PR 리뷰에서는 본문에서 설명하는 IPAContext, 공유 상태와 프레임별 상태 및 두 LSC 상태 타입을 클래스 선택에도 포함했습니다. 이 연결을 관계 그림과 선언 위치 표에서 함께 확인할 수 있습니다. 그림은 추출된 관계만 나타내며 호출 순서는 표현하지 않습니다.

샘플 수 1의 정규화, LUT 분할 경계, 센서별 화질과 실제 적용 프레임은 추가 검증 대상입니다. 자동 검사 통과는 사람의 기술 검토나 사내 Camera HAL 검증 완료를 뜻하지 않습니다. 이 보강분은 로컬 검토본이며 공개 사이트에는 아직 배포하지 않았습니다.
