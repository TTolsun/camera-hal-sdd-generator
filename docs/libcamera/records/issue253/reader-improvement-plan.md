# 확인된 독자 과업 공백의 보완과 재평가 계획

진행 상태와 실패·재시도는 [후속 실행 기록](reader-improvement-result.md)에 남긴다. 이 계획의 고정 과업·판정 기준은 유지한다.

원래 [절차](protocol.md), [정답 기준](rubric.md), A/B 버전과 24개 자동 시행은 그대로 보존한다. [추가 원인 대조](cost-qt-result.md)에서 확인한 T2·D1·D2만 보완하며 새 결과로 원래 실패를 덮어쓰지 않는다. 사람 참가자가 없는 상태와 읽기 부담·사람 검토 시간의 미측정도 유지한다.

변경은 설정·질문·근거와 생성기에서 수행한다. 생성된 한국어/영어 원고나 HTML을 수동으로 써서 CLI 성공으로 보고하지 않는다. 생성·번역은 명시한 독립 Codex CLI/Terra High, 근거 검토는 별도 승인된 동일 검토 프로필로 실행한다. 실패·재시도·캐시 재사용은 각 단계 장부에 남긴다.

긴 순서·분기·소유권 항목에는 해당 질문의 그림을 함께 점검한다. 짧은 링크 안내는 표·기존 그림 연결만으로 충분한 경우 그 사유를 기록한다. 최종 한영 문서의 링크 목적지·390px 화면·그림 확대와 소스 경계를 확인한 뒤 생성기 CI/병합, 공개 SDD PR/병합, Pages/실제 URL을 별도 확인한다.

## 자동 재평가를 시작하기 전의 잠금

원래 task 문구·루브릭·600초 제한과 실패 포함 분모를 유지한다. 새로운 비교 문서의 Git SHA, source_commit, build ID, manifest·각 허용 산출물 해시와 생성기 SHA를 재평가 시작 전에 별도 잠금 파일에 저장한다. 현재 이 새 버전 잠금은 아직 없으며 평가를 시작하지 않는다. 최신 upstream 문서와 source293 고정 비교를 혼합하지 않는다. 소스 버전이 달라지면 같은 조건의 전후 효과 시험이라고 부르지 않는다.

재평가는 새 컨텍스트의 서브에이전트에 과업 하나와 조건 하나만 제공한다. 다른 과업·정답표·원래 답변·채점 피드백은 제공하지 않는다. 고정 시작점부터 실제 열람·답변·근거·미발견·중단을 기록한다. 시행 시작·첫 근거 도달·최종 제출의 경계를 사전에 명시하고, 도구 대기·환경 지연을 분해하지 못한 값은 null로 둔다. 서브에이전트의 주관적 읽기 부담 점수는 만들지 않는다.

이 추가 시험은 확인된 실패 과업의 자동 회귀 점검이다. 원래 작은 표본·같은 모델·역할과 언어/도구 차이를 없애지 못한다. 같은 에이전트를 재사용한 추가 점검은 이전 노출로 표시하며 첫 노출 성과에 합치지 않는다. 자동 정답·탐색 시간의 변화는 사람 생산성·읽기 부담이나 #163의 실제 비작성자 최소 기준을 충족하지 않는다. 개선·동등·악화·판단 불가를 실제 결과에 따라 보고하며 기준을 낮추지 않는다.
