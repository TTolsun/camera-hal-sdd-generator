## 기록 경계

시작은 과업 공개 직전, 첫 근거 도달은 실제 근거를 처음 연 시점, 종료는 답과 근거 제출 시점이다. 도구·네트워크 대기도 경과 시간에 포함하되 별도 측정 가능한 값만 분리한다. 종료·실패·중단·미응답을 전부 분모에 넣는다. 측정하지 못한 필드는 null/빈칸이며 0초·성공으로 채우지 않는다. 자동 시행의 경과 시간은 추론·도구 지연이며 사람 탐색 시간으로 해석하지 않는다.

허용 도움은 시작 경로와 동일 과업 문구 재제시뿐이다. 설명·정답·경로 힌트·외부 지식으로 답을 보충하면 help=true로 기록하고 독립 성공에서 제외한다. 환경 장애는 원래 시행과 지연을 남기고 복구 시행을 연결한다. 좋은 결과로 기존 실패를 덮어쓰지 않는다.

정답 여부, 독립 완료, 첫 코드/근거 도달 초, 전체 초, 질문/도움 횟수, 오해한 조건, 실제 방문 경로·검색어, 노출 순서, 읽기 경험을 기록한다. 사람 읽기 부담은 1=매우 부담됨~5=매우 낮은 부담이다. 자동 에이전트에게 이 점수를 대신 매기게 하지 않으며 null로 둔다. 모델은 관측한 탐색 장애만 서술한다.

## 판정 기준

공통 B 과업의 실제 사람 최소 기준은 비작성자 3명 이상(신입 관점 1명·타팀 관점 1명 포함), 공통 6과업 중 5개 이상 무설명 정답, 부담 중앙값 4 이상이다. 6개 중 중단/미응답도 분모이다. 추가 인원이 있으면 모든 사전 배정 시행을 보고하며 5/6만 골라내지 않는다. D1/D2에는 각 핵심 조건을 모두 요구하고 확인된 차단 오해가 하나라도 있으면 개선·재평가가 필요하다. 표본이 늘면 기준을 낮추지 않는다.

정확성·조건 보존을 먼저 판단한다. B의 독립 정답 수가 A보다 적거나 새 차단 오해가 생기면 악화다. 정확성이 낮아지지 않고, 양 조건 모두 독립 정답인 짝의 시간 중앙값이 20% 이상 감소하고, 도움 수가 늘지 않고, 사람 부담 중앙값이 1점 이상 좋아지면 이 표본에서만 개선이다. 정답 수가 같고 양쪽 정답 짝의 시간 변화가 ±20% 미만·도움 수가 같고 부담 중앙값 차이가 1점 미만이면 동등이다. 그 밖의 혼합 결과, 양쪽 정답 짝 없음, 사람 부담 미측정, 시간 누락은 판단 불가다. 성공 짝만의 시간은 전체 실패율·제한시간 초과 수와 나란히 제시한다. 실패를 제외한 속도만으로 개선을 주장하지 않는다.

자동 부록은 정답·탐색 장애·실측 실행 시간만 비교한다. 사람 효과 종합 판정은 판단 불가다. 같은 모델 계열·훈련 지식·역할 가정과 소표본 때문에 일반 사용자 성공률·인과 효과·사내 생산성으로 확대하지 않는다. 재시험은 정답 공개 여부와 노출 횟수를 기록하고 새 최초 시험처럼 세지 않는다.

## 실제 변경 비용의 사전 범위

단일 실제 upstream 변경 `293d751a814e0d4c34e85ad457ccd9d5eefd1a61`(부모 `be909e49b7cfcbf8e888b6a17928ae06fd7f9a96`)의 qcam AWB uniform 설정 수정을 고정한다. 변경 파일은 `src/apps/qcam/viewfinder_gl.cpp/.h`이며 10줄이 추가됐다. 변경 선택은 비용 수집 전이다. 원인과 수정 위치는 커밋의 공개 설명에 있다.

예상 영향은 qcam 렌더링 경로와 해당 경로를 인용·선택·watch하는 문서다. request 완료·PipelineHandler 정지 계약 자체의 변경으로 추정하지 않는다. 현재 예제의 근거/선택/watch와 실제 impact를 대조하고, qcam이 분석 범위 밖이면 그 사실과 남은 추출·의미 검토를 보고한다. 무영향 판정을 변경 전체의 검증으로 확대하지 않는다.

새 작업 디렉터리에서 변경 diff, 영향 분석, 가능한 검증·생성·번역·독립 검토·사이트 확인을 단계별로 기록한다. 재사용 횟수·신규 호출 수·재시도·실패·미시작과 원고/질문/근거 수정량을 구분한다. 기존 전체 facts를 이용하면 재추출로 부르지 않는다. 미실행 단계는 0비용 완료가 아니다. 사람 활동 검토 시간은 현재 미측정이다. 모델 검토 시간을 그 칸에 넣지 않는다. 비교 가능한 이전 사람 검토 기록이 없으므로 최초 부분 기준값이며 절감률을 계산하지 않는다. 실제 전체 갱신이 끝나지 않으면 비용 완료 조건도 미완료다.

공식 upstream 확인은 비교 입력을 임의로 최신본으로 바꾸는 이유가 아니다. 최신 upstream과 배포본 차이는 별도 기록한다. 공개 문서 수정이 필요해지면 생성 경로에서 수정하고 리뷰·CI·생성기 병합·공개 SDD PR·Pages·URL 검증을 수행한다. 원고/HTML을 수동 보정하거나 사람 승인 기록을 만들지 않는다.
