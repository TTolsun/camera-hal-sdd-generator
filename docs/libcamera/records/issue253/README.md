# #253 평가 준비와 자동 시행 결과

2026-11-05 현재 **사람 효과와 전체 유지 비용은 판단 불가**다. 사용자의 요청으로 서브에이전트 세 역할이 24개 자동 시행을 수행했다. 실제 비작성자 참가자·실측 사람 과업은 각각 0명·0개다. 자동 읽기 부담 점수를 만들지 않았고 #253과 #163은 미완료로 유지한다.

## 결과 전에 고정한 범위

평가 전에 생성기 커밋 `7e31d2f`에서 [과업·순서·판정 기준](protocol.md), [진행자 정답표](rubric.md), [버전·해시](lock.json)를 고정했다. 공식 자료 A는 source293의 Documentation·소스·테스트, 새 문서 B는 공개 SDD `178aa978…`의 build `04465b19…`다. 동일 소스의 자료 묶음을 비교했으며 과거 SDD와의 전후 비교가 아니다. 평가 시작 전에 B의 manifest 산출물 328개와 원본 소스 파일 1328개의 해시를 확인했다. 기준 문서는 변경하지 않았다.

#163의 [최신 본문](inputs/issue163.json)과 [댓글](inputs/issue163comments.json)은 실제 사람 0명·0과업, 두 그룹 자동 가독성 partial→partial이었다. 그 과거 성과와 이번 결과를 합산하지 않는다. 공통 T1~T6의 의미와 실제 사람 최소 조건을 유지하며 T1은 두 자료에 적용할 수 있도록 첫 진입 질문을 일반화했다. D1 완료 누락 진단과 D2 정지 경로 변경 계획은 #253의 추가 범위다. #150의 내용 승인, #163의 다른 화면·배포 기준, #215의 전체 항목별 그림 보완 상태는 변경하지 않았다.

## 자동 과업 결과

서브에이전트는 작성 맥락을 상속하지 않고 허용 자료·과업만 받아 수행했다. 두 조건을 교차 순서로 읽었으나 같은 과업의 두 번째 노출에는 기억이 남는다. 별도 Codex CLI / `gpt-6.1-terra` / high가 고정 기준·제공한 소스 창으로 채점했다. [원본 답·근거·시간](automated/), [자동 채점과 한계](grades.json), [집계](summary.json)를 보존한다. 모든 실패와 누락도 분모에 포함했다.

| 항목 | 기존 자료 A | 새 문서 B |
| --- | --- | --- |
| 공통 과업 정답 | 4/6 | 5/6 |
| 추가 진단·변경 과업 정답 | 1/6 | 3/6 |
| 전체 자동 정답 | 5/12 | 8/12 |
| 1차 노출만의 정답 | 3/6 | 3/6 |
| 전체 실행 시간 중앙값 | 46.5초 | 37.5초 |
| 양쪽 모두 정답인 5짝의 시간 중앙값 | 34초 | 30초 |
| 보고된 추가 도움 | 0회 | 0회 |
| 사람 읽기 부담·사람 탐색 시간 | 미측정 | 미측정 |

두 조건 모두 정답인 짝에서는 B가 T4·T3·T5에서 더 느리고 D1·T6에서 더 빨랐다. 전체 시간에는 오답도 포함되며, 성공한 짝만의 중앙값은 실패율과 별도로 제시했다. 조건 자료의 1차 노출만 집계하면 정답 수가 같으며 과업·역할 난이도도 균형 표본이 아니다. 시간은 도구로 측정한 초 단위 추론·탐색·대기 경과이며 실제 사람의 탐색 시간으로 환산하지 않는다. E02의 shell wall time 합계는 도구 지연의 부분 관측이며 순수 환경 지연이나 사람 활동 시간을 뜻하지 않는다.

자동 채점도 잠정 결과다. 모든 인용 HTML·장치/테스트 원문을 독립 검토 입력에 다시 포함한 것은 아니며, Camera::stop 소스 창 하나는 범위를 잘못 지정해 비어 있었다. 시행 뒤 감사에서 E01 T4/D1/D2의 두 조건 6시행이 지정 시작점을 다시 열지 않았음이 확인됐다. 모든 역할은 전체 과업을 먼저 읽었고 시간 경계도 사전 정의와 달랐다. 자세한 차이는 [절차 감사](procedure-audit.md)에 남긴다. 원래 자동 채점 6/12·8/12는 보존했으며 D1의 기준 적용을 재검토한 결과 E01/D1/A를 오답으로 정정해 현재 5/12·8/12다. [독립 재검토](d1-consistency.json)는 고정 기준을 유지했고 새 독자 시행은 없었다. 시행 기록과 채점 한계를 숨기지 않고 그대로 보존했다. 이 결과로 실제 사람의 공통 5/6 조건을 충족했다고 판단하지 않는다. 모델 역할 3개는 사람 3명이나 독립 모델 계열 3개가 아니다.

실패는 기존 자료의 첫 진입점 누락, 양 조건의 장치별 하드웨어 구성 책임 누락, 준비 타임아웃·완료 콜백 관측 누락, 정지 전후 콜백·중복 완료·장치별 stopDevice 검증 계획 누락이었다. 새 문서에서 D1 타임아웃과 D2 정지 반환 전후 관측을 찾은 다른 시행도 있으므로, 답의 누락을 곧바로 문서 내용 부재로 단정하지 않는다. 실패별 확인 창·미검토 범위와 다음 보완 조건은 [후속 범위](followup.md)에 남긴다. 이번에는 설명을 중복 추가하거나 평가 기준을 낮추지 않았다. 개선 후 재시험을 수행했다고 주장하지 않는다.

사전 기준의 시간 20% 감소·부담 1점 개선 조건을 확인하지 못했고, 자동 추가 과업에도 실패가 남았다. **업무 효과는 개선/동등/악화 중 어느 것으로도 확정할 수 없다.** 사람 부담·실제 수행과 비교 가능한 갱신 비용이 없어 도입 효과나 비용 절감을 주장하지 않는다.

## 실제 소스 변경 한 건의 부분 비용

비용 수집 전에 qcam AWB uniform 수정 `be909e49…→293d751a…` 한 건을 선택했다. 두 파일에 10줄이 추가되며, 검은 화면의 원인을 수정한 실제 upstream 변경이다. 이 과거 변경의 재측정이며 새로운 upstream 변경이나 실제 장치 재현이 아니다.

[원본 단계 장부](cost.json), [실제 impact](impact.json), [별도 Terra High 근거 대조](cost-review.json)를 보존한다. 첫 impact는 설정 이동 준비 오류로 실패했고 8.942초였다. 설정을 기존 products_file 경로 기능으로 바로잡은 두 번째 impact는 14.005초에 종료 코드 2로 중단했다. overview·component-index가 watch에 걸렸지만 qcam 두 파일이 기존 분석 facts에 없어 needs-review가 남았다. 이전 facts도 없어 삭제·이름 변경 비교를 완료하지 않았다. 근거 부족을 무영향 성공으로 바꾸지 않았다.

독립 소스 검토 호출은 16.527초였다. 그 전에 UTF-8 읽기 준비 실패와 잘못된 command 형식으로 검토 준비가 실패했으며, command 형식 오류 0.003초도 장부에 남았다. 이 두 준비 실패는 실제 모델 호출이 아니다. 완료된 새 모델 호출은 소스 검토 1회이며 과업 최초 채점 1회는 [별도 평가 비용](grading-execution.json), 일관성 재검토 1회는 [재검토 비용](d1-consistency-execution.json)이다. 생성·번역 호출 0회는 미실행이지 무료 갱신 완료가 아니다. 실패·반복 diff와 impact까지 장부에 포함하며 과거 생성 기록을 새 호출로 세지 않는다.

기존 source293 facts를 재사용했고 새 Clang 추출·빌드·원고 갱신·번역·사람 활동 검토는 수행하지 않았다. 원고·질문·근거의 수정량은 0이며 수정 필요성 판정도 아직 보류다. 설정·프로토콜·원자료·채점 기록의 새 파일 분량은 제품 원고 수정량과 구분한다. 대기·CPU·사람 검토 시간은 분리 계측하지 않아 null이다. 이전 기록의 사람 검토 시간도 추정치뿐이므로 전체 비용·절감률을 계산하지 않는다.

소스 검토가 지적한 ‘빌드한 모든 앱’ 안내는 현재 분석 빌드의 앱 범위(cam·GStreamer)와 qcam의 비활성 여부를 함께 확인해야 한다. 넓은 watch 일치만으로 qcam이 색인에 있다고 판단할 수 없다. 현재 비용 시험은 qcam이 빠진 facts를 실제로 검출해 멈춘 범위까지다. 검토자가 당시 장부의 준비 실패를 지적한 원본은 보존하고, 이후 성공한 독립 검토 실행과 구분한다.

## 공개 상태와 남은 조건

공식 upstream master는 확인 시점 `be7e83e91348250c015aad6d6f59f1468555bae8`이었고 공개 upstream/master도 같은 SHA였다. 고정 평가 문서의 source293과 다르다. 최신 upstream 전체 추출·원고 갱신 완료로 표시하지 않는다. 이번 변경은 평가 자료·비용 원자료이며 생성기 동작·집필 규칙·제품 원고·HTML을 바꾸지 않았다. 고정된 평가 입력을 수정해 더 좋은 결과로 대체하지 않았다.

사람 평가는 [빈 24시행 양식](human-results.csv)에 실제 비작성자 3명 이상의 결과가 필요하다. 정답표를 사전에 보여 주지 않고, 신입 관점·타팀 관점을 포함하여 공통 6과업 중 5개 독립 정답과 부담 중앙값 4 이상을 실제로 측정해야 한다. 추가 진단/변경 과업의 확인된 차단 오해도 해결해야 한다. 자동 판독·자동 채점·공개 배포를 사람 승인이나 사내 HAL·실기기 검증으로 바꾸지 않는다.

평가표·측정 정의·실패 목록은 표와 원자료로 비교할 수 있어 별도 그림을 생략했다. 제품 설명 항목의 그림 적절성·390px 화면은 이 파일 평가로 검증하지 않았다. 배포·병합·공개 URL 확인은 publication.json에 별도로 기록하며, 이 문서 준비만으로 #253 또는 Goal을 완료하지 않는다.
