# 독자 과업 공백 보완의 진행 기록

[사전 계획](reader-improvement-plan.md)에 따른 후속 작업이다. 원래 24건의 자동 시행·정답표·시간 경계와 사람 결과 양식은 보존한다. **새 자동 과업 재평가는 아직 시작하지 않았고, 사람 참가자는 0명이다.** 따라서 업무 효과와 사람 읽기 부담·검토 시간은 판단할 수 없다. 이 기록의 상태는 진행 중이다.

잘못된 `python -m sdd.localization_cli` 실행은 종료 코드 0이어도 번역을 수행하지 않았다. 별도 진단에 실제 미실행·카탈로그 동일·호출 0회로 남기고, 문서화된 `python -m sdd.site_localization`으로 실제 번역했다. 최신 소스 단계의 첫 번역도 ROI 용어가 없어 모델 호출 전에 실패했다. 기존 용어를 제거하지 않고 현재 main의 승인된 ROI 정의를 별도 용어집에 추가한 v2 설정을 고정한 뒤 재시도했다. 원래 실패 설정과 장부는 보존한다.

최신 한영 계약의 첫 독립 CLI 검토는 2,725.200초·85회 호출 뒤 미해결 지적 5개를 남기며 실패했다. 검토 중 `doQueueRequest()`가 요청을 넣는 `queuedRequests_`를 “대기 목록”으로 표현한 본문과 영어 번역의 불일치를 발견했다. 생성 질문에 정확한 큐 이름과 별도 `waitingRequests_`와의 구분을 추가하고 `queuedRequests_`를 필수 용어로 강화했다. 원래 용어 그룹과 정답 기준은 제거하지 않았다. 새 설정에서의 최초 재생성은 기준 계약의 용어 변경을 명시하지 않아 차단됐고, 다음 실행은 Codex CLI의 Windows 권한 오류로 실패했다. 각각 87.856초·32.588초이며 성공 비용으로 세지 않는다. 계약 강화 이유를 명시한 설정과 같은 CLI의 별도 재시도는 378.976초·새 호출 37회로 생성에 성공했다. 영어 번역은 84.138초·변경 문자열 23개·새 호출 4회였다. 최종 계약 재검토가 끝나기 전에는 전체 수정 완료로 판정하지 않는다.

새 원고의 별도 내용 검토에서 T2와 D2는 통과했다. D1 검토는 journey 절만 제공했을 때 다른 담당 절에 있는 의무·관찰 계획을 빠졌다고 지적했다. 원래 판정을 보존하고 실제 request-diagnosis 및 연결된 절·소스·고정 정답 기준을 함께 제공한 재대조에서는 해당 쟁점이 해소됐다. 이 재대조의 `reader_task_status`는 `not-evaluated`다. 각 짧은 답에 모든 근거 내용을 복제하지 않으며, 전체 D1 독자 과업의 통과와 펜스·타임아웃 관측 계획 제시 여부는 실제 새 시행에서 여전히 판정해야 한다.

## 실제 화면에서 발견한 연결 오류

새 연결 중 정지 절은 URL과 ID가 맞아도 그림이 그려진 뒤 제목이 화면 밖에 남았다. 원래 부드러운 스크롤은 비동기 그림 렌더링 중 위치가 바뀐 목적지로 계속 움직였고, 시간별 측정에서는 load·그림 완료 뒤에도 제목이 화면에서 벗어났다. 원래 JavaScript와 기본 스크롤의 별도 대조에서는 제목이 화면 안에 도착했다. 최종 변경은 공통 CSS의 `scroll-behavior:auto`이며 88px 상단 여백을 보존한다. 입력·스크롤·히스토리 처리를 추가한 JavaScript 실험은 독립 검토에서 반려됐고 채택하지 않았다. 원본 JavaScript는 바이트 단위로 복원했다. 마지막 CSS 독립 검토는 통과했다.

정확한 미리보기의 HTML 6개와 CSS·JavaScript의 HTTP 응답을 모두 SHA-256으로 대조한 후, 한국어·영어 각각 1280px·390px의 새 Chrome 컨텍스트에서 검사했다. 각 조건의 그림 3개 확대·검색·Esc 초점 복원과 연결 3개 도착 위치가 모두 통과했다. 스크린샷의 전체 보기에서는 작은 글자를 확대해야 한다. 이 검사는 자동 상호작용·화면 점검이며 사람 읽기 부담이나 실제 모바일 장치 검증이 아니다. 재사용 가능한 [예제 검사](../../../../examples/libcamera/validation/issue253/reader-clarity/README.md)를 남긴다.

앞선 화면 준비 실패도 보존한다. sandbox 네트워크 차단·서버 연결 실패와 고정 포트가 다른 작업의 문서를 반환한 두 검사는 효과 결과로 사용하지 않는다. 마지막 검사는 OS가 할당한 고유 loopback 포트에서 실제 파일 해시 일치를 먼저 확인했다. 화면 변경용 별도 카탈로그의 출력 경로를 잘못 지정한 실행은 원본 입력을 잠시 변경했고, 진행 중 검토가 이를 감지해 648.938초 뒤 중단했다. 원본은 동일 해시 백업에서 복원했고 잘못된 출력·실행과 실패 보고서를 따로 보존했다. 올바른 별도 카탈로그의 정상 갱신과 최종 native-anchor 단계의 갱신은 각각 18.025초·17.780초였으며 모델 호출 없이 1,909개 기존 문자열을 정상 재검증·재사용했다. 이 중단 검토를 최종 통과로 사용하지 않는다. 현재 최종 카탈로그로 실제 요청·원래 CLI 영수증을 다시 대조하는 계약 검토를 진행 중이다.

각 경과 시간은 해당 subprocess의 시작부터 종료까지다. 단계가 겹치거나 초기 구축·복원·환경 지연이 포함된 경우를 구분하며, 이 표를 단순 합산한 값을 사람 유지 비용이나 소스 변경 한 건의 비용으로 부르지 않는다. CPU·모델 서버 대기·사람 활동을 분해한 값은 측정하지 않아 null이다.

## 비교 가능한 범위와 남은 작업

원래 비교 자료의 source293은 고정한다. 새 발행 준비 소스는 공식 upstream `be7e83e91348250c015aad6d6f59f1468555bae8`이다. T2·D1·D2 정답에 사용하는 공식 문서와 Camera·PipelineHandler·Request의 파일 7개가 두 커밋에서 동일한 것을 SHA-256으로 확인했다. 전체 사이트·환경·조건의 동등성을 뜻하지 않는다. 새 발행에는 별도 이슈의 역할별 진입점·질문 안내와 qcam 포함 추출 범위도 함께 들어간다. 후속 자동 결과를 문장 하나의 인과 효과나 기존 A/B 시험의 새 최초 노출로 해석하지 않는다.

새 upstream의 변경 중 Meson 버전은 기존 영향 분석에서 미매핑으로 검출됐다. 독립 CLI의 범위 검토는 버전 표기만 바뀐 창을 out-of-scope로 분류했다. 이는 자동 범위 판정이며 사람 승인이 아니다. Python 바인딩 변경은 이 빌드의 분석 범위 밖이고 실기기·GPU·Python 실행을 검증하지 않았다. 373개 선택 창의 재대조를 전체 소스의 의미 검토로 확대하지 않는다.

재생성한 request-lifecycle의 독립 질문 36개와 vendor-overview의 책임 질문 2개를 개별 점검했다. 24개는 관련 근거 연결 그림을 사용하고 14개는 짧은 단일 API·조건·기록 항목·숫자 요약이므로 생략 이유를 남겼다. 이 범위를 나머지 문서나 #215 전체의 검토 완료로 확대하지 않는다.

최종 계약 재검토와 정상 사이트 빌드·검증을 마친 뒤 새 발행 버전과 산출물 해시를 고정해야 한다. 그 뒤 새 컨텍스트의 서브에이전트에 과업 하나·조건 하나만 제공하여 T2·D1·D2를 회귀 점검한다. 읽기 부담과 사람 검토 시간은 자동으로 대신 채우지 않는다. 생성기 PR 병합, 공개 SDD PR 병합, Pages와 실제 산출물 확인도 아직 남았다. #253과 #163은 미완료다.

이 파일은 실행·비교 조건과 비용의 표로 충분하므로 별도 제품 동작 그림을 생략한다. 새 제품 설명의 하드웨어 책임 경계·정지 구현 검토·제출 회차별 완료 비교 그림은 원고와 별도로 검토하며, 이 기록의 표로 제품 그림 검증을 대신하지 않는다.
