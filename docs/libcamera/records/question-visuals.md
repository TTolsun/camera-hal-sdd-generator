# 질문에 맞춘 시각화 검증 기록

**시스템을 처음 읽는 독자가 상태·요청 흐름·수명·실패 분기를 설명 옆의 그림으로 확인하도록 보완했습니다.** 공개 libcamera를 사용하는 정적 문서 검증이며 사내 HAL 적용이나 기기 실행 검증이 아닙니다.

2026-10-25에 공식 upstream master와 공개 보관 브랜치가 모두 `2c4b67c0792f88f69bcdf9cbf73e81b3d8cf4b6f`인 것을 확인했습니다. 새 소스 커밋이 없어 해당 커밋의 기존 전체 빌드 facts와 원고를 재사용했습니다. 구조를 재추출하거나 LLM에 설명을 다시 작성하게 하지 않았습니다. 질문·근거·생성 정책이 같은 답변을 이월하여 원고에 그림을 배치했고 기존 작성자 기록을 유지했습니다.

| 문서 | 보완한 그림 |
|---|---|
| 시스템 개요 | 장치 탐색·등록 책임, 접수 성공과 완료 통지 |
| 카메라와 요청 모델 | 원본 상태도에 있는 상태·자기 전이·허용 호출, 요청·버퍼 유지 기간 |
| 요청 처리와 문제 진단 | 구성 실패, 제출부터 완료까지, 소유권, 대기·큐 한도·취소, 정지 순서 |
| Pipeline Handler | 준비·장치 큐의 분기, 버퍼 완료와 명시적 요청 완료 |
| Vendor 문서 세 편 | 장치 구현 경계, 획득부터 해제까지, 구성 검증의 세 결과 |
| IPA 관리와 구현 진입점 | 모듈·서명·프록시 선택, 스레드와 IPC 경계 |
| IPU3 LSC의 설정과 프레임 처리 | 첫 프레임의 기본 활성화, update·활성화·색온도에 따른 갱신 분기 |
| RKISP1 카메라별 왜곡 보정 | 카메라별 보정값 보관·전달, 기본값과 입력 오류 |

10개 문서에 그림 20개를 추가했습니다. 그림의 99개 노드와 96개 화살표에 연결된 발췌 33개를 Git 원본 9개 파일과 대조했고, 위치·본문·해시가 일치했습니다. 노드와 화살표는 작성한 설계 해석이며 해시나 구절 검사가 해석의 정확성을 자동 승인하지 않습니다. 원본 상태도에 없는 전이, 정적 호출 목록에서 추정한 실행 순서, 기기 성능·스레드 보장은 추가하지 않았습니다.

그림은 설명 절의 첫 문단 뒤에 둡니다. 절이 번호 절차로 시작하면 그림을 목록 앞에 두어 번호가 끊기지 않게 합니다. 그림 아래에서 요소·전이별 원문을 펼치고 Mermaid 원문을 내려받을 수 있습니다. 영어판은 같은 ID·연결을 유지하면서 선언한 영문 레이블을 사용합니다.

검증 결과는 다음과 같습니다.

- 전체 회귀 검사 793개가 통과했고 1개는 기존 조건에 따라 생략했습니다. 최종 관련 검사 61개도 통과했습니다. 노드·화살표 근거 누락, 발췌·커밋·selector 변경, 잘못된 연결, 번역 누락과 노드 한도 초과 시 기존 원고·사이트를 보존하는 검사를 포함합니다.
- 한영 42페이지의 내부 링크 오류는 0개였으며 manifest 검사와 반복 빌드 동일성 검사를 통과했습니다.
- 로컬 브라우저에서 변경한 한국어 10페이지와 영어 10페이지의 Mermaid 렌더링·가로 넘침을 확인했습니다. 상태 전이와 요청 문서는 실제 SVG 크기와 설명 근처의 배치도 확인했습니다. 이후 번호 절차를 분리하지 않도록 배치를 고쳤고 회귀 검사로 확인했습니다.
- Windows 브라우저의 현재 주소를 확인하지 못해 UI 자동화가 중단됐습니다. 휴대폰 화면과 이번 변경에 대한 확대·검색·Escape 동작의 수동 재검증은 완료하지 못했습니다. 해당 기능의 기존 구현은 변경하지 않았습니다.

사람의 의미 승인, 독립 독자 평가, 실제 카메라 실행과 사내 HAL 검증은 수행하지 않았습니다. 공개 문서의 사람 검토 상태도 승격하지 않았습니다. 생성기·문서 저장소 병합 및 실제 공개 파일 검증 결과는 배포 저장소의 `run.json`에 별도로 기록합니다.
