# 공개 문서 본문의 중복 설명 정리

공개 libcamera SDD의 한국어·영어 60쪽에서 독자가 읽는 문단과 목록 842개를 모두 대조했다.
기준 배포는 `e9322a2e2fc3061e57257dc8ec705fc40abad680`이며 분석 소스는
`e117198c015057761bb0bbaa85f963c41ce412d7`이다. 표·코드·그림과 접힌 감사 기록은 이번 본문 감사에서 제외했다.

독립 Codex CLI의 `gpt-6.1-terra`, reasoning effort `high`로 세 묶음을 검토했다.
[페이지별 판정과 보존 조건](prose-cleanup/audit-before.json)은 수정 후보이며 자동 승인이나 사람 독자 평가가 아니다.
서로 다른 함수의 조건·오류·호출 책임은 중복으로 취급하지 않는다. 독립적으로 읽는 문서의 짧은 요약도 유지한다.

## 생성 질문의 정리

- `team-overview`: 네 계층의 순서를 소개한 뒤, 입출력·연동 예·책임 경계는 해당 절에서 설명한다.
- `ipa`: 실행 절은 호출 연결을, 종료 절은 호출 전제와 정리 순서를, 실패 절은 오류 분기를 맡는다.
  프록시 생성과 init/start, 모듈 로드 실패를 종료 절에서 다시 요구하지 않는다.
  생성자의 소유권·이벤트 연결은 한 답변으로 묶는다. load 성공 전제, 오류의 모듈 경로, unique_ptr,
  연결 대상과 valid_ 설정은 필수 답변으로 남긴다. 두 인터페이스의 센서 제어 인자 차이도 보존한다.
- `ipu3-lsc-flow`: 같은 첫 프레임 조건의 enabled/update와 한 호출의 대상·세 인자를 각각 한 문장으로 묶는다.
  기존 필수 식별자와 인자 순서는 유지한다.
- `framebuffer-allocator`: 반환 결과만 간결하게 설명하고, 근거를 읽는 과정인 if 범위 설명을 본문에 요구하지 않는다.
- 용어집의 FPS·ETIMEDOUT 표제어 반복과 IPU6·RK3399의 겹친 서술을 줄인다.
  타이머 설정값과 공식 문서에 기재된 지원 범위라는 한정은 유지한다.

기존 설계 질문의 필수 항목·조건을 삭제해서 분량을 줄이지 않는다.
원고·번역은 CLI를 통해 생성하고, 근거 대조와 게시 계약 검사를 다시 수행한다.

## 검증 상태

관련 독자 범위·답변 계약·설계 계약·용어집·결합 질문 회귀 검사 79개가 통과했다.
공개 e117 고정 입력에서 네 문서를 실제 CLI로 생성하고 소스 근거 대조를 수행했다.
실패한 응답과 재시도·완료 체크포인트 재사용은 기록하며 독립 신규 표본으로 합산하지 않는다.
본문을 수동 수정하거나 집필·검증 정책을 완화하지 않았다.

[동일 소스의 응답 분량](prose-cleanup/fixed-source-comparison.json)은 생성된 답변 텍스트만 비교한다.
원본 코드·감사 메타데이터나 HTML 문단 수를 본문 분량에 섞지 않는다.
[최종 전후 편집 검토](prose-cleanup/fixed-source-editorial-review.json)에서는 네 문서 모두 잔여 반복과
필수 정보 누락이 발견되지 않았다. 이 자동 검토는 실제 사람 평가를 대신하지 않는다.

최신 공개 소스 갱신본에 적용한 전체 원고·번역·공개 산출물과 Pages 확인은 별도 배포 기록으로 남긴다.
사내 Camera HAL이나 실기기 검증 결과로 확대하지 않는다.

## 최신 전체 원고의 추가 정리

공개 PR #184에 보존된 libcamera `212c689fcf2450bbfbaab25c7472895ac277b5d6`의 전체 원고도 대조했다.
초기 네 문서 밖에서 남은 반복은 다음 질문 계약에 반영한다.

- 연동 구현: configure의 검증 전제와 사용자 정의 필드 허용 범위를 구분하고,
  stopDevice의 장치 요청 처리 의무에서 공통 stop 순서를 다시 설명하지 않는다.
- Camera 요청과 요청 수명주기: 같은 ReuseBuffers 분기의 setRequest와 pending_ 삽입을 묶는다.
  요청 전달의 두 중단 조건, 장치 제출의 성공·오류 반환, 버퍼 완료와 요청 완료의 차이를 각각 함께 설명한다.
- 요청 수명주기: Pending 선두에서의 중단, 정지의 상태 전환과 블로킹 호출, disconnect TODO의 소속과
  대기 요청을 각각 한 설명으로 묶는다. 종료 큐 검사와 조사 기록에서는 앞선 호출 순서를 다시 나열하지 않는다.
- 문제 진단: 연결 해제와 상태 범위 분기를 함께 관찰하고, Adjusted 결과와 호출자의 확인 의무를 구분한다.
  장치 configure 반환과 이후 스트림 연결 검사, 취소된 요청과 장치 제출 실패의 조사 지점을 분리한다.
- RKISP1 보정: setControls의 미구성 반환과 구성된 스트림의 동적 제어 오류 조건을 함께 설명한다.
  populateMetadata의 미구성 반환은 다른 함수의 조건이므로 보존한다.

동일한 근거 종류의 질문 13묶음을 합치며 기존 근거 식별자·필수 용어·거부 조건은 합집합으로 유지한다.
API 의무, 구현 동작, 설명, 조사 계획의 근거 종류를 서로 합쳐 통과시키지 않는다.
한 문서만 읽는 데 필요한 짧은 계약 요약은 보존하며, 최종 전체 본문 감사와 공개 배포 확인은 후속 산출물에서 기록한다.

추가 다섯 문서는 독립 Codex CLI `gpt-6.1-terra/high`의 실제 생성과 근거 대조를 통과했다.
[동일 source212 답변 비교](prose-cleanup/extended-source212-comparison.json)에서 답변 텍스트는
16,856자에서 14,353자로 줄었다. 요청 수명주기는 5,200→3,880자, 문제 진단은 3,252→2,505자다.
[결합 질문의 근거 종류·필수 용어](prose-cleanup/extended-question-contracts.json)를 함께 보존한다.
전체 28개 원고의 건강 검사와 19개 LLM 원고의 현재 입력·본문·그림 검사는 통과했다.
이미 더 짧게 정리되어 공개된 source212 원고는 현재 계약을 재검증하여 유지했다.

최신 공개 [libcamera-sdd PR #60](https://github.com/TTolsun/libcamera-sdd/pull/60)의 원본 영수증과
체크포인트도 해시 대조해 복원했다. 복원 도중 아직 없는 영수증을 참조한 시도는 정상 검사에서 중단되었으며,
당시 원고 출력은 보존됐다. 전체 복원을 마친 뒤 정상 CLI 재개가 통과했다. 실패한 실행과 완료 단위 재사용을
신규 독립 시험으로 바꾸지 않았고, 원본 운영 메타데이터는 새 공개 증거 묶음에 넣지 않는다.

한영 계약 대조에서 대기 큐의 요청을 영어 `pending requests`로 옮긴 한 곳의 범위가 모호하게 판정됐다.
일반 번역·재시도·묶음 번역 지침에 `대기 요청`을 `waiting requests`로 구분하고 장치의 미완료 요청 전체로
범위를 넓히지 않는 규칙을 함께 적용한다. 해당 번역만 실제 CLI로 다시 요청하며, 수동 영어 문장이나
검토 판정 수정으로 통과시키지 않는다.

## 전체 HTML 감사의 최종 보완 범위

중간 사이트의 한영 60쪽·본문 822개를 다시 감사한 결과를 추가로 대조했다. 문서별 독립 요약과 서로 다른 함수의
조건은 유지하고, 12개 문서의 19개 주제에서 같은 대입·상태·전제·주어를 반복하는 질문을 정리한다.
기존 API 조건·반환·소유권·펜스 권고는 결합 질문에 남긴다. 초기화할 세 필드와 조사 기록도 함수별로 함께 설명한다.

같은 문서의 하드웨어 매칭 책임은 `vendor-integration/boundary`가 맡는다. 삭제한 개요 발췌 전체가
기존 상세 발췌에 포함되는 것을 [원문 포함 검사](prose-cleanup/handler-source-owner-proof.json)로 확인했다.
`completeBuffer`의 호출 책임은 버퍼 질문이, 마지막 버퍼와 별도의 요청 완료 조건은 완료 질문이 맡는다.
소스나 필수 조건을 사용하지 않는 질문에 붙여 검사를 우회하지 않는다.

시나리오의 전체 호출 수는 도입부에 한 번, hide 규칙의 수는 추적 범위에서 설명한다. 전체 호출·후보·예약 표시는
보존한다. 표시 지문을 갱신하여 기존 원고가 새 표시로 검증됐다고 조용히 통과하지 않도록 한다.
이 범위 이후에는 새 편집 과업을 확장하지 않고 실제 생성·한영 대조·사이트·공개 배포를 마무리한다.

종결 검토에서 cam의 별도 도구 소개를 문서의 기본 시험 명령 안내에 합치고, 제품 개요의 완료 의무도 한 번씩만
설명하도록 보완했다. 명령 안내는 README가 제시한 절차라는 소스 사실이며, 실제 장치 실행 결과를 뜻하지 않는다.
명령·옵션·프레임 수와 문서의 범위를 유지한 실제 CLI 생성·근거 대조가 통과했다.

마지막 편집 대조에서 축약 중 빠진 접근 검사 음수 반환·컨트롤 정보 맵의 주소 비교, 입력 크기 탐색의
최솟값 반복 조건·재초기화, IPA worker 검색·소켓 생성 인자를 복원했다. 같은 단계에서 남아 있던 대기 큐
삽입 설명도 한 번으로 제한했다. 해당 다섯 문서는 실제 CLI 12호출로 생성·근거 대조를 통과했다.

재사용의 버퍼 연결·목록 초기화·필드 초기화 구현은 `camera-requests/lifetime`이 맡는다.
요청 수명 문서는 소유권·버퍼 유효 기간·펜스 회수와 권고·핸들러 접근 의무를 보존하고 내부 구현 세 파트를
반복하지 않는다. 정지 관찰 지점은 같은 문서의 정지 절에 남겨, 뒤의 조사 목록에서 다시 나열하지 않는다.
계약 대조의 재사용 상태 근거도 상세 구현을 맡는 문서로 연결한다. 관련 계약·생성 검사 148개가 통과했다.
