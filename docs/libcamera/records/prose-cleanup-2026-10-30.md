# 공개 문서 본문의 중복 설명 정리

공개 libcamera SDD의 한국어·영어 60쪽에서 독자가 읽는 문단과 목록 842개를 모두 대조했다.
기준 배포는 `e9322a2e2fc3061e57257dc8ec705fc40abad680`이며 분석 소스는
`e117198c015057761bb0bbaa85f963c41ce412d7`이다. 표·코드·그림과 접힌 감사 기록은 이번 본문 감사에서 제외했다.

독립 Codex CLI의 `gpt-6.1-terra`, reasoning effort `high`로 세 묶음을 검토했다.
[페이지별 판정과 보존 조건](prose-cleanup/audit-before.json)은 수정 후보이며 자동 승인이나 사람 독자 평가가 아니다.
서로 다른 함수의 조건·오류·호출 책임은 중복으로 취급하지 않는다. 독립적으로 읽는 문서의 짧은 요약도 유지한다.

## 생성 질문의 정리

- `team-overview`: 네 계층의 순서를 소개한 뒤, 입출력·연동 예·책임 경계는 해당 절에서 설명한다.
- `ipa`: 실행 절은 호출 연결을, 종료 절은 호출 전제와 정리 순서를, 실패 절은 오류 분기를 맡는다.
  프록시 생성과 init/start, 모듈 로드 실패를 종료 절에서 다시 요구하지 않는다.
- `ipu3-lsc-flow`: 같은 첫 프레임 조건의 enabled/update와 한 호출의 대상·세 인자를 각각 한 문장으로 묶는다.
  기존 필수 식별자와 인자 순서는 유지한다.
- `framebuffer-allocator`: 반환 결과만 간결하게 설명하고, 근거를 읽는 과정인 if 범위 설명을 본문에 요구하지 않는다.
- 용어집의 FPS·ETIMEDOUT 표제어 반복과 IPU6·RK3399의 겹친 서술을 줄인다.
  타이머 설정값과 공식 문서에 기재된 지원 범위라는 한정은 유지한다.

기존 설계 질문의 필수 항목·조건을 삭제해서 분량을 줄이지 않는다.
원고·번역은 CLI를 통해 생성하고, 근거 대조와 게시 계약 검사를 다시 수행한다.

## 검증 상태

관련 독자 범위·답변 계약·설계 계약·용어집 검사 69개가 통과했다.
고정 공개 입력의 실제 CLI 생성·근거 대조, 공개 산출물과 Pages 확인은 진행 중이다.
사내 Camera HAL이나 실기기 검증 결과로 확대하지 않는다.
