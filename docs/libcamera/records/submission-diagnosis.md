# 요청 제출 오류 진단 보완

공개 libcamera의 `Camera::queueRequest()` 실패를 실제 검사 순서와 반환값으로 좁힐 수 있도록 기존 「구성과 요청 오류 조사」 문서를 보완합니다. 새 질문과 그림은 libcamera 예제 설정에만 추가하며 CLI와 `impact.json` 형식은 변경하지 않습니다.

## 보완 범위

- 연결 해제와 Running 상태 검사, 요청 생성 카메라, RequestPending 상태, control 정보 맵, 빈 버퍼 맵과 비활성 스트림을 각각 오류 코드에 연결합니다.
- 모든 검사를 통과한 뒤 AeEnable 전처리와 queued 호출을 예약하는 경로를 설명합니다. API 주석의 `-ENOMEM`과 함수 본문에 나타난 명시적 반환 분기는 구분합니다.
- 제출 검사 그림을 추가하고 기존 큐 그림의 취소 조건과 구성 함수 반환 분기를 바로잡습니다. 접근 검사, 실제 구현 조사 계획, 버퍼 추가 실패, 취소, 버퍼 완료와 요청 완료, 제출 순서의 그림을 해당 진단 질문에 연결합니다.
- 다른 절에서 이미 설명한 펜스 회수와 완료 후 소유권은 새 누락으로 집계하지 않습니다.

## 입력과 실행

공식 upstream 확인 결과는 `df8e348d64b4932a0676256ed24f0da3ee9438bc`입니다. 직전 공개 발행 이후 새 커밋은 없으며 기존 분석 커밋 `293d751a814e0d4c34e85ad457ccd9d5eefd1a61`과의 차이는 Meson 버전 선언입니다. 기존 구조 facts와 실행 기록을 보존하고, 동일 분석 커밋에서 새 질문의 소스 발췌를 수집했습니다. 새 구조 추출이나 0.8.0 실행 검증으로 표시하지 않습니다.

생성·번역은 공개 기본값인 독립 Codex CLI `gpt-6.1-terra`와 `model_reasoning_effort="high"`를 사용합니다. 최종 내용 검토와 문서 간 계약 대조는 별도 검토 프로필과 CLI 호출로 수행합니다. 과거 Claude 생성 기록과 사람 검토 상태는 보존합니다.

기존 대상 원고는 Claude로 작성되었으므로 이번 Codex 생성에서 다른 모델의 초안을 새 호출처럼 재사용하지 않았습니다. 대상 문서의 19개 단위를 새로 생성·근거 검사한 뒤, 그림 수정 후 재조립에서는 19개 네이티브 체크포인트를 모두 재검증·재사용했습니다. 첫 재조립은 약 6.03초였으며 새 모델 호출은 없었습니다. 이 수치는 전체 발행 시간의 개선율이 아닙니다.

## 검증과 한계

- 예제 프로필·공개 입력·그림 관련 회귀 검사 51개가 통과했습니다.
- 최종 독립 CLI 검토에서 19개 질문이 통과했고 `needs-work`는 0개입니다. 9개 그림의 소스 연결과 노드 한도를 검사했으며, 그림을 생략한 짧은 항목에는 개별 사유를 남겼습니다.
- 입력 변경 중 검토를 시도한 실행은 변경 감지로 거절되었습니다. 같은 작업의 동시 모델 실행도 실행 잠금으로 차단되었습니다. 이 기록과 수정 전 지적을 보존하며 성공 결과에 합산하지 않습니다.
- 이 기록은 해당 문서의 보완 범위입니다. 전체 시각화 이슈 #215, 전체 독자 평가 #163, 나머지 보류 계약, 실제 하드웨어 및 사내 HAL 검증의 완료를 뜻하지 않습니다.

공개 SDD의 후속 PR에 원본 CLI 기록, 항목별 판정, 한영 대조, 두 정상 export, Pages 배포와 공개 파일 대조 결과를 연결합니다. 배포 확인 전에는 로컬 생성만으로 발행 완료라고 표시하지 않습니다.

이 문서는 검증 범위와 기록을 안내하므로 별도 그림은 생략합니다. 독자가 사용할 그림은 생성되는 진단 문서에 있습니다.
