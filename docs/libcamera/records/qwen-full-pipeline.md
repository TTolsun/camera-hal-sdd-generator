# Local Qwen 전체 문서 시험

공개 libcamera의 13개 섹션과 19개 원고를 Local `qwen3.5:9b`로 생성·보완하여 문서 검사, 영어 번역, 한영 42개 페이지와 반복 빌드를 통과했습니다. 최초 전체 생성에서 실패한 항목은 생성기와 소스 질문을 개선하여 실제 모델로 보완했습니다. 통과한 답변·번역은 현재 검사를 다시 적용하여 유지했으며 원고를 사람이 대신 작성하지 않았습니다.

## 입력과 확인 범위

공식 upstream HEAD는 `2c4b67c0792f88f69bcdf9cbf73e81b3d8cf4b6f`입니다. 기존 300-TU 구조 facts(1,513개 클래스·589개 함수·6개 시나리오)를 재사용하고 해당 커밋에서 소스 발췌를 다시 수집했습니다. 새 구조 추출을 수행한 시험은 아닙니다.

10개 LLM 설명 문서의 56개 주제·387개 문장을 실제 요청·응답 해시와 대조했습니다. 나머지 원고는 추출 구조와 템플릿으로 만듭니다. `repair` 시험이며 모든 주제를 마지막 실행에서 새로 호출한 것으로 계산하지 않습니다. 실제 응답 수에는 실패·재시도·근거 대조도 포함되므로 통과 답변 수와 다릅니다.

이 시험은 기본 Hermes 운영 경로와 분리한 직접 HTTP 비교 시험입니다. 이후 main에 추가된 IPA 모듈 검사 문서는 별도 [실제 Hermes 시험](cli-runners.md)을 통과한 기존 원고를 유지합니다. 공개 게시본에는 이 문서가 추가되므로 전체 HTTP 시험의 13개 섹션·42개 페이지와 게시본의 문서 수를 구분합니다.

## 발견하고 고친 문제

소스 질문을 호출자 의무·관측 분기·조사 계획으로 나누고 함수 범위를 함께 확인하도록 했습니다. 독립 독자는 상태 허용 조건을 AND로 설명한 오류, 연결 해제 TODO의 잘못된 소속, void 함수에 다른 함수의 반환 계약을 붙인 오류를 찾았습니다. 질문·발췌와 재검사를 개선한 뒤 Qwen으로 보완했습니다.

조사 계획에 생성기의 `quote_id`와 근거 매핑 평가가 섞이면 거절합니다. 함수 이름 자리표시자가 빠진 번역은 게시하지 않으며, 통과한 항목을 유지하고 실패한 항목만 원래 자리표시자와 함께 재요청합니다. 서식 보완으로 기존 답변이 불필요하게 재생성되지 않도록 현재 검사 전에 코드 서식을 적용합니다. 코드 서식은 백틱만 추가하며 모델의 단어와 실제 응답 대조는 유지합니다.

사이드바는 독자 그룹 → 작업 분류 → 문서의 크기·굵기·들여쓰기를 구분합니다. 데스크톱과 모바일에서 확인했으며 모바일 가로 넘침은 없었습니다. 문서 검색과 그림 확대·요소 검색도 확인했습니다. 생성 HTML을 직접 수정하지 않았습니다.

## 독자 평가와 남은 범위

작성 맥락을 받지 않은 별도 평가자가 사이트 내부 발췌로 첫 파일·다음 읽을 곳, 요청 접수와 완료의 차이, 완료 누락 시 관측할 함수·값·분기, 구성 실패와 정지 문제의 시작점을 찾았습니다. 후속 평가에서 생성 검증 문구는 사라졌고, Markdown이 `_d()->metadata_`의 밑줄을 강조로 해석하는 표시 문제를 추가로 찾아 생성기에서 보완했습니다. 평가별 build ID·답·경로·한계는 공개 시험 자료에 보존합니다.

자동 검사·모델 근거 대조·독립 독자 평가·사람 승인을 구분합니다. 장치별 실제 실행과 요청 식별자·시각·스레드를 묶는 실행 기록 양식은 이 시험에서 검증하지 않았습니다. 사내 HAL·사내 LLM·폐쇄망 의존성·사내 게시와 사람 승인은 별도로 확인해야 합니다.

[공개 전체 시험 자료](https://github.com/TTolsun/libcamera-sdd/tree/main/qwen-full)에서 실제 모델 응답, 실패 시험 요약, 최종 원고·번역과 파일 해시를 대조할 수 있습니다. 생성기 실행 절차는 [사내 LLM 생성 시험](../../inhouse/contract-authoring.md#사내-llm-생성-시험)을 따릅니다.
