# Vendor 문서의 로컬 9B 오류 분석과 재시험

후속 [정확한 문서 작성 시험](vendor-9b-focused.md)과 [PR #84의 실제 Qwen 개요 생성](../qwen-overviews.md)을 함께 확인하세요. 이 페이지의 실패 및 대체 원고 기록은 당시 시험 결과입니다.

**의미 오류와 검증기의 오탐을 함께 수정하고, 공개 입력으로 실제 모델을 다시 시험했습니다.** 대상은 libcamera `2c4b67c0792f88f69bcdf9cbf73e81b3d8cf4b6f`이며 사내 HAL·실기기 검증이 아닙니다. 작성 세션의 소스 대조를 독립 평가나 사람 승인으로 취급하지 않습니다.

## 원응답에서 확인한 문제

| 사례 | 원문과의 차이 | 반영한 방법 |
|---|---|---|
| 정지 시 자동 완료 | 원문에도 automatic completion이 있습니다. 문제는 인접한 completeRequest 통지 의무를 떼어 내 무조건적인 보장으로 읽히게 한 점입니다. | 요청 추적의 주체와 파이프라인의 통지 의무를 같은 질문·문단에 둡니다. |
| 호출 스레드와 안전성 | completeBuffer를 CameraManager 스레드에서 호출하라는 계약에 순서·스레드 안전성 보장이라는 인과를 덧붙였습니다. | 근거 유형을 선언하고 알려진 과장 표현을 차단합니다. 부정 문장도 시험해 오탐을 확인합니다. |
| stopDevice의 역할 | 장치 구현자가 지켜야 할 계약을 관측한 구현처럼 설명하고 취소·오류 상태를 생략했습니다. | 계약형 의무 표현과 취소·오류의 누락을 검사합니다. 공통 stop 구현과 장치 계약을 나눕니다. |
| 구성 검증 상태 | Adjusted만 설명하고 Invalid·Valid를 빠뜨렸습니다. 발췌 끝의 다른 함수 선언도 요약했습니다. | 세 상태를 각각 질문하고 식별자 경계로 확인합니다. 관련 없는 끝 선언을 발췌에서 제외합니다. |
| 확인 의무의 오탐 | 원문의 caller shall check를 옮긴 문장을 “확인해야”라는 단어 때문에 근거 부족으로 거절했습니다. | 인용에 확인 의무가 있고 답변이 호출자의 의무를 설명하는 경우를 구분합니다. 근거 불명확 문장까지 통과시키지는 않습니다. |
| 재시도와 분량 | 이전 답변 없이 오류만 보냈으며, 짧은 완전한 답도 일반 산문의 80자 하한으로 거절했습니다. | 거절한 초안과 오류를 함께 보내고 구조화된 답변에서는 최소 분량 대신 내용·근거 연결을 검사합니다. |

세 Vendor 페이지의 12개 주제를 30개 작은 질문으로 나눴습니다. `answer_contract`의 근거 유형·필수 용어 대안·알려진 오류 패턴은 예제 설정에 있습니다. 공통 검사에 libcamera 식별자를 넣지 않았습니다. 저장 원고와 내보내기에서도 분할 질문 ID, 근거 범위와 누락을 다시 검사합니다. 단어·문체 검사가 조건의 정확성과 의미를 증명하지는 않습니다.

## 시험 조건과 판정

모델은 Ollama `qwen3.5:9b`, Q4_K_M, digest `6488c96fa5faab64bb65cbd30d4289e20e6130ef535a93ef9a49f42eda893ea7`입니다. 재시험의 Ollama 버전은 0.40.11입니다. temperature 0.1, num_ctx 16384, 재시도 1회, design_revision false를 사용했습니다. 질문을 다듬는 중간 시험과 마지막 설정의 시험을 구분하여 보존합니다. 초기 결과와의 비교는 질문·검사가 함께 바뀐 비교이며 특정 변경 하나의 효과를 증명하는 실험은 아닙니다.

| 실행 | 자동 검사 결과 | 작성자의 소스 대조 및 한계 |
|---|---|---|
| 기존 시험 (`local-trial`) | 2/3 문서 통과 | 통과 문서에도 의무·안전성 오류가 있어 채택하지 않았습니다. |
| 질문·검사 보완 후 (`semantic-final1`, think=false, 출력 4000) | 0/3 문서 통과 | Camera 명시, 호출자 동기화, null 반환의 최소 답변 조건을 충족하지 못했습니다. 각 문서는 첫 실패에서 중단하므로 뒤의 모든 질문을 평가한 결과가 아닙니다. 용어 누락 검사 자체를 의미 판정으로 세지 않습니다. |
| 추론 설정 비교 (`semantic-reasoning1`, think=true, 출력 6000) | 0/3 문서 통과 | 세 문서 모두 최종적으로 출력 한도 내 답변을 만들지 못했습니다. 약 909초가 걸렸고, 중간에 Invalid·Adjusted·Valid 답변은 생성됐습니다. 전체 자동 작성 성공이 아닙니다. |
| 오류별 독립 질문 1·2회 (`semantic-regression1`, `semantic-regression2`) | 각각 3/6 질문 통과 | 정지 시 통지, 버퍼/요청 완료 구분, stopDevice 취소·오류 누락을 차단했습니다. Invalid의 잘못된 “또는” 조건은 용어 검사를 통과하여 추가 회귀 사례로 남겼습니다. 두 번째 Adjusted 답변은 변경 가능성을 이미 변경된 사실처럼 표현한 문제가 있습니다. |
| Invalid 오류 패턴 추가 후 (`semantic-regression3`) | 3/6 질문 통과 | 같은 세 완료·정지 질문은 계속 차단됐습니다. 이번 Invalid·Valid 답변에는 앞선 조건 오류가 없었으며, 이전 실제 Invalid 오답은 추가 검사로 거절됨을 회귀 테스트로 확인했습니다. Adjusted의 “모든 스트림” 표현은 원문의 any stream과 다시 대조해야 하므로 자동 통과를 채택으로 올리지 않았습니다. |

오류별 시험은 앞 질문의 실패 때문에 다른 사례를 놓치지 않도록 여섯 질문을 독립 섹션으로 실행했습니다. 페이지 전체 시험의 독자 프로필과는 범위가 다릅니다. 추론 시험 뒤에는 roles를 자연스럽게 번역한 “역할 목록·스트림 용도”도 필수 용어의 대안으로 허용했습니다. 마지막 회귀 시험에는 관측한 Invalid 조건 오류 차단 규칙도 포함합니다. 각 실행의 설정 사본과 해시로 이 차이를 구분합니다.

**이 모델 설정에서 Vendor 문서의 무인 생성·게시 품질이 확보됐다고 판단하지 않습니다.** 검증기가 거절한 답변을 자동으로 고쳐 사실처럼 게시하지 않았습니다. 남은 자연어 의미 오류는 문자 기반 검사만으로 모두 막을 수 없습니다. 평가 도구는 실제 연결만 허용하며 원고 게시나 사람 승인을 수행하지 않습니다.

공개 문서의 세 페이지·30개 답변은 이 작성 세션이 원문과 대조한 `response-bundle/codex-session` 원고입니다. 로컬 9B 응답이라고 표시하지 않습니다. 나머지 원고 16편과 이전 Qwen EGL 갱신 근거, 최신 main의 작업별 탐색 메뉴를 유지합니다. 새 한국어 원고와 영어 번역은 모두 사람 검토 전입니다.

통합 회귀 테스트는 792개 통과·1개 건너뜀이었고, 마지막 Invalid 회귀 사례를 포함한 관련 테스트는 68개 통과했습니다. 공개 산출물은 한영 42페이지, 링크 오류 0개, 반복 빌드의 98개 파일 일치를 확인합니다. 실행 보고서·공개 입력에 대한 실제 요청/응답 기록과 작성자 대조는 [공개 재시험 근거](https://github.com/TTolsun/libcamera-sdd/tree/main/vendor-llm-retest)에서 확인할 수 있습니다. 추론 토큰 한도로 답변이 없었던 호출에는 성공 응답 영수증이 없으며 evaluation.json의 실패로 기록합니다.

## 사내 적용 범위

사내에서는 같은 질문 분할·근거 유형·재시도·검증 코드를 사용하되 실제 HAL의 함수·조건·근거와 승인 기준을 설정해야 합니다. 사내 LLM은 `ollama` 또는 `openai-compatible` 연결로 교체할 수 있습니다. libcamera에 대한 시험 통과도 사내 모델과 코드에서 같은 품질을 보장하지 않습니다.

새 오류는 원응답·입력 지문과 함께 회귀 사례로 남기고 올바른 문장도 같이 시험하세요. 검사 통과율과 문장별 의미 대조를 따로 기록하고, 실제 제품 사양·지원 조합·성능 측정 근거가 없으면 구매·홍보용 보장을 만들지 않습니다. 절차는 [사내 계약 집필](../../inhouse/contract-authoring.md#사내-llm-생성-시험), 설정은 [답변 계약 참조](../../reference/sections.md#답변의-누락과-알려진-오류-검사)에 있습니다.
