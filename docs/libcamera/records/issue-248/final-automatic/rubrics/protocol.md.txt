# 고정 기준본으로 독자 평가를 진행하세요

이 절차의 과업·성공 조건은 2026-11-05에 자동 결과 관측 전에 고정했습니다. [#163의 절차](../goal-162-163/reader-protocol.md), [고정한 진행자 채점 기준 사본](rubric-163.md), 빈 실제 결과를 재사용합니다. 자동 시험 뒤 추가한 기록 검사는 과업·성공 조건을 바꾸지 않으며 실제 사람 평가는 아직 시작하지 않았습니다. 과거 자동 평가와 해결된 탐색·그림 문제를 새 사람 관측으로 계산하지 않습니다. 최종 대상은 사내 Camera HAL이며 이 시험은 공개 libcamera 문서에 한정됩니다.

## 기준과 선정 범위

공개 URL은 https://ttolsun.github.io/libcamera-sdd/ 입니다. 기준 build_id는 `10b23c926b880b542f12e88ef22352f75b5cb7271cdb52f3bb5020eb4e0e4a93`, 공개 저장소 커밋은 `f7f82444a5d93fcd49b7fd388e52e55582d4f2fa`, 생성기 main은 `25f65afa160878db732e9739db5043d753ba3bfb`입니다. 원본 manifest와 페이지 해시는 `baseline.json`에 고정합니다. 분석 소스와 upstream mirror는 별도로 기록합니다. 평가 직전과 직후 manifest를 비교하고, 다른 빌드는 섞어 채점하지 않습니다. 고정 커밋의 `docs/` 사본으로 재현할 수 있습니다.

기존 여섯 경로는 소개→기술 채택→연동→코드 탐색을 대표하므로 유지합니다. 중단 후 조사 재개를 위해 `request-diagnosis.html`과 연결된 `request-lifecycle.html`을 추가합니다. 전체 사이트·전체 시각화(#215)·실기기·사내 HAL·임상적 ADHD 이해 검증은 제외합니다.

## 참가자에게 전달할 과업

비작성자 최소 3명에게 각각 아래 두 기본 과업과 S·R·X를 수행하게 합니다. 신입 관점과 타팀 관점을 각각 한 명 이상 포함합니다. 참가자에게는 시작 URL, 배정 과업과 기록 양식만 주고 이 절차의 채점 기준은 주지 않습니다.

| 참가자 관점 | 기본 과업 1 | 기본 과업 2 |
|---|---|---|
| 신입 | index에서 처음 열 문서와 요청을 따라갈 다음 문서·절을 찾고 선택 이유를 설명하세요. | overview에서 요청의 소유자·삭제 책임과 재사용 전 절차를 근거와 함께 찾으세요. 연결된 상세 문서로 이동해도 됩니다. |
| 타팀 | vendor-overview에서 공통 계층과 장치 구현의 책임·지원 한계를 찾으세요. | vendor-assurance에서 내장 벤치마크에 포함·제외되는 처리를 찾으세요. |
| 비작성자 | vendor-integration에서 마지막 버퍼 완료와 요청 완료의 차이, 명시 호출자·스레드를 찾으세요. | scenarios/queue_request에서 요청 전달 대상과 예약된 호출 표기, 정적 추적의 한계를 찾으세요. |

1. **S 자기 설명:** 제출 함수가 성공을 반환했지만 완료 알림이 없습니다. 성공 반환과 완료가 무엇이 다른지 문서를 닫은 상태에서 자기 말로 설명하세요. 이어 문서를 열고 자신의 설명을 뒷받침하는 위치를 찾으세요.
2. **R 중단 후 복귀:** 완료 누락 조사를 시작하고 확인한 단계·관측값·아직 모르는 점·근거·다음 분기를 자유 형식 메모로 남기세요. 문서를 닫고 5분 동안 무관한 일을 하세요. 같은 시작 URL로 재진입하여 자기 메모만 이용해 조사 상태, 다음 행동과 근거를 다시 찾으세요. 중단 전·후 URL, 돌아간 경로, 재탐색 시간과 막힌 이유를 따로 기록하세요. 기억만으로 답하거나 실제로 닫지 않았다면 복귀 성공으로 세지 않습니다.
3. **X 새로운 조건:** 같은 요청에 버퍼가 둘 있습니다. 하나의 버퍼 완료만 관측했습니다. 무엇을 완료로 단정할 수 있고, 무엇을 더 조사해야 합니까? 문서 근거를 제시하세요. 기본 과업의 전후 비교 점수에는 합산하지 않습니다.

기본 과업은 각각 10분, S·X는 각각 10분, R의 복귀 탐색은 10분을 상한으로 사용합니다. 상한을 넘거나 도움을 받거나 중단해도 원래 분모에 남깁니다. 소요 시간은 관측한 값만 기록합니다. 자동 에이전트는 사람의 망각·주의 중단을 재현할 수 없으므로 R을 탐색 절차 시험으로만 기록합니다.

## 사전 고정 성공 조건

기본 여섯 과업은 #163의 채점 기준을 그대로 적용합니다. 세 사람에게서 최소 6과업 중 5개 이상이 정확한 답과 유효한 근거를 작성자의 설명 없이 찾아야 합니다. 읽기 부담 척도는 1=매우 부담됨, 5=부담이 매우 낮음이며 모든 배정 기본 과업의 중앙값이 4 이상이어야 합니다. 누락 점수는 좋은 점수로 보충하지 않고 평가 미완료로 처리합니다. 참가자를 추가하면 결과를 모두 포함하고, 각 사람에게 두 과업을 배정합니다. 같은 과업의 반복 성공으로 다른 질문의 실패를 가리지 않도록 서로 다른 기본 과업 5개 이상의 성공도 확인합니다.

S는 세 사람 각각 (a) 성공 반환은 요청 접수/전달 성공이며 완료 증명이 아님, (b) 비동기 처리 후 별도 요청 완료 통지를 확인함, (c) 버퍼 완료와 요청 전체 완료를 구분함을 자기 말로 설명하고 해당 근거를 다시 찾아야 합니다. 문서 문장 복사는 자기 설명으로 인정하지 않습니다.

R은 세 사람 각각 중단 전 조사 상태를 복원하고, 실제 함수·값을 확인하는 다음 행동과 그 결과에 따른 다음 분기를 유효한 근거로 찾아야 합니다. 아직 관측하지 않은 상태를 실행 사실로 단정하거나 상태 변경 함수를 관측 목적으로 재호출하는 계획은 실패입니다. 진행자는 중단·재진입을 확인하고 원문 메모와 방문 기록을 남깁니다. 최소 의미를 모두 충족해야 성공이며 속도만으로 채점하지 않습니다.

X는 남은 버퍼·요청의 완료 여부를 단정하지 않고 추가 완료 상태와 요청 완료 통지 조건을 조사해야 합니다. 기준 근거는 `vendor-integration`의 요청 반환, `request-lifecycle`의 버퍼/요청 완료와 `request-diagnosis`의 완료 누락 분기입니다. 실제 페이지·발췌 링크는 기준본에서 확인해 `facilitator.md`에 고정합니다.

쉬움, 흥미, 문장의 자연스러움은 각기 1~5점과 이유 원문을 받습니다. 1=매우 어려움/흥미 없음/매우 부자연스러움, 5=매우 쉬움/매우 흥미로움/매우 자연스러움입니다. 흥미·자연스러움에는 합격 최저점을 새로 만들지 않으며 정확성·부담 점수와 합산하지 않습니다. 낮은 응답을 삭제하거나 긍정 답변을 유도하지 않습니다.

## 기록·비교·공개

`human-results.csv`는 실제 사람만, `agent-results/`는 자동 시험만 보관합니다. 각 기록에는 참가자 ID·관점·비작성 여부·build_id·과업·답변 원문·URL/앵커·근거·시작/종료 시각·실측 초·방문/되돌아간 경로·도움·정확성·막힌 이유를 남깁니다. S에는 문서를 닫았는지, R에는 중단 전 메모·중단/재진입 관측·복원 상태·다음 행동/분기를 추가합니다. 미발견과 미측정을 그대로 남깁니다.

원본은 로컬 비공개로 수집합니다. 공개 가능 여부가 확인되기 전에는 원문을 커밋하지 않으며 공개 저장소에는 익명 집계만 올립니다. 에이전트 결과는 출처를 표시한 자동 시험으로 공개할 수 있습니다. 작성자가 참가자에게 임의로 연락하지 않습니다.

병목별로 관측 위치→원인 가설→설명 소유 위치→수정→동일 과업 재평가를 기록합니다. 설명 순서·용어·그림·상세 연결은 관측 근거에 맞춰 생성 경로에서 수정합니다. 새 분량·그림 수는 성과 지표가 아닙니다. 같은 참가자의 전후 결과는 학습 효과가 있으므로 새 조건 X 및 처음 읽는 새 참가자의 결과와 구분합니다. 소표본의 성공률을 일반 사용자 전체로 확대하지 않습니다. 결과를 본 뒤 채점 기준을 낮추지 않으며 범위·기준 변경은 이유·시점·재평가 필요성을 기록합니다.

다음 단계는 참가자에게 `participant.md`와 해당 과업의 빈 기록 행을 전달하는 것입니다. 실제 사람 평가가 남으면 #163·#248과 Goal 전체를 완료 처리하지 않습니다.
