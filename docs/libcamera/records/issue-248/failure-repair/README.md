# 완료 단계와 복귀 메모를 다시 검증했습니다

세 역할에 [사전에 고정한 과업](plan.md)을 배정했습니다. 신입, 타팀, 비작성자 역할을 각각 새 에이전트에 맡겼습니다. 이전 답변과 정답표는 제공하지 않았습니다. 실제 참가자는 0명이며 이슈 #248과 #163의 사람 평가와 전체 Goal은 미완료입니다.

| 자동 과업 | 이전 판정 | 새 세 역할의 첫 독립 판정 |
| --- | ---: | ---: |
| 기본 이해·탐색 | 5/6 | 6/6 |
| 자기 설명과 근거 재탐색 | 2/3 | 2/3 |
| 중단 후 상태·행동·근거 복원 | 2/3 | 1/3 |
| 새 조건 적용 | 3/3 | 3/3 |

이전 비작성자 역할이 놓쳤던 `completeRequest()`의 CameraManager 호출 계약과 중단 전 제보·미확인 상태를 새 비작성자 역할은 근거와 함께 찾았습니다. 새 신입 역할은 자기 설명에서 버퍼와 요청 전체의 완료를 구분했으나, 재열람 답에 그 차이를 뒷받침하는 절을 인용하지 못했습니다. 새 복귀 답변 두 개에는 각각 버퍼 알림의 미확인 상태 누락, 제보와 실측의 혼동이 남았습니다. 첫 판정과 원답을 유지했습니다. [응답과 판정 요약](trial-summary.json)

평가 후보 build_id는 `236846f043d327f50e060de29ac5b8e20ca0e42b6378e23def6d2eae43fe4270`입니다. Chrome에서 고정 HTML을 렌더링하고 방문별 응답 해시와 화면을 보존했습니다. 재열람 전 자기 말 원답과 중단 전 메모는 각각 별도 파일로 저장했습니다. 338.775초, 326.833초, 322.630초 뒤 시작 주소에서 재개했고 메모 바이트의 동일성을 확인했습니다. 모델이 앞 문맥을 유지하므로 이 간격은 자동 탐색 절차에 대한 기록입니다. 기본 과업의 쉬움·흥미·자연스러움은 각각 에이전트 추정 중앙값 4/5이며 이유와 원답이 함께 있습니다. 이전 표본과는 빌드와 열람 방식이 다릅니다.

연동 가이드에서 `completeRequest()`의 스레드와 함수 반환 후 요청 접근 금지로 바로 이동할 수 있게 했습니다. 개요의 기존 그림에 접수 반환, 버퍼 알림·추적, 별도 요청 완료를 함께 표시했습니다. 공통 `site.reading_checkpoints`는 조사 메모를 쓰는 위치를 제공하며, 제보·관측·해석·미확인·다음 분기·근거를 구분합니다. 짧은 연결과 빈 메모에는 링크와 목록이면 충분합니다. 새 평가의 재열람 및 복귀 경로를 보고 요청 수명 주기에서도 개요와 진단 메모로 연결했습니다.

두 번째 평가 후보는 공개 PR #99의 `c19d05128f3ae1f0ebe63acb4deaca9fbb1dde78` 입력으로 만들었습니다. 기존 그림에 사용한 두 소스 창의 파일·줄·원문·해시가 같음을 확인했습니다. 당시 생성기 인용 정책에 따라 세 원고의 그림 메타데이터를 다시 검증했으며 본문은 그대로입니다. 개요에서는 기존 생성기 관리 그림 영역만 바뀌었습니다. 이 후보의 한영 검토와 표준 계약 감사가 통과했고, 66개 HTML과 358개 산출물을 반복 빌드로 확인했습니다. 이후 공개 PR #100과 #102를 반영한 발행본, 별도 S·R 확인 및 Pages 기록은 발행 PR에 연결합니다. [생성기 PR #285](https://github.com/TTolsun/camera-hal-sdd-generator/pull/285)
