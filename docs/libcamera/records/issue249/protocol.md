# 요청 완료 통지와 버퍼 회수 경계의 평가 기준

평가 질문은 [questions.json](../../../../examples/libcamera/validation/issue249/questions.json)에 먼저 고정했습니다. 읽기 평가에는 이 질문과 최종 문서만 전달하며, 채점 근거·작성 대화·생성 설정은 전달하지 않습니다. 별도 Codex CLI / gpt-6.1-terra / high를 사용하고 실제 사람 평가와 구분합니다.

## 대표 문서와 설명 소유권

기존 `request-lifecycle.md`의 `요청·버퍼·fence의 수명`을 대표 항목으로 보강합니다. 새 페이지를 만들지 않습니다. 제출·대기·완료의 전체 흐름은 같은 페이지의 `제출에서 완료까지`, 재사용 필드 초기화 구현은 `camera-requests.md`, 파이프라인 구현 계약은 `pipeline-requests.md`, 장애 조사 절차는 `request-diagnosis.md`가 소유합니다. 대표 항목은 이 계약들이 버퍼 회수 판단에 어떻게 연결되는지 설명합니다.

기존 항목의 첫 요약과 `request-owner`는 삭제·재사용 책임을 반복합니다. `buffer-duty`, `complete-access`, `cancel-rules`는 같은 수명 경계를 각기 작은 질문에서 되풀이할 수 있습니다. 이 전제를 문제·원리·정상 흐름·조건 변화·변경 확인으로 묶고 필수 조건은 유지합니다. 최종 조립본과 관련 문서의 의미 중복을 다시 확인합니다.

## 비교와 합격 기준

공개 manifest·원고·소스 커밋과 본문 해시를 기준본으로 보관했습니다. 평가 질문과 결과·코드 위치·판단 조건·다음 확인이라는 비교 요소는 생성 전에 고정했습니다. 최초 채점표가 질문 밖의 API 세부와 식별자 철자까지 요구한 문제를 발견해 그 비교는 제외했습니다. 질문은 바꾸지 않았으며, 명확히 한 동일 채점표를 기준본과 개선본에 적용했습니다. 채점표의 최초·수정본과 모든 실패·재평가 원본을 보존합니다. 재평가에도 독립 읽기 CLI에는 정답표나 수정 설명을 주지 않습니다.

검토 창은 처음 12개였으며, B의 완료 상태를 직접 확인할 `Request::Private::complete()` 구현 창을 추가해 13개가 됐습니다. 최초 준비 스크립트의 고정 파일은 이후 준비 시 갱신됐으므로 최종 `freeze.json`을 최초 시각의 불변 스냅샷이라고 부르지 않습니다. 기준 원고·고정 질문과 최초 실제 CLI 요청·응답이 원래 비교 입력을 보존합니다. 이후 공식 upstream 갱신에서는 이 창을 포함하는 파일의 바이트가 같음을 Git diff로 대조했습니다.

필수 조건 누락, 결과를 바꾸는 오답, 근거 접근 실패가 하나라도 있으면 수정 후 새 CLI 호출로 재평가합니다. 읽기 답변을 생성 원고로 사용하거나, 저장 응답을 새 추론으로 표시하지 않습니다. 같은 입력의 원고 재사용은 별도 검증 범위입니다.

평가 범위는 공통 요청 완료와 버퍼 수명입니다. 개별 하드웨어 파이프라인의 DMA·캐시·타이밍, 실제 기기 실행, 사내 HAL, 실제 사람의 이해도는 검증 범위 밖입니다. 설계 선택의 역사와 대안 비교는 결정 기록이 없으면 주장하지 않습니다.

## 반복 생성과 변경 검증

같은 입력의 재생성에서 설명 순서·답변·발췌·그림·필수 조건이 보존되는지 확인합니다. LLM의 새 호출이 바이트 단위로 결정적이라는 뜻은 아닙니다. 질문·소스·설명 구성 변경 시 과거 원고의 검증·재사용이 거절되고 해당 범위가 새 검토 대상으로 잡히는 회귀를 실행합니다. 원고와 사이트의 사람 승인 상태는 승격하지 않습니다.

고정 질문은 `examples/libcamera/validation/issue249/evaluate.py --mode reading`으로 문서만 읽게 합니다. 별도 근거 검토는 같은 명령의 `--mode grounding --sources ...`로 실행합니다. 읽기 결과의 문서·질문 해시를 확인한 뒤 `grade.py --document ... --answers ... --out ...`로 채점합니다. 모든 호출은 별도 `independent-review.yaml`의 Codex CLI / `gpt-6.1-terra` / high를 사용합니다. 출력 경로가 이미 있으면 원본 보존을 위해 거절합니다.

실제 사람의 이해도 변화는 #248의 별도 과업입니다. 참여자 결과가 없는 동안 자동 5문항 통과로 사람 평가 또는 이슈·Goal 전체 완료를 표시하지 않습니다. 참여자에게 임의로 연락하지 않습니다.
