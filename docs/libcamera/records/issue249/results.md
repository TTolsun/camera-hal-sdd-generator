# 요청 완료 상태와 자원 회수 판단의 대표 사례

대표 항목은 기존 `request-lifecycle.md`의 **요청·버퍼·fence의 수명**입니다. 새 중복 페이지를 추가하지 않았습니다. 문제 → 소유권과 두 완료 경계 → 정상 완료 → 조건 변화·실패 → 변경 확인의 다섯 단계가 기존 질문별 근거를 연결합니다. 생성기의 공통 `explanation` 계약과 단계별 그림 배치는 [사용법](../../../reference/explanation.md)에 있습니다.

## 독자가 새로 판단한 내용

고정된 문서 읽기 과업에서 기준본은 B의 내부 `complete()` 이후 상태값을 문서 안에서 확인하지 못했습니다. 개선본의 독립 CLI 독자는 `cancelled_`가 주어지지 않으면 `RequestComplete`와 `RequestCancelled`를 모두 고려해야 한다고 답했습니다. 이 상태 선택과 애플리케이션 반환은 별개이며, 반환 루프는 매번 선두를 다시 검사하므로 A가 완료됐다는 사실만으로 중간 Pending 요청을 건너뛰어 B를 반환하지 않습니다.

버퍼 알림·요청 완료 상태·애플리케이션 콜백·완료 함수 반환 뒤 핸들러 접근은 서로 다른 판단 경계입니다. 마지막 버퍼 알림만으로 해제·재연결의 안전성을 확정하지 않으며, 콜백을 아직 관찰하지 못했다는 사실로 내부 추적이나 완료 호출이 아직 남았다고 단정하지 않습니다. 버퍼 유효성 의무도 모든 재사용의 일괄 금지로 확대하지 않습니다. 이 네 과업은 기준본도 통과했으므로 새로 획득한 능력으로 부풀리지 않습니다.

변경 확인은 조기 재사용과 다른 스레드의 직접 완료 호출을 대상으로 합니다. 문서는 내부 버퍼 추적, 추가 처리, 명시적 완료, 제출 순서, 호출자의 버퍼 유지와 핸들러의 접근 종료를 함께 대조하도록 합니다. `completeBuffer`·`completeRequest`의 CameraManager 스레드 호출 의무는 애플리케이션 콜백의 실제 실행 스레드 보장이 아닙니다. 역사적 설계 의도와 대안의 성능 우위는 결정 기록이 없어 주장하지 않았습니다.

## 분량과 설명 소유권

아래 수치는 저장된 `generated_design.answers[].text`의 Unicode 글자 수입니다. 메타데이터·렌더러가 붙인 인용·접힌 원문·제목·Mermaid는 제외하며 인라인 코드 표기는 포함합니다.

삭제한 기존 답변의 부분 문구를 수동 재작성하지 않았습니다. 전체 답변 선택의 해시와 이동 이유를 `integration_lineage.whole_statement_selections`에 남기고, 새 대표 항목은 실제 지정 CLI로 생성했습니다. 기존 구현·진단 문서의 고유 질문은 유지했습니다. 제출 요약을 전부 삭제하거나 필수 실패 조건을 줄여 분량을 낮추지 않았습니다.

## 평가와 수정 이력

[평가 절차](protocol.md)의 다섯 질문은 생성 전에 고정했습니다. 독립 읽기 CLI에는 질문과 frontmatter를 제외한 문서만 주었습니다. 별도 채점 CLI가 문서 해시·질문 해시가 일치하는 답변을 평가했습니다. 최종 비교는 **기준본 4/5, 개선본 5/5**이며, 사람의 이해도 점수나 통계적 효과가 아닙니다.

최초 2/5 대 5/5 비교는 채점표가 질문 밖의 API 상세·식별자 철자까지 요구한 탓에 제외했습니다. 질문은 그대로 두고 양쪽 문서에 같은 기준을 적용하자, 중간 개선본 역시 미지정 취소 플래그의 참 분기를 놓쳐 4/5였습니다. 그 미발견을 실제 구현 창과 본문·그림으로 보완한 뒤 다시 읽게 했습니다. 불리한 결과와 실패 초안도 원본으로 보존합니다.

독립 소스 검토는 제출 성공을 콜백 시각 보장으로 바꾼 표현, 이미 완료된 B의 재취소로 읽히는 예, 모든 버퍼 재사용을 금지하는 과장, 중간 Pending 요청을 생략한 그림 관계를 지적했습니다. 각각 수정 후 새 CLI 검토를 받았습니다. 최종 대표 항목의 본문·그림·조건부 예는 제공한 13개 고정 소스 창과 대조해 통과했습니다. Chrome에서 겹친 루프 간선 두 문구도 줄였으며, 답변 본문·근거가 같음을 확인하고 최종 문서를 다시 읽게 했습니다.

독립 코드 리뷰가 찾은 단계 제목의 HTML 주석 삽입도 설정 검증에서 거절하도록 고쳤습니다. 관련 회귀는 생성 전 모델 호출 차단과 발행 조립 경로를 확인합니다. 같은 입력 반복은 새 추론 없이 설명 순서·답변·근거·그림이 유지되는 검증이며, 새 LLM 표본의 문장이 항상 같다는 주장이 아닙니다. 질문·소스·단계 변경의 입력 지문 무효화와 다른 주제 보존도 검사합니다.

## 소스와 공개 통합 범위

공식 upstream과 공개 mirror는 `be7e83e91348250c015aad6d6f59f1468555bae8`을 확인했습니다. 종전 `293d751a…` 이후 변경 세 파일은 대표 항목의 실제 근거 파일과 겹치지 않았습니다. 최종 facts는 최신 소스를 실제 Meson/Ninja 빌드·Clang 추출한 결과이며, 294개 번역 단위의 파싱 오류는 0개, 시나리오는 6개입니다. 클래스 1,412개에서 1,403개로 바뀐 차이는 LC-compliance 테스트 도구의 다섯 번역 단위를 이번 빌드에서 제외했기 때문이며 소스 삭제나 전체 커버리지 증가로 표시하지 않습니다. 10개 파이프라인과 7개 IPA를 포함했습니다.

새 대표 항목의 원래 생성 소스는 `293d751a…`이며 해당 창의 바이트 일치와 전체 인용을 최신 facts에서 다시 검증했습니다. 영향 밖 원고는 원래 생성자·날짜·원본 소스를 보존해 현재 근거에 이월했습니다. 동시 병합된 공개 #243의 최신 원고·두 그림·번역과 원래 인증 프로필도 보존했습니다. 이를 이번 작업의 새 생성으로 세지 않습니다.

과거 WSL 가상 CPU 프로브는 재실행하지 않았습니다. 실제 기기·DMA·캐시·시간, 사내 HAL와 실제 독자의 이해 변화는 검증하지 않았습니다. 자동 검토는 사람 승인이 아니며 #215의 전체 시각화 보완 완료도 뜻하지 않습니다.

생성기 병합·전체 계약 대조·최종 사이트·Pages의 확정 결과는 공개 발행 기록과 이 이슈의 최종 댓글에 각각 남깁니다. 실제 사람 참여 결과가 없는 동안 이슈와 Goal 전체는 완료로 표시하지 않습니다.
