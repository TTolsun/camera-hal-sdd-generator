# Vendor 문서 구성과 생성 검증

**제품 개요, 연동 가이드, 지원 범위와 검증을 분리했습니다.** 공개 libcamera 소스 `2c4b67c0792f88f69bcdf9cbf73e81b3d8cf4b6f`를 대상으로 합니다. 사내 HAL이나 실제 장치 시험 결과가 아닙니다.

| 문서 | 독자가 판단할 내용 | 근거 |
|---|---|---|
| libcamera 제품 개요 | 어떤 문제를 해결하고 어떤 기능과 설계 강점을 제공합니까? | 공식 소개, Camera, 공통 요청 큐 |
| 연동 가이드 | 어떤 순서로 연결하고 누가 무엇을 구현합니까? | Camera, PipelineHandler, IPA 선택·완료·정지 계약 |
| 지원 범위와 검증 | 구성 제약은 무엇이며 성능 자료가 어디까지 입증합니까? | 구성 검증 계약, Software ISP 측정 범위 |

처음 제안한 긴 제목과 단일 페이지는 채택 판단과 구현 계약을 섞었습니다. 현재는 세 페이지의 12개 주제로 나누고 개요의 분량 한도 예외도 제거했습니다. 요청 진단·Pipeline Handler·IPA·개별 알고리즘 문서는 구현자가 찾는 대상이 분명하므로 상세 제목을 유지합니다.

소스에 공통 큐 관리가 있다는 사실은 설명할 수 있지만 제품의 성능 우위, 지원 기종, 고객 요구 충족이나 양산 품질을 입증하지는 않습니다. 공식 벤치마크 절차도 이 문서에서 실행한 측정 결과로 표현하지 않습니다. 구매·임원 홍보 자료로 확정하려면 실제 제품의 사양·지원 조합·측정 결과·공개 승인을 추가해야 합니다.

## 반복 생성과 사내 적용

공통 프로필 `vendor-overview`, `vendor`, `vendor-assurance`를 공개 예제·사내 템플릿·mini HAL에 적용했습니다. libcamera 이름이나 빌드·호스트·모델은 공통 프로필에 넣지 않습니다. 실제 사내 근거가 없는 템플릿은 생성을 통과하지 않습니다.

`python -m sdd.evaluate_reader`는 운영 원고와 분리된 폴더에서 설정한 실제 모델을 호출합니다. 원응답, 입력 커밋, 설정·출력 지문과 성공·실패를 남기며 자동 검사 통과를 사람 승인으로 올리지 않습니다. 연결·실행 방법은 [계약 집필 절차](../../inhouse/contract-authoring.md#사내-llm-생성-시험)에 있습니다.

공개 게시 원고는 Codex 세션의 소스 대조 답변을 입력 해시에 묶은 response-bundle로 생성합니다. 이는 사내 LLM의 품질을 입증하지 않습니다. 별도 실제 모델 시험 결과는 아래에 기록합니다.

## 로컬 모델 시험 결과 — 2026-10-25

Ollama의 `qwen3.5:9b`(Q4_K_M, digest `6488c96fa5faab64bb65cbd30d4289e20e6130ef535a93ef9a49f42eda893ea7`)에 공개 입력을 직접 전달했습니다. temperature 0.1, num_ctx 16384, 출력 4000토큰, 재시도 1회, design_revision false 조건입니다. 시험은 약 169초가 걸렸습니다.

| 문서 | 자동 검사 | 작성 세션의 의미 대조 |
|---|---|---|
| 제품 개요 | 통과 | 정지 시 모든 요청의 자동 완료를 보장하는 표현이 있어 채택하지 않았습니다. 장치 구현자의 완료 의무를 유지해야 합니다. |
| 연동 가이드 | 통과 | completeBuffer의 호출 스레드 계약을 순서·스레드 안전성 보장으로 확장했고, stopDevice의 의무를 관측된 동작처럼 설명했습니다. 채택하지 않았습니다. |
| 지원 범위와 검증 | 실패 | 필수 질문 대신 모호한 설명을 추가한 답변이 차단됐습니다. Invalid·Valid 구분도 빠져 있으며 성능 주제에는 도달하지 못했습니다. |

이 시험으로 모델 연결과 격리된 평가 실행은 확인했습니다. 자동 검사 통과만으로 의미 정확성을 보장하지 못하므로 사내 무인 게시 준비 완료로 판단하지 않습니다. 원고·프롬프트·원응답과 evaluation.json은 로컬 `build/vendor/local-trial`에 보관하며 공개 사이트에는 채택하지 않은 답변을 넣지 않습니다. 시험 당시 개요 전용 프롬프트를 사용했고 이후 같은 제약을 세 Vendor 프로필로 확장했습니다. 확장 프롬프트의 실제 모델 재시험이나 사내 HAL 검증을 완료했다고 주장하지 않습니다.
