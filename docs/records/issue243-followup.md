# #243 후속: 남은 두 지적의 근거 범위를 닫기

이 기록은 #243 완료 당시 남긴 두 `insufficient-evidence` 판정을 후속으로 대조합니다. 과거 실패·판정·영수증과 사람 검토 상태는 덮어쓰지 않습니다. 사내 HAL이나 새 장치 실행의 검증이 아닙니다.

| 대상 | 확인한 원인 | 수정 또는 추가 근거 |
|---|---|---|
| `queueRequestDevice`의 버퍼·파라미터 설명 | 과거 영어의 공동 수식은 후속 공개 main에서 이미 수정됐습니다. 새 독립 CLI 검토는 현재 한국어에도 공동 수식의 모호함이 남았다고 지적했습니다. | 버퍼와 스트림의 관계, 요청에 파라미터 집합이 있다는 관계를 별도 문장으로 구분하도록 공개 예제 질문을 수정합니다. 기존 `reject_patterns`는 확인된 재발 구문 하나를 검사하며 일반적인 의미 검토를 대신하지 않습니다. |
| `queueRequest`의 오류 우선순위 | 구현과 호출부만으로는 생략한 `allowDisconnected` 인자와 오버로드를 확정할 수 없습니다. | `include/libcamera/internal/camera.h:59–65`의 두 선언을 시나리오·제출 검사 질문에 연결하고 해당 공통 계약 감사에도 제공합니다. 단일 State 오버로드의 기본값 false, 연결 검사→상태 검사, 음수 결과의 즉시 전파를 함께 대조합니다. |

실제 공개 기준은 `libcamera-sdd`의 `c3c9fbe3a5bf5fc5fb6c6006ca0f35cba5637325`, 소스는 `be7e83e91348250c015aad6d6f59f1468555bae8`입니다. 원래 분석 소스 293과 이번 다섯 참조 파일의 전체 바이트가 같음을 확인했습니다. 새 클래스 추출을 완료했다는 뜻은 아닙니다.

별도 Codex CLI / `gpt-6.1-terra` / high의 최초 검토는 한국어 모호함을 지적하고 오류 우선순위 설명을 지지했습니다. 첫 보정에도 같은 구문이 남아 해결로 집계하지 않았습니다. 로컬 `reject_patterns` 형식을 잘못 지정한 실패도 별도로 남겼으며, 이후에는 공통 설정 검사를 호출 전에 수행합니다. 최종 단위 보정과 근거 대조 뒤 다른 답변 33개를 보존하고, 문단 경계가 달라진 영어 표시 두 단위를 지정 CLI로 번역했습니다. 별도 최종 검토는 두 대상과 한영 대응을 지지했고 새 지적은 없었습니다.

처음 선택 문서 전체를 새로 생성하려던 실행은 원고 저장 전에 중단했습니다. 원본 293 생성의 주제·체크포인트 식별자를 현재 be7 실행으로 승격하지 않았습니다. 후속 단위 실행은 기존 `_request_unit`·답변 검증·페이지 조립을 사용하며, 다른 답변의 과거 식별자는 유지합니다. 과거 답변을 현재 프로필에서 새로 생성했다고 표시하지 않습니다.

공개 운영 입력에는 기존 `collect`로 얻은 선언 창을 facts에 추가하고 시나리오·제출 검사 계약에 연결합니다. 예제의 다음 정상 추출에서는 각 질문에 연결된 `access-declaration`을 수집합니다. 이미 배포된 원고의 과거 설정과 현재 예제 설정을 같은 실행이었다고 바꾸지 않습니다.

공통 계약 감사·생성기 CI/병합·공개 SDD·Pages·공개 산출물 대조의 최종 결과와 원본은 [#243의 후속 발행 댓글](https://github.com/TTolsun/camera-hal-sdd-generator/issues/243) 및 공개 `publication/issue243-followup`에 연결합니다. 이 기록만으로 사이트 전체 미판정이나 사람 검토의 완료를 선언하지 않습니다. 짧은 두 계약의 차이와 소스 범위는 표로 대조할 수 있어 이 기록의 별도 그림은 생략합니다.
