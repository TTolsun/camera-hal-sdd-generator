# 역할별 작업·의사결정 경로의 공개 사례

같은 요청 처리 근거에서 파트원은 다음 조사 작업을, 기술 의사결정자는 검증의 착수·보류 조건을 찾도록 구성했습니다. [생성기 PR #257](https://github.com/TTolsun/camera-hal-sdd-generator/pull/257)에서 공통 기능을 검토합니다. 실제 사람 평가가 없어 [이슈 #250](https://github.com/TTolsun/camera-hal-sdd-generator/issues/250) 전체는 미완료입니다.

## 기준과 근거 소유권

착수 기준은 생성기 `25f65af`이며 작업 중 main의 `bc58d09`, `dd5daa3` 및 `bc3430b`까지 통합했습니다. 공개 원고 29개와 facts는 실제 공개 기준본의 manifest 해시와 일치함을 확인한 뒤 재사용했습니다. 사실은 `request-lifecycle`의 `journey`, `resources`, `stopping`에서 선택한 분할 답변을 그대로 표시합니다. 별도 상세 원고나 사람 승인 장부를 만들지 않았습니다.

사전 질문·출력 위치·평가 과제는 [공통 계약](../concepts/role-decisions.md), 역할별 순서는 [공개 설정](../../examples/libcamera/reader-paths.yaml)에 있습니다. 기존 Vendor/Developer를 유지하며 사실·가설·미측정 효과·결정 요청을 구분합니다.

공식 upstream과 공개 `upstream/master`에서 확인한 최신 SHA는 `be7e83e91348250c015aad6d6f59f1468555bae8`입니다. facts·원고·이전 실행의 기준은 `293d751a814e0d4c34e85ad457ccd9d5eefd1a61`로 유지합니다. 역할별 경로가 참조하는 주제의 근거 창과 재생성한 Pipeline Handler 네 주제의 창 총 67개를 전체 변경 경로와 대조했으며 해당 라이브러리 소스 창은 변경되지 않았습니다.

새 버전 선언, AGC 초기 추정과 Python 구성 API 변경은 이 대표 요청 경로의 검토 밖입니다. 최신 SHA에서 전체 facts를 다시 추출하거나 카메라를 실행하지 않았습니다. 이전 가상 실행을 새 결과로 바꾸지 않았으며 사내 HAL도 검증하지 않았습니다.

## 독립 검토와 수정

별도 Codex CLI `gpt-6.1-terra`와 `-c model_reasoning_effort="high"`로 구현·근거를 대조했습니다. 입력 한도 초과와 입력 변경 감지로 중단된 실행은 성공으로 집계하지 않습니다. 같은 CLI에서 질문을 분리하고 완료된 체크포인트의 현재 입력·원본 영수증을 대조해 재개합니다.

조사·수정 확인 질문의 연결 부족, 홈 승인 표시 유지 가능성, 답변·용어집 검사 누락, 설정의 Markdown 링크 삽입 가능성을 수정했습니다. 실제 H2 파서와 제목 추출 코드를 포함해 홈 제목도 대조했습니다. 최종 구현 창의 독립 검토에는 추가 지적이 없었습니다. 이것은 사람 승인이나 전체 소스 의미 검증이 아닙니다.

문서 간 대조에서 기존 Pipeline Handler의 “한도 미만” 설명이 원문의 `==` 중단 조건과 맞지 않음을 발견했습니다. 현재 기본 CLI와 집필 규칙으로 네 주제를 재생성하고 주제별 근거 그림 다섯 개를 추가했습니다. 과거 작성자가 Claude였으므로 한 문장만 재사용한 결과로 표현하지 않습니다. 나머지 28개 원고를 보존했으며, 이후 병합된 공개 #243의 Vendor 원고와 추가 사실 하나도 통합했습니다. 모든 기존 facts 항목은 그대로입니다.

독립 원문 검토의 지적에 따라 잠금 반복 전체의 완료, `releaseDevice`·조건부 unlock·감소 순서, 정지 때 `stopDevice` 반환 주체와 미완료 제출 요청의 계약, 입력 탐색의 중첩·감소·재초기화·unsigned 차감식·두 `std::max` 식을 보완했습니다. 마지막 원문 검토의 남은 한 건은 첫 탐색과 재초기화 사이에 순서 간선을 더하자는 탐색성 제안입니다. 현재 노드 문장과 본문은 순서를 명시하며 그림은 중첩 구조와 별도 계산식을 표현하므로, 이 제안을 근거 오류로 집계하거나 반영 완료로 표시하지 않습니다.

실제 독자의 작업 성공 자체가 미확인이라는 문장을 “성공 개선률 미확인”으로 좁힌 번역, 파라미터 집합까지 스트림에 연결한다고 읽히는 영어 번역은 독립 검토 피드백을 넣어 선택 CLI로 수정했습니다. 자리표시자를 반복한 실패 응답은 검증에서 거절하고 새 CLI 실행으로 재시도했습니다.

공통 상세 설명의 큐 취소 조건과 fence 준비 조건에 대한 추가 보완 후보는 별도로 남깁니다. 이번 경로에서 그 상세 문장을 새로 요약하지 않았으며 기존 답변을 그대로 표시합니다. 상세 설명 전체나 #249를 완료했다고 주장하지 않습니다.

## 작성 맥락 없이 읽은 대리 평가

두 평가자는 작성 대화·설정·정답표 없이 사이트와 문서 안의 발췌만 읽었습니다. 두 평가 전후 build ID는 모두 `225175d168e04d8061c94a97f8125f587f54338562a4871ea85b64edc3428c67`로 같았습니다. 이는 계약 대조가 진행 중인 비공개 한국어 미리보기입니다.

| 익명 역할 | 실제 응답과 미발견 사항 | 주관적 관련성 |
|---|---|---|
| 대리 파트원 | 제출 반환값, 준비 대기·장치 전달·완료 반환의 파일·함수·값·분기와 수명·수정 후 확인 위치를 찾았습니다. 실제 장애 입력·기기 구현·담당자·정량 합격선은 확정하지 않았습니다. | 전체 4/5점입니다. |
| 대리 기술 의사결정자 | 기술적 성질과 효용 가설·미측정 효과를 구분하고 착수·보류 선택지·추가 입력을 찾았습니다. 비용·효과 비교와 실제 결정 권한은 미발견으로 남겼습니다. | 과제별 4–5/5점입니다. |

두 평가자는 `request-lifecycle.html`과 `request-diagnosis.html`의 코드 발췌를 대조했습니다. 의사결정자는 홈 아래쪽에서 새 경로를 발견했다고 답했습니다. 이를 반영해 역할별 시작 링크를 첫 기존 H2 앞에 배치하고 H1·기존 카드·안내 그림의 근거를 유지했습니다.

이 점수는 에이전트의 주관적 응답이며 사람의 만족도·작업 성과·기간 단축률이 아닙니다. 실제 비작성자 파트원과 기술 의사결정자 각 1명 이상, 실제 임원 참여 여부는 아직 확보하지 못했습니다. 원본 공개 허락과 익명 응답·오해·관련성을 실제 참여자에게 확인해야 합니다.

## 항목별 시각화 검토

| 항목 | 판정과 이유 |
|---|---|
| `claim-submission` | 짧은 두 문단으로 제출과 완료를 구분합니다. 전체 단계는 기준 문서의 `lifecycle-queue-return-completion`, `waiting-queue-conditions`, `dispatch-cancel-or-device` 그림으로 연결하며 다시 그리지 않습니다. |
| `claim-ownership` | 짧은 유지 책임 설명입니다. 여러 단계의 실제 수명과 실패 예외는 기준 문서의 `request-ownership`과 fence 그림에서 관리합니다. |
| `claim-stopping` | 정지·연결 해제를 한 문단으로 구분합니다. 상세 분기는 `stop-disconnect-contract`, `camera-stop-branches` 그림으로 연결합니다. |
| `claim-value`, `claim-measurement` | 한 문단과 입력·배경 표로 가설·미측정을 구분하므로 그림을 생략합니다. 미관측 효과의 그래프를 만들지 않습니다. |
| `claim-trial`, `claim-adoption` | 착수·보류와 입력은 간단한 표로 충분하여 그림을 생략합니다. 복잡한 기술 실행은 공통 진단 설명·그림을 연결합니다. |
| 역할 질문·입력 목록 | 독립적인 구현 설명이 아닌 짧은 탐색·입력 목록이므로 그림을 생략합니다. 중복 답변은 제목이 있는 링크로 재사용합니다. |

검토 범위는 위 대표 항목과 연결한 근거 창입니다. 공개 사이트 전체의 그림 보완이나 #215 완료를 뜻하지 않습니다.

## 사내 적용과 남은 조건

[사내 양식](../../examples/inhouse-template/config/reader-paths.yaml)은 `ready: false`이며 실제 자료가 없으면 게시를 중단합니다. 사내 문제·소스·빌드·장치·계측·책임·승인 권한·게시 경계·승인된 생성 및 별도 검토 CLI 설정이 필요합니다. 공개 역할·호스팅 방식을 사내 필수 조건으로 강제하지 않습니다.

실제 사람 평가, 사내 HAL 적용, 실제 임원 공감 검증은 미완료입니다. 역할별 설정 자체의 사람 승인을 기록하는 CLI도 아직 없어 `site.require_approval: true`에서는 게시를 차단합니다. 자동 검사·독립 CLI 검토·대리 평가·공개 배포는 각각 구분해 보고합니다.

다음 단계: 실제 참여자에게 [사전 과제](../concepts/role-decisions.md#비작성자-평가의-사전-계획)와 같은 배포본만 제공하고 익명 결과를 기록합니다.
