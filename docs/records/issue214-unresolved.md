확인한 문제는 문서의 조건 누락입니다. libcamera 구현 오류를 발견했다고 주장하지 않습니다. `pipeline_handler.cpp`의 큐 처리·완료·정지·최대 큐 계약, 두 내부 헤더와 `camera.cpp`의 접근·큐잉 구현을 실제 소스 창8개로 제공했습니다. 전체 저장소의 불변식 증명이나 새 실행 시험은 아닙니다.

독립 확인은 지정된 Codex CLI `gpt-6.1-terra` / high로 수행했습니다. 필요한 한 단위의 새 문장은 지정된 Claude Code CLI `claude-haiku-5-5` / high로 생성하고 내부 근거 대조를 수행했습니다. 나머지 접수 설명 두 문단과 전달 주제 네 문장은 그대로 유지합니다. 오래된 전달 단위의 생성 입력을 현재 프로필에 맞는 것처럼 바꾸지 않으며, 원래 모델·정책·입력 지문을 보존하고 현재 소스·계약으로 재검증합니다. 새 생성과 기존 이월은 구분합니다.

해당 질문의 기존 그림은 접근 검사의 음수 반환 시 즉시 종료하는 경계를 올바르게 표현하므로 유지합니다. 세 쟁점의 판정은 표로 비교할 수 있어 이 기록에는 별도 그림을 추가하지 않습니다. 기존 자동 판정과 사람 검토 전 상태를 삭제하거나 승격하지 않습니다.

발행할 때 현재 계약 payload로 새 독립 검토가 필요한 배치와 재검증할 배치를 먼저 계산합니다. 원본 CLI 요청·응답·버전·모델·인자·영수증, 소스 창·해시와 이월/수정 범위는 [공개 후속 패키지](https://github.com/TTolsun/libcamera-sdd/tree/main/publication/issue214-unresolved)에 보존합니다. 병합·CI·정상 export·Pages와 공개 manifest 확인 결과는 해당 PR과 [이슈214](https://github.com/TTolsun/camera-hal-sdd-generator/issues/214)의 후속 기록에 연결합니다.
