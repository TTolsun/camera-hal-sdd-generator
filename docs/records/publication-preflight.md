# 번역 전 표본 검사와 첫 병합 전 통합 시험

기존 검증·실행 기록을 유지하면서 잘못된 표본을 번역 전에 거절합니다. 독립 근거 대조와 최종 한영 사이트 검사를 생략하지 않습니다. 공통 동작은 [발행 입력과 실행 상태](../concepts/publication-inputs.md)를 따릅니다.

## 실행 전에 정한 비교

2026-11-05 KST에 새 native 문서 실행 결과를 보기 전에 다음 범위를 정했습니다. 기존 #241 기록은 그대로 보존합니다.

| 대상 | 확인할 결과 |
|---|---|
| 기존 공개 #241 표본에 없는 canonical 다음 문서 연결을 넣은 복사본 | 실제 번역 CLI가 번역 전에 실패하고 모델 호출 0회·원고·카탈로그 원본 보존을 기록합니다. 복사한 과거 원고를 신규 생성 성공으로 집계하지 않습니다. |
| 정상 공개 표본의 전체 실행 | 새 원고 생성→번역 전 검사→별도 Codex CLI 근거 대조→export→사이트 검사를 연결합니다. 명시적 CLI 대역의 통합 회귀와 native 실행을 구분합니다. |
| 저장 실패를 주입한 통합 회귀 | 이전 원고·사이트·기존 실행 기록을 유지하고 새 실패 기록을 보존합니다. |

새 공개 질문은 `Request::addBuffer()`가 전달받은 fence를 실제로 이동하는 조건입니다. 고정 소스는 `293d751a814e0d4c34e85ad457ccd9d5eefd1a61`의 `src/libcamera/request.cpp:475–505`이며, 전체 거절 검사·버퍼 연결을 통과한 뒤 `fence && fence->isValid()`일 때 `setFence(std::move(fence))`를 호출한다는 창을 대조합니다. 예전 표본이 명시적으로 제외한 이 조건을 별도 소스 근거와 질문별 그림으로 보완합니다. 실패 시 전체 소유권·하드웨어 동작·전체 안내서·사내 HAL 검증은 포함하지 않습니다.

생성·번역은 공개 Codex CLI / `gpt-6.1-terra` / high이며 근거 대조는 별도 검토 설정으로 실행합니다. 지정 CLI 실패를 다른 CLI·직접 API·저장 응답·수동 원고로 신규 성공 처리하지 않습니다. 기존 공개 프로필 한도와 사람 검토 pending 상태는 유지합니다.

측정은 기존 `generation-runs`, 원본 CLI 영수증, 명령 벽시계와 파일 SHA-256을 사용합니다. 과거 #241의 footer 수정으로 추가 번역 1회·4문자열이 발생한 기록과 이번 호출 전 거절을 비교하되, 서로 다른 원고의 시간 차이를 일반 절감 시간으로 바꾸지 않습니다. 전체 CI·사람 조사·외부 대기는 문서 호출 시간과 구분합니다. 표로 비교 가능한 짧은 검증 계약이므로 별도 그림은 생략하며 공개 질문에는 근거 그림을 둡니다.

원본 입력·실행·native 검토·비교·공개 배포 결과는 공개 SDD의 `publication/publication-preflight/` 증거와 연결된 생성기·공개 SDD PR에 보존합니다.
