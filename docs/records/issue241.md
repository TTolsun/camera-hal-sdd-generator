# 이슈 #241 작업 계약과 검증 기록

한 발행 작업의 범위와 기준을 재개 후에도 확인하고, 기준 변경으로 필요한 재검토와 순서 조정으로 예방할 수 있는 재작업을 구분합니다. 공개 libcamera 시험은 사내 HAL 검증 결과가 아닙니다.

## 실행 전에 정한 비교 범위

2026-11-05 KST에 구현·신규 CLI 실행 결과를 보기 전에 다음 범위를 정했습니다. 기준 생성기는 `83c83158dfd1ff876a4c52ae3db8e56fdc1aaae5`입니다. 공개 소스 기준은 `293d751a814e0d4c34e85ad457ccd9d5eefd1a61`이며 공식 upstream의 최신 상태는 별도로 확인합니다.

- 공개 대표 질문은 `camera-requests`의 `Request::addBuffer()` 거절 검사 순서·반환값입니다. 이 질문의 현재 소스 창과 기존 공개 원고를 먼저 대조하고, 독자의 필수 과업에서 확인되는 누락만 보완합니다. 생성·번역·독립 검토의 실제 대상은 호출 전에 별도 입력 목록으로 고정합니다.
- 생성·번역은 독립 Codex CLI / `gpt-6.1-terra` / `-c model_reasoning_effort="high"`를 사용합니다. 독립 근거 검토는 같은 모델·인자를 명시한 별도 검토 프로필과 원본 영수증으로 구분합니다. 기존 한도는 유지하며 새 토큰·호출·시간·분량 한도를 추가하지 않습니다.
- 동일 기준 재개, 선행 정책 미통합, 실행 중 입력 변경, 병행 main 변경, 사용자 범위 추가, 범위 밖 비차단 발견을 통제 시험으로 비교합니다. 테스트 대역을 실제 신규 CLI 검토로 집계하지 않습니다.
- 기존 `generation-runs`의 호출·단계·단위 상태를 사용하여 계획 대비 실행을 연결합니다. 실행 시간 합과 벽시계 경과를 구분하고, 대기·네트워크·작업자 조사처럼 미계측된 시간을 추정으로 채우지 않습니다.
- #242의 검토 재사용 판정과 #243의 반복 실패 진단은 변경하지 않습니다. #215 전체 보완과 #163 전체 독자 평가는 제외합니다. 필요한 차단 결함은 이 제외 범위로 넘겨 성공 처리하지 않습니다.

## 기존 충족 사항과 실제 공백

| 대상 | 현재 보장과 이번 경계 |
|---|---|
| `publication_plan.prepare` | 선택 문서·질문·입력 지문·예상 재사용/생성·이유와 실효 CLI를 기록합니다. 현재 단일 파일을 덮어쓰므로 과거 계획과 범위 변경 이력을 잃습니다. |
| `generation_run.Execution` | `operation_id`별 누적 호출·시간, 단계·단위·실패·30초 heartbeat를 제공합니다. 어느 계획·계약 버전을 실행했는지 연결하지 않습니다. |
| 체크포인트·단계 입력 | 현재 근거·정책과 원본 영수증으로 재검증하고 변경·손상을 거절합니다. 이번에는 판정 알고리즘을 바꾸지 않습니다. |
| 기준 계약·보고서 검사 | 질문/summary/용어/소유권 누락과 보고서 해시·단계·상태·입력 불일치를 호출 전에 거절합니다. 이번 선행 통합 검사도 이 보고서 검사를 재사용합니다. |

기준 회귀는 20건 통과했습니다. 시스템 Python에는 pytest가 없었고 첫 공유 가상환경에는 jsonschema가 없었습니다. 의존성이 갖춰진 기존 b199 가상환경에서 이 작업 트리의 `src`를 지정해 통과했으며 공유 환경을 변경하지 않았습니다. 첫 임시 경로의 부모 디렉터리 누락도 시험 준비 실패로 구분합니다.

## 과거 재작업의 인과관계

[#214 기록](issue214.md)에 따르면 세 원고의 필수 보완과 병행 main 통합 뒤 79개 배치 중 75개 재사용·4개 신규 검토를 했습니다. 이후 임의 기본 분량 제한을 제거하면서 정책 지문이 바뀌어 79개를 새 검토했습니다. 마지막 재검토는 필요한 검증이며, 알려진 정책 수정의 통합을 앞당길 수 있었다면 그 이전의 중복 검토를 예방할 여지가 있습니다. 정책 수정을 언제 처음 확정했는지와 모든 배치의 의존 관계가 충분히 계측되지 않아 절감 시간·임계 경로·79회 전부의 예방 가능성을 확정하지 않습니다. 이후 UI 변경은 신규 호출 0회로 79개를 재검증했으므로 모든 변경이 전체 신규 검토를 유발한다는 가정도 하지 않습니다.

이 기록의 비교 항목은 표로 대조할 수 있어 별도 그림을 생략합니다. 실행 흐름은 [발행 입력과 실행 상태](../concepts/publication-inputs.md)에 연결합니다.

## 구현 중 검증과 미완료 항목

첫 작업 계약·기존 검사 묶음은 16건 통과했고, 기존 변경 행렬과 사이트 검사를 포함한 묶음은 75건 통과했습니다. 이력 삭제·실행 패키지 코드 감시를 보완한 12건, 중첩 프로필·대체 버전·최종 사이트 복구를 보완한 16건도 각각 통과했습니다. 이 수치는 중간 코드의 회귀이며 최종 전체 시험·CI의 통과로 표시하지 않습니다.

독립 Codex CLI / Terra High 코드 검토의 원본 요청·응답·영수증은 실행별로 보존합니다. 검토에서 발견한 실제 공백은 이력 끝부분 삭제 탐지, 중첩 단계 프로필, 최종 사이트 복구의 수명, 실행 중 새 버전 채택, 소스 창 감시, 실제 전달된 transport 설정과 메모리 설정 변경입니다. 기존 exporter의 소스 커밋·원고 지문·근거·영수증 검사를 새 작업 계약 검사가 대신한다고 해석한 지적은 실제 exporter 경로와 회귀로 대조합니다. 자연어 완료 조건을 자동 승인으로 바꾸지 않습니다. 이력 파일의 실행 중 삭제·손상 검사를 포함한 작업 계약 전용 24건은 통과했습니다.

전체 시험의 중간 실행은 추가 코드 검토 지적을 반영하기 위해 이 작업이 시작한 프로세스 트리만 확인·종료하고 원본 부분 로그와 중단 이유를 남겼습니다. 완료된 시험으로 집계하지 않습니다. 샌드박스의 임시 폴더에서 디렉터리를 생성하지 못한 준비 실패 두 건도 보존합니다. 최종 전체 검증은 별도로 필요합니다.

공개 표본은 `examples/libcamera/validation/issue241/prepare.py`로 준비합니다. 원래 공개 facts와 31줄 `addBuffer` 소스 창을 대조하고, 질문·범위·CLI 프로필·그림 근거를 호출 전에 저장합니다. 전체 원고를 이 표본으로 대체하지 않습니다. 실제 `sdd.cli generate --sections camera-requests`는 선행 `policy-ready.json`이 없을 때 실패했고 `generation-runs`의 호출 수는 0회였습니다. 첫 `python -m sdd` 호출은 잘못된 모듈 진입점을 사용한 준비 실패로 따로 보존했습니다. 선행 검사 성공 이후의 신규 생성·번역·독립 검토·재개와 배포는 아직 미완료입니다.

공식 upstream은 `be7e83e91348250c015aad6d6f59f1468555bae8`로 확인·별도 fetch했습니다. 고정 293 이후 변경은 버전, libipa 초기 gain 추정, Python CameraConfiguration 노출의 세 경로입니다. 대표 질문의 `src/libcamera/request.cpp`는 Git diff가 없으며 고정 창의 실제 바이트도 일치합니다. 최신 소스의 실행·전체 사실 추출·사내 HAL 검증을 완료했다고 주장하지 않습니다. 공개 upstream 브랜치 반영과 최종 배포 증거는 후속 단계에서 확인해야 합니다.

통합 회귀 136건은 c29c79d에서 통과했습니다(860.77초). 같은 커밋의 전체 CI는 모듈 순환·설정 스냅샷 경계 두 검사에서 실패했고 Ubuntu 3.11의 나머지 2,663건은 통과했습니다. 보고서 검사를 낮은 계층으로 분리하고 원본 설정 스냅샷 경계를 명시했습니다. 최종 저장 중 버전 채택·다른 발행 작업의 저장을 막으며 기록 저장 실패와 입력 변경 시 복구합니다. 복구 중 사용자가 편집한 사이트 파일은 덮어쓰지 않고 충돌로 기록합니다. 중간 시험 18·19는 이 결함 수정을 위해 자체 프로세스만 종료했으며 완료 시험으로 집계하지 않습니다.

저장 경계·실제 transport·최종 기록 실패의 집중 회귀는 28건 통과했고 테스트의 Path import 누락 한 건은 수정했습니다. 부분 복사 실패 때 기존 파일을 먼저 자르지 않도록 원자적 교체를 적용했습니다. 사용자 편집 보존·복사 실패·의존성 검사 25건이 통과했습니다(1.32초).

초기 source HEAD만 비교하면 수정된 근거 파일을 원래 커밋의 내용으로 표시할 수 있어 선택 근거의 추적 상태·HEAD 대비 차이도 검사했습니다. 해당 결함·하위 소스 디렉터리·ref 패킹 회귀 3건이 통과했습니다(76.61초). 공개 표본은 모델 원고 결과를 보기 전에 한영 계약과 별도 게시 위치를 추가로 고정했으며 원래 준비 입력도 보존했습니다. 전체 안내서의 새 검토·사내 검증을 이 표본으로 대체하지 않습니다.

고정 뒤 새 model을 선택하는 경로는 거절하며 실제 생성·재개와 함께 2건 통과했습니다(60.93초). Git의 assume-unchanged/skip-worktree 표시는 선택 근거의 초기 변경을 숨길 수 있어 해당 선택 입력은 검증 불가로 거절합니다. 플래그를 자동 변경하지 않으며 일반 수정·두 플래그 회귀 3건이 통과했습니다(43.79초). 이 PR의 대체된 CI 실행만 취소해 최신 검증의 대기열 부담을 줄였고 기록은 보존했습니다.

독립 Codex CLI/Terra High 검토 18의 추가 지적은 없었습니다. 이후 검토 결과를 바꾸지 않고 발행 설정 자체의 실행 간 기준을 별도로 점검했습니다. 보고서·공통 라벨·기준 계약·예산 등 publication 설정은 식별자와 계약 파일 위치를 제외하고 입력 기준에 포함합니다. 보고서·예산 변경 시 동일 버전 거절, 명시적 다음 버전 채택의 회귀 2건이 통과했습니다(18.89초). 최종 통합 코드의 공개 선행 조건 재시험도 보고서 누락으로 실패했고 실제 호출은 0회였습니다(명령 벽시계 3.885초).

PR #254는 5821ccd로 병합했습니다. 최종 PR CI(41904992053)는 Ubuntu 3.11/3.14 각각 2,844건, Windows 3.11/3.14 각각 2,843건과 제외 1건으로 통과했습니다. 병합 코드와 시험 head의 파일 차이는 없었습니다. 고정 공개 표본의 첫 실제 Codex/Terra High 생성은 원고 1회·근거 대조 1회, 명령 벽시계 41.722초였고 동일 기준 재개는 추가 호출 0회·9.572초였습니다. 최초 계획은 모두 보존됐습니다. 재개 파일의 차이는 시각과 checkpoint_units 메타데이터였으며, 두 필드를 되돌린 바이트가 최초 저장 해시와 정확히 일치하는 재구성 측정으로 확인했습니다. 이 재구성을 새 CLI 생성으로 집계하지 않습니다. 무기록 질문 변경은 실제 CLI에서 0회 호출로 거절됐고 직전 원고 바이트가 보존됐습니다. 독립 검토 보고서가 없는 조기 export도 거절됐습니다.

번역 준비 중 현재 완료에 필요한 저장 결함을 발견했습니다. 카탈로그 저장이 계약의 저장 경계 밖에 있었고, 번역 호출에 임시 한국어 렌더링 설정이 전달되어 같은 계약의 기준과 달라질 수 있었습니다. 번역에 원래 발행 설정을 전달하고 실제 저장·복구를 계약 경계에 포함하며 외부 편집은 보존하도록 수정합니다. 관련 번역·복구·의존성 회귀 27건이 통과했습니다(11.41초). 번역 호출 전 발견이므로 버린 번역 결과는 없으며, 새 기준·회귀·독립 검토와 계약 버전의 변경 이유를 남긴 뒤 재개합니다.
