# 이슈 #241 작업 계약과 실제 완료 증거

한 발행 작업의 범위·기준·변경 이유를 기존 계획과 실행 기록에 연결하고 실제 생성·번역·독립 검토·재개·배포 경로에서 검증했습니다. 생성기 PR [#254](https://github.com/TTolsun/camera-hal-sdd-generator/pull/254), [#263](https://github.com/TTolsun/camera-hal-sdd-generator/pull/263), [#265](https://github.com/TTolsun/camera-hal-sdd-generator/pull/265)와 공개 SDD [PR #90](https://github.com/TTolsun/libcamera-sdd/pull/90)이 병합됐습니다. [Pages 실행](https://github.com/TTolsun/libcamera-sdd/actions/runs/41923061001)이 성공했고 공개 manifest와 88개 산출물의 해시가 로컬 검증본과 일치했습니다. 공개 libcamera 시험이며 사내 HAL 적용·하드웨어 검증 결과가 아닙니다.

## 기존 기능과 실제 변경

착수 때 최신 이슈·댓글, main·작업 트리·병행 작업과 AGENTS.md·DESIGN.md·site.md·집필 규칙을 읽었습니다. 작업 트리는 깨끗했고 기존 사용자 파일·실행·실패·사람 검토 상태를 보존했습니다. 사용자가 선택한 방향은 작업 계약과 변경 이력입니다.

| 기존 보장 | 이번에 보완한 공백 |
|---|---|
| #214의 publication_plan은 입력 지문·대상·질문·계획을 계산합니다. | 기존 최신 파일을 유지하면서 원래 계획을 불변 보관하고 계약 판본·실행과 연결합니다. |
| operation_id와 generation_run은 누적 호출·시간·단계·단위 상태를 기록합니다. | 범위·완료 조건·선행 변경·소스/생성기 기준·세 역할 프로필·제외·발견 분류와 변경 이유를 판본으로 묶습니다. |

`publication.operation_file`은 선택 기능입니다. 일반 기능은 생성기에, libcamera 입력·준비 도구는 예제에 둡니다. CLI와 impact.json schema 1은 유지했습니다. #242의 재사용 판정과 #243의 실패 진단을 이 작업의 성과로 흡수하지 않습니다. 소스 저장소나 다른 세션을 잠그거나 중단하지 않습니다. 출력 저장 잠금은 협력 실행에만 적용되며 비협력 프로세스에 대한 OS 수준 원자적 비교·교환을 주장하지 않습니다.

실제 번역과 독립 검토에서 현재 완료를 막는 결함 두 가지를 추가로 발견했습니다. 카탈로그 저장·복구를 계약 경계에 넣고 임시 한국어 설정 대신 원래 번역 설정을 전달했습니다(PR #263). 프로필 교체가 로더의 원본 설정 스냅샷을 잃지 않도록 복사 방식을 고쳤습니다(PR #265). 입력 검사를 완화하거나 실패를 저장 응답으로 대체하지 않았습니다. 실행 흐름·스키마·Mermaid는 [발행 입력과 실행 상태](../concepts/publication-inputs.md)를 참조합니다.

## 결과를 보기 전에 정한 공개 비교

초기 생성기 기준은 `83c83158dfd1ff876a4c52ae3db8e56fdc1aaae5`, 고정 소스는 `293d751a814e0d4c34e85ad457ccd9d5eefd1a61`입니다. 신규 성공 호출 전에 `camera-requests/request/buffer-rejection`의 질문·한영 계약·검사·프로필·배포 위치를 고정했습니다. `Request::addBuffer()`의 세 거절 검사·반환값과 setRequest/pending 연결이 대상이며 전달 fence의 이동·실패 소유권은 제외했습니다. 근거는 request.cpp:475–505의 31줄, SHA-256 `c1c0b55f2925856df843fa155a14bb07eb616f52b6bde75cd3b0b5a4ab03b64a`입니다.

기존 공개 facts를 보존하고 이 소스 창을 갱신했습니다. 전체 소스의 새 Clang 추출이나 전체 안내서 보완 완료로 표시하지 않습니다. 별도 경로에 실제 신규 한영 원고와 7노드 근거 그림을 발행했으며 기존 안내서와 검토 상태는 유지했습니다. [사전 비교 계획과 원본 입력](https://github.com/TTolsun/libcamera-sdd/blob/9056546f920c78a28b9992484008a79871752a00/publication/issue241/comparison-plan.json)이 범위의 기준입니다.

생성·번역은 native Codex CLI / `gpt-6.1-terra` / `-c model_reasoning_effort="high"`입니다. 독립 근거 대조는 같은 실효값을 명시한 별도 `review.yaml`과 새 CLI 영수증으로 구분했습니다. 실제 command·model·args·요청·응답을 보존했습니다. 앱·CLI 전역 설정과 기존 사내 선택을 바꾸지 않았으며 새 작업 전체 토큰·시간·호출·분량 한도를 정하지 않았습니다.

선행 통합과 무기록 변경 거절은 이미 수행한 작업을 잃거나 확인되지 않은 기준으로 호출을 계속하는 경로를 막았습니다. 체크포인트 재사용 자체를 새 기능의 절감으로 주장하지 않습니다. 필수 결함과 근거 판정은 최종 차단 조건으로 유지했고, 표본의 비차단 `LLM` 약어 경고는 별도 개선으로 보류했습니다. 경고를 수정 완료로 바꾸거나 관련 없는 전체 품질 작업을 추가하지 않았습니다.

## 검토·회귀·배포 증거

실제 진입점의 통제 회귀는 동일 재개, 선행 정책 미통합, 호출 중 입력 변경과 출력 보존, 병행 선택 ref 변경과 무관 ref 보존, 명시적 사용자 범위 추가, 비차단 후속 발견을 검증합니다. `tests/test_publication_operation.py`의 transport 대역을 실제 모델 검토로 집계하지 않습니다. 공개 native 관측은 별도로 위 표와 원본 기록에 남겼습니다.

최종 기록의 측정·배포 주장도 별도 native Codex CLI/Terra High로 대조했고 지적은 0건이었습니다. [원본 요청·응답·영수증](../libcamera/records/issue241/completion-review-originals.tar.gz)은 별도 보관하며 이 보고서 대조 1회를 문서 생성·검토 13회에 더하지 않습니다. 검토 창 밖의 코드·CI를 새로 검증한 결과로 표시하지 않습니다.

독립 native 코드 검토 19-core·21-translation·22-profiles는 수정 후 추가 지적이 없었습니다. 과거 지적·실패·자체 중단한 부분 시험은 보존하고 완료 검증으로 합치지 않았습니다. 최종 PR CI는 Python 3.11/3.14 × Ubuntu/Windows에서 모두 통과했습니다.

## 여전히 필요한 검토와 측정 한계

실제 근거 창 밖과 전체 안내서는 이번 표본으로 검토 완료되지 않습니다. #215 전체 그림 보완·#163 전체 독자 평가, 별도 메타데이터 용어 보완, 사람의 한영 내용 승인, 실제 사내 소스·구성·하드웨어 검증은 각각 남습니다. 이후 소스·정책·프로필·원고 변경에는 현재 기준에 맞는 재검토가 필요합니다. 이를 현재 필수 결함의 미해결 상태와 혼동하지 않습니다.

[#214 기록](issue214.md)의 75개 재사용·4개 새 검토 뒤 정책 변경으로 79개 새 검토가 필요했던 사실은 유지합니다. 정책 통합 순서를 앞당기면 중복 작업을 줄일 여지가 있지만 언제 확정됐는지·배치 의존 관계·동일 입력 old-generator native 비교가 없어 79회 전부의 예방 가능성·일반 절감 시간·임계 경로를 확정하지 않습니다. UI 변경 후 0회 호출로 79개를 재검증한 기록도 유지합니다.

위 시간은 명령별 벽시계입니다. 부모 준비·하위 번역 journal은 겹치므로 단계 시간 합을 전체 경과로 표시하지 않습니다. 사람 조사·CI와 외부 네트워크 대기 중 명령 밖 구간은 미계측입니다. 최초 재개는 generated_at·checkpoint_units 메타데이터를 바꿨습니다. 최초 파일의 전체 바이트는 당시 저장하지 않아, 저장된 최초 해시에 맞는 두 필드 재구성으로 확인했습니다. 이를 원본 파일 저장·바이트 동일성·새 CLI 생성으로 표현하지 않습니다.
