## 성능 비교의 범위

Windows 11과 CPython 3.14.7의 같은 환경에서 PR69 고정 입력을 사용했습니다. 비계측 벽시계는 개선 전 141.1999초, 개선 후 18.6569초로 7.57배입니다. 별도 cProfile 실행은 각각 453.4652초와 36.5475초이며 벽시계 성능 수치에 섞지 않습니다. YAML `safe_load`는 863회에서 21회, 실제 계약 요청 구성은 15회에서 5회로 줄었습니다. 변하지 않은 섹션 목록은 단계에서 한 번 구성합니다. 다섯 계약 payload의 바이트와 461개 claim의 판정 범위를 대조합니다.

코드 변경은 검토 정책 해시를 바꾸므로 과거 영수증에 새 정책의 승인을 부여하지 않았습니다. 정상적인 새 정책 검사는 과거 보고서를 stale로 거절했습니다. 성능 실험의 `--historical-validator`는 원본 검증기 전체와 정책·영수증을 그대로 두고 입력 준비만 새 구현으로 교체합니다. 모든 기존 계약·원본 응답 검사를 실행하지만, 이 결과는 현재 정책의 신규 검토 통과가 아닙니다. 정상 export에는 별도 Codex CLI의 새 검토가 필요합니다.

통제된 CLI 변경 행렬은 실제 모델 호출 실험과 구분합니다. 동일 입력과 UI 레이블 변경은 생성 0회, 질문 또는 근거 하나의 변경은 대상 생성 1회, summary 추가는 해당 생성 1회와 기존 항목 재검증, 검토 정책 변경은 기존 원고 재검토, 집필 규칙 변경은 해당 원고 재생성으로 연결됩니다. 영향 밖 불필요한 생성은 모든 경우 0회입니다.

## 공개 보완의 경계

공식 upstream HEAD는 `293d751a814e0d4c34e85ad457ccd9d5eefd1a61`로 같았습니다. 현재 공개 #70 입력에서 `Request::addBuffer`의 null stream, 잔존 fence, 중복 stream과 성공 후 연결 경계가 빠진 것을 확인해 `camera-requests.md`만 새로 생성했습니다. 다른 원고 28개는 보존합니다. 검토한 창은 Request의 공개 계약·addBuffer 전체 구현·reuse 근거이며, 나머지 소스나 #215·#163 전체를 검토했다고 주장하지 않습니다.

실행 중 main의 #217·#219·#220을 통합했습니다. 공개 발행 기준은 현재 공개 #70 계약이며 main의 별도 reader 요구 14개 차이는 `main-contract-drift.json`에 명시해 보류합니다. 필수 summary·용어·출력 소유권을 삭제하는 예외를 자동 허용하지 않았습니다. Claude 번역 프로필은 기존 그림 인증용 프로필과 분리하고 실제 CLI 영수증을 유지합니다.

독립 Codex 항목 검토에서 9개 답변의 반복과 4개 항목의 그림 필요성을 확인했습니다. 해당 답변만 새 CLI로 수정하며, 그림은 소스 해시와 유일한 원문 인용에 연결합니다. 짧은 단일 조건 항목은 별도 그림 생략 사유를 검토 기록에 남깁니다.

## 실행별 모델 선택

생성·번역은 독립 Claude Code CLI `claude-haiku-5-5`와 `--effort high --setting-sources project,local`을 사용합니다. 독립 근거 검토는 별도 Codex CLI `gpt-6.1-terra`와 `-c model_reasoning_effort="high"`를 사용합니다. 공개 기본 프로필이나 전역 설정은 바꾸지 않습니다. 설치 확인 결과는 Claude Code `2.1.284`, Codex CLI `0.166.0-alpha.5.1`이며, 설치 확인은 모델 호출 성공을 뜻하지 않습니다.

토큰·시간·호출 예산을 추가로 설정하지 않습니다. 장시간 실행 전에 대상 문서·질문과 신규·재검증·이월 사유를 확정하고 기존 impact·design_reuse·checkpoint·generation_run으로 기록합니다. #215 전체 시각화 보완과 #163 전체 독자 평가는 이 작업 범위에 포함하지 않습니다.

이 문서는 검증 결과를 연결하는 표 중심 기록이므로 항목별 그림을 생략합니다. 변경하는 공개 문서의 독립 항목은 별도 시각화 검토 대상으로 남습니다.
