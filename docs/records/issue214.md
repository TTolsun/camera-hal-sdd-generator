## 같은 입력의 성능

측정 환경은 Windows11, CPython3.14.7입니다. 고정 기준은 생성기 `ea5fa4c1b4eb2748d373cc911c3d4c67e87a93a1`, libcamera `293d751a814e0d4c34e85ad457ccd9d5eefd1a61`, SDD `85b4cd8d6fd9e1778eac3f20cbd0df0e6b8b7cf3`입니다.

비계측 벽시계는 84.9778초 → 11.2212초, **7.57배**입니다. 별도 cProfile은 307.3565초 → 22.9695초입니다. YAML `safe_load`는863회 →21회, 실제 계약 요청 구성은15회 →5회, 동일 섹션 데이터 구성은 단계당1회입니다. API 호출 횟수와 실제 재구성 횟수를 구분합니다.

원래 10월31일 측정(141.1999초 →18.7056초)과 당시 로그도 보존했습니다. 현재 환경에서 전후를 다시 실행한 값을 최종 표에 사용합니다. 전체 발행 시간이나 LLM 시간에 이 비율을 그대로 적용하지 않습니다.

새 코드는 검토 정책 해시를 바꾸므로 과거 영수증에 새 승인을 부여하지 않았습니다. 정상 검사는 stale 보고서를 거절합니다. `--historical-validator` 성능 실험은 원본 검증기·정책·응답·영수증과 모든 기존 검사를 유지하고 입력 준비만 교체합니다. 이 결과는 현재 정책의 신규 검토 통과가 아닙니다. 정상 export에는 현재 정책의 실제 독립 Codex 검토가 별도로 필요합니다.

변경 행렬의 모델 호출은 통제된 CLI 대역이며, 실제 새 문서 생성·독립 검토 성공으로 표시하지 않습니다. 실제 발행에서도 vendor 보완 뒤79개 배치 중75개 재사용·4개 신규 검토를 확인했습니다. 이후 분량 기본값 수정으로 정책 지문이 바뀌어 해당 정책의 검토는 다시 수행하며, 이전 판정은 원본대로 보존합니다.

## 발행 입력과 범위

착수 기준 생성기 main은 `2793c94d7307813ce4effbb24c59eee26999e0e3`이며 기존 작업을 보존했습니다. 병행 PR217·219·220·221을 통합했고 PR222는 별도 작업입니다. 공개 기준은 PR71의 `da29d3eb7f500e5221bd610506ea72639c2bb422`입니다. 해당 공식 cam 문서·근거·번역을 그대로 보존했습니다.

변경 원고는 `camera-requests.md`, `request-lifecycle.md`, `vendor-overview.md` 세 개입니다. addBuffer의 null stream·잔존 fence·중복 stream·성공 후 연결 경계를 보완했고, 독립 검토가 확인한 완료/통지 시점과 대기열 순회 주체의 모순을 수정했습니다. 범용 지원 질문의 근거 없는 전제와 질문별 그림의 누락도 이 범위에서 바로잡았습니다. 나머지26개 원고는 유지합니다.

독립된63개 항목의 그림 필요성과 생략 사유를 기록합니다. 일부 반복·분량 지적과 main의 별도 reader 계약14개 차이는 후속 범위로 남깁니다. #215 전체 그림 보완이나 #163 전체 독자 평가를 완료했다고 주장하지 않습니다. 실제 제공한75개 소스 창과 그 밖의 미검토 범위를 기록합니다.

중단 이후 공식 upstream `df8e348d64b4932a0676256ed24f0da3ee9438bc`를 확인해 공개 `upstream/master`를 동기화했습니다. 변경은 Meson 버전0.7.2→0.8.0 한 줄이며 참조하는 upstream 파일36개의 Git blob이 같습니다. 문서·facts·원래 실측의293기준과 실제 VERSION 값을 보존합니다. 0.8.0 새 빌드·실기기·사내 HAL 검증 결과로 바꾸지 않습니다.

## 분량 처리와 판단

이전 코드의 임의 기본 분량 차단과 공개 페이지별 예외를 제거했습니다. 본문 길이·전체 Markdown 길이·증가율의 기본값은 `null`이며 측정값과 근거·소유권·중복·범위 검사를 유지합니다. 특정 환경에서 명시한 양의 한도는 계속 검사합니다. 이번에 작업자가 선택했던180,000자 예외와 그 정책의 두 export는 철회된 중간 기록으로 보존하고 최종 검증으로 사용하지 않습니다.

독자의 과업과 필요한 조건·예외·책임을 기준으로 분량을 판단합니다. 사내 문서는 별도 프로필로 구성하며 실제 소스와 빌드·CLI 환경을 제공받아 검증해야 합니다. 변경 관련55개 시험은 통과했으며, 최신 전체 CI 결과는 PR의 현재 체크와 공개 패키지에 기록합니다.

## 실제 CLI와 승인 상태

생성·번역은 Claude Code `2.1.284`, `claude-haiku-5-5`, `--effort high --setting-sources project,local`입니다. 독립 검토는 별도 Codex CLI `0.166.0-alpha.5.1`, `gpt-6.1-terra`, `-c model_reasoning_effort="high"`입니다. 실행별 override이며 공개 기본 모델이나 앱·CLI 전역 기본값은 바꾸지 않습니다.

원본 요청·응답·stdout·영수증·버전·모델·인자를 대조합니다. 완료 호출 수에는 거절된 초안·실패 판정·재시도가 포함되며 성공 원고 수와 다릅니다. CLI 실패 원본을 보존하고 다른 CLI·API·저장 응답·수동 원고로 신규 성공을 대체하지 않습니다. 토큰·시간·호출 예산을 임의로 추가하지 않습니다. 자동 검토 상태를 사람 승인으로 전환하지 않습니다.

이 기록은 검증 결과와 증거를 연결하는 표 중심 문서이므로 별도 그림은 생략합니다. [실행·사이트 절차](../concepts/site.md)를 따릅니다.
