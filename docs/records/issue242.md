# 이슈 #242: 변경 이유와 실제 재사용 판정 대조

이 작업은 기존 #214 재사용 경로에 판정 이유를 연결합니다. #214의 영향 밖 신규 호출 0회가 이미 동작한다는 점을 먼저 확인했으며, 전체 재생성이 발생한다고 가정하지 않았습니다. 발행 기준·범위·변경 이력은 #241의 소유 범위입니다. 착수 및 재확인 당시 #241은 열린 상태이고 댓글이 없어 새 공유 계약을 확정하거나 중복 구현하지 않았습니다.

## 재현한 공백과 변경

기준 main `83c83158dfd1ff876a4c52ae3db8e56fdc1aaae5`에서 기존 변경 행렬·사전 검사 11개가 통과했습니다. 질문·근거·집필 규칙 변경은 같은 `no exact completed checkpoint or reusable manuscript` 사유로 표시되었습니다. 질문·근거 변경의 일부 후속 단위는 사전 계획에서 재검증으로 표시됐지만 실제로는 재사용했고, summary 추가에서는 반대 분류가 나왔습니다. 입력이 같은 새 답변이 나올 수도 있으므로 앞선 실행 전에 후속 판정을 확정할 수 없었습니다.

`publication_plan`은 미확정 의존성과 예상 작업을 구분합니다. 기존 `generation_run`의 단위·호출 상태는 유지하면서 사전 예측과 실제 검사·호출 결과를 같은 단위 ID로 연결합니다. 가까운 기록은 해시 차이를 설명하는 비교 자료로만 사용하며, 기존 정확한 요청·소스·모델·인자·정책·원본 영수증 검사가 재사용 여부를 결정합니다. 다른 섹션과 식별 정보가 부족한 과거 기록을 혼동하지 않습니다. 진단의 동시 기록은 기존 실행 잠금으로 직렬화합니다.

문서 간 검토의 의미 정책·요청 payload는 바꾸지 않았습니다. 기존 영수증 경계에서 관측하며 정책 파일을 해시에서 제외하지 않습니다. CLI 사용법과 `impact.json` schema 1, 사람 검토 상태도 유지합니다. [재사용 경계](../concepts/reuse-boundaries.md#실행-전에-예상한-판정과-실제-결과-대조하기)의 그림과 표에서 판정 관계를 확인할 수 있습니다.

추가 경계 시험에서는 Python의 `1 == True` 때문에 JSON 정수·불리언 변경이 같다고 판정되는 문제를 재현했습니다. 유효한 이전 체크포인트를 현재 예상 파일명으로 옮긴 시험에서 기존 식별자 비교가 오래된 정책 입력을 통과시켰습니다. 파일명만 신뢰하지 않고 기존 canonical JSON 해시로 호환 식별자를 다시 비교하도록 수정했습니다. 차이 설명도 같은 비교를 사용합니다. 수정 전 실패와 수정 후 거부 결과, 원본 영수증을 함께 보존했으며 알 수 없는 의존성의 형식 변경도 보수적으로 거부합니다.

## 비교와 실제 CLI의 구분

동일한 두 질문·두 그림·두 번역을 가진 고정 입력에서 동일 입력, 질문, 근거, 번역, 그림, 화면 설정, 결정적 검사 정책, 근거 대조 정책, 전역 집필 규칙, CLI 프로필, 미등록 식별자 입력을 비교합니다. 입력 전체의 해시는 첫 실행·변경 전에 고정합니다. 호출 수 외에도 실제 본문·HTML 변경, 그림의 현재 근거 해시, 번역 변경, 영향 밖 답변·그림 보존, 사이트 검사와 원본 archive 바이트 보존을 확인합니다. 이 행렬의 모든 전송은 테스트 대역입니다.

다음 명령은 지정한 #214 이후 기준 커밋을 별도 소스 트리로 읽고 같은 시험을 전후 순차 실행합니다. 원본 Git ref와 기존 영수증은 수정하지 않습니다.

```powershell
python tools/benchmark_issue242.py --baseline-ref <고정한-기준-커밋> --out <새-비교-디렉터리>
```

실제 공개 libcamera 표본은 분석 커밋 `293d751a814e0d4c34e85ad457ccd9d5eefd1a61`의 `camera.cpp` 두 API 문서 창입니다. 보관 발췌가 원본 Git 파일에 정확히 한 번 존재하고 시작 줄이 일치하는지 먼저 검사했습니다. 생성과 내부 근거 대조는 독립 Codex CLI `gpt-6.1-terra` / high를 실제 실행했으며, 별도 검토 설정의 Codex CLI로 완성된 두 설명을 다시 대조했습니다.

| 실제 실행 | 신규 호출 | 벽시계 | 호출 시간 합 | 같은 품질 검사 |
|---|---:|---:|---:|---|
| 두 질문 최초 생성·내부 근거 대조 | 4 | 21.5656초 | 20.7375초 | 2페이지, 끊어진 링크 0개, manifest 검사 통과 |
| 동일 입력 재개 | 0 | 0.4072초 | 0초 | 같은 검사 통과 |
| 질문 하나 변경 | 2 | 11.2085초 | 10.6669초 | 같은 검사 통과 |

별도 독립 검토는 두 설명의 허용 상태·오류 반환·스레드 안전성 범위가 제공된 API 계약과 일치한다고 판정했습니다. 짧은 검증 표본의 각 항목은 상태·반환값 목록만으로 이해할 수 있어 별도 그림을 생략할 수 있다고 기록했습니다. 이는 공개 문서 전체·실기기·사내 HAL 검증이 아닙니다. 원본 실패·재시도·자동 미판정과 사람 검토 전 상태는 승격하지 않습니다.

## 통합·검증 증거

작업 중 main에 병합된 #244의 그림 확대 계약을 확인하고 통합합니다. 발행 직전 최신 main과 공개 SDD를 다시 대조하며 병행 변경을 보존합니다. 로컬 집중 회귀, 실제 CLI 영수증, 전후 비교 수치와 독립 검토 원본은 공개 #242 발행 증거에 연결합니다. 전체 CI·생성기 병합, 필요한 공개 SDD PR·Pages·공개 manifest와 산출물 확인은 [이슈 #242](https://github.com/TTolsun/camera-hal-sdd-generator/issues/242)의 완료 기록에서 각각 확인합니다. 미완료 실행을 통과로 계산하지 않습니다.

이 기록의 수치·판정·보존 결과는 표로 직접 비교할 수 있으므로 별도 그림을 반복하지 않습니다. 전체 발행 시간에 표본 시간이나 테스트 대역의 비율을 적용하지 않으며 추가 호출 절감을 확인하지 못한 경로에서 절감했다고 주장하지 않습니다.
