# glossary.yaml 참조

**문서에 쓰는 약어와 분야 용어의 뜻을 `config/glossary.yaml`에 한 번만 적습니다.** 사이트를 만들 때 생성기가 문서마다 그 문서에 쓰인 용어의 표를 넣고, 전체 용어를 모은 용어집 페이지를 만듭니다.

## 왜 필요한가

문서는 그 분야를 아는 사람이 쓰기 때문에 IPA, ISP, LSC 같은 약어를 뜻 없이 쓰기 쉽습니다. 처음 읽는 사람은 첫 문장부터 막힙니다. 문장마다 뜻을 덧붙이면 같은 설명이 여러 문서에 반복되고, 뜻을 고칠 때 일부만 바뀝니다. 그래서 뜻은 용어집 한 곳에 적고, 화면에 보여 주는 일은 생성기가 맡습니다.

## 형식

```yaml
terms:
  - term: IPA                          # 문서에 나오는 그대로 적습니다. 대소문자를 구분합니다.
    full: Image Processing Algorithms  # 약어를 풀어 쓴 이름. 없으면 생략합니다.
    definition: >-                     # 한두 문장. 무엇이고 이 코드에서 어떤 역할인지 씁니다.
      화질 알고리즘을 담은 별도 모듈입니다. ...
    aliases: [IPA 모듈]                # 같은 뜻의 다른 표기. 없으면 생략합니다.
common: [API, CPU, YAML]               # 뜻을 풀지 않아도 되는 일반 약어
```

| 키 | 필수 | 뜻 |
|---|---|---|
| `terms[].term` | 예 | 용어. 표의 첫 칸에 표시합니다. |
| `terms[].definition` | 예 | 뜻. 줄바꿈은 공백 하나로 합칩니다. |
| `terms[].full` | 아니요 | 풀어 쓴 이름. 용어 옆 괄호에 표시합니다. |
| `terms[].aliases` | 아니요 | 다른 표기. 이 표기가 나와도 같은 용어로 표에 넣습니다. |
| `common` | 아니요 | 약어 검사에서 뺄 일반 약어. 분야 용어와 사내 약어는 넣지 않습니다. |

같은 이름이 두 용어에 있거나, `terms`와 `common`에 함께 있거나, `term`·`definition`이 비어 있으면 사이트 빌드가 실패합니다.

파일 위치는 기본으로 설정 디렉터리의 `config/glossary.yaml`이고, [`paths.glossary_file`](config.md#output과-paths)로 바꿀 수 있습니다.

## 화면에 보이는 것

1. 각 문서의 요약 문단 바로 뒤에 **이 문서의 용어** 절이 생깁니다. 휴대폰에서도 읽기 쉽게 표가 아닌 목록으로 보여 줍니다. 그 문서의 본문에 나온 용어만, 처음 나온 차례대로 싣습니다. 처음 나온 5개는 펼쳐 두고, 나머지는 접어 둡니다. 그래서 문서의 주제어는 접힌 쪽에 숨지 않습니다.
2. 왼쪽 메뉴의 문서 안내 다음에 **용어집** 페이지가 생깁니다. 모든 용어를 이름 순으로 싣습니다.
3. 원고(Markdown)와 그 내려받기 파일은 바뀌지 않습니다. 용어를 고쳐도 원고를 다시 생성하지 않고 `export-site`만 다시 실행합니다.

## 약어 검사

`export-site`는 코드가 아닌 본문에서 대문자로 시작하고 대문자·숫자로만 된 단어(IPA, IPU3, RKISP1)를 찾습니다. `terms`나 `common`에 없는 약어가 있으면 약어와 문서 이름을 출력합니다.

| 정책 (`site.undefined_terms`) | 동작 |
|---|---|
| `fail` | 게시를 중단하고, 이전에 만든 사이트를 그대로 둡니다. 용어집 파일이 있으면 기본값입니다. |
| `warn` | 경고만 출력하고 게시합니다. 용어집 파일이 없으면 기본값입니다. |
| `off` | 검사하지 않습니다. |

검사하지 않는 부분은 다음과 같습니다.

- 인라인 코드(`` `ISP` ``), 코드 블록, 들여쓴 소스 발췌, 링크 주소
- 클래스 이름처럼 소문자가 섞인 단어(`IPAManager`)와 식별자의 일부(`V4L2_CID`)
- 구성 요소 색인(`kind: per-package`)의 설명 칸. 소스 주석을 그대로 옮긴 글이라서 뺍니다.

약어가 아닌 분야 용어(파이프라인 핸들러, 블랙 레벨)는 자동으로 찾지 못합니다. 처음 읽는 사람이 모를 만한 용어는 직접 `terms`에 추가합니다.

## 검사가 실패하면

1. 출력에서 약어와 문서 이름을 확인합니다. 예: `LSC: ipa.md, ipu3-lsc.md`
2. 분야 용어나 사내 약어이면 `terms`에 뜻을 적습니다. 일반 약어이면 `common`에 추가합니다.
3. 코드 식별자를 본문에 그대로 쓴 경우이면, 원고 설정에서 그 단어를 백틱(`` ` ``)으로 감쌉니다.
4. `export-site`를 다시 실행합니다.

용어의 뜻은 사람이 쓰고 검토합니다. 생성기는 뜻이 맞는지 판단하지 않습니다.
