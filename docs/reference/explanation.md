# 조건 변화와 변경 위험을 연결하는 설명

기존 주제의 `parts`를 문제 → 핵심 원리 → 정상 흐름 → 조건 변화·실패 → 변경 확인으로 묶으려면 선택적 `explanation`을 지정합니다. 소스·질문·필수 용어는 프로젝트 설정에서 정합니다. 생성기는 제품의 설계 이유를 추정하지 않습니다.

```yaml
explanation:
  - {id: problem, title: 독자가 해결할 문제, parts: [problem]}
  - {id: principle, title: 결과를 결정하는 원리, parts: [ownership]}
  - {id: normal, title: 정상 흐름, parts: [normal]}
  - {id: conditions, title: 조건 변화와 실패, parts: [failure, cancellation]}
  - {id: change, title: 변경할 때 확인할 관계, parts: [change]}
```

다섯 단계는 이 순서로 선언하며, 기존 `parts` 전체를 빠짐없이 한 번씩 같은 순서로 소유해야 합니다. 각 질문의 호출에는 전체 질문 묶음과 현재 질문의 담당 범위를 함께 주고, 실제 답변 근거는 해당 part의 발췌로 제한합니다. 같은 전제와 책임을 모든 질문에서 다시 설명하도록 요구하지 마세요. 최종 원고는 단계별 H3 제목으로 조립하고 답변 순서·누락을 다시 검사합니다. 이 계약은 설명의 의미 정확성이나 독자의 이해를 자동 승인하지 않습니다.

단계 제목은 Markdown·HTML 구분자가 없는 한 줄의 일반 텍스트로 지정합니다. 제목으로 본문을 숨기거나 임의 링크·앵커를 삽입하는 입력은 생성 전에 거절합니다.

선언형 소스 근거 그림과 `generation: llm` 그림 모두 `stage: conditions`처럼 단계를 지정하면 해당 단계의 첫 설명 뒤에 배치합니다. 설명 단계는 H3, 그 안의 그림 제목은 H4로 표시합니다. 그림의 `topic`·소스 근거·노드 한도 검사는 그대로 적용합니다. 설명 구성이 있는 주제에서 단계를 생략한 그림은 첫 단계에 배치합니다. 설명 구성이 없는 기존 주제의 그림은 기존 위치와 H3 제목을 유지합니다. 알 수 없는 단계는 모델 호출 전에 거부하며, 명시한 단계 밖에 놓인 LLM 그림은 원고 검사에서 거부합니다. 위치를 바꿀 때는 정상 `generate`로 재조립합니다. 최종 조립본에서는 독립된 각 질문에 필요한 그림 또는 생략 사유를 따로 검토합니다.

항목별 시각화 검사는 H3 설명 단계와 그 안의 H4 그림 제목을 구분합니다. 그림 밖의 독립된 H4 질문도 별도 점검 대상입니다. 한 단계의 그림으로 다른 질문의 충족 여부를 대신하지 않으며, 기존 독자 질문을 그림 제목으로 바꿔 누락 검사를 통과시킬 수 없습니다.

질문·단계·선택 소스가 달라지면 기존 입력 지문이 맞지 않으므로 해당 주제의 재검토·생성이 필요합니다. 같은 입력에서 검증된 원고를 재사용할 때도 답변·근거·단계 순서를 재검사합니다. 모델의 새 추론이 항상 같은 문장을 생성한다는 보장은 아닙니다. 기존 CLI·`impact.json` 형식과 사람 승인 상태는 바꾸지 않습니다.

완료 여부는 사전에 고정한 조건 변화 질문을 작성 맥락 없는 별도 CLI로 풀게 하고, 별도 근거 검토에서 실제 발췌와 대조해 판단합니다. 설계 이유와 대안 비교에는 결정 기록 등 추가 근거가 필요합니다. 공개 사례의 질문과 평가 절차는 [이슈 #249 기록](../libcamera/records/issue249/protocol.md)에 있습니다.
