# 역할별 항목의 소스 근거 그림

`site.reader_paths`가 가리키는 역할별 설정에 `visuals`를 추가하면 해당 질문 곁에 소스 근거 그림을 배치합니다. 기준 원고의 문장은 바꾸지 않습니다. 그림 정의는 기존 질문별 그림과 같은 `schema: 1`, `sections` 형식을 사용합니다.

```yaml
# reader-paths.yaml의 다른 필수 필드는 그대로 유지합니다.
visuals:
  file: reader-visuals.yaml
  placements:
    - role: work
      anchor: claim-ownership
      section: capture
      visual: owner-boundaries
```

`role`은 기존 `work` 또는 `decision`, `anchor`는 그 역할에 실제로 표시되는 `question-<aspect>` 또는 `claim-<id>`입니다. 질문 앵커는 그 질문에서 처음 표시하는 주장의 설명 다음에 배치하는 별칭입니다. 앞서 표시한 주장의 링크만 있는 질문은 로컬 설명이 없어 거부합니다. 그림의 주제와 모든 근거는 실제 그림 앞에 표시되는 그 주장만의 참조 범위에 속해야 합니다. `section`은 그 주장이 근거로 참조하는 기준 문서의 ID이며, 그림의 `topic`·노드·화살표는 그 문서의 현재 소스 창을 사용합니다. 클래스·경로·질문은 프로젝트 설정에 둡니다.

그림 파일에는 각 배치에 대응하는 선언을 정확히 한 번 둡니다. 같은 그림을 여러 역할이나 항목에 반복 배치하여 충족 처리할 수 없습니다. 다른 질문의 일반 그림을 연결하는 설정도 항목 적절성 검토를 대신하지 않습니다.

조립은 기존 소스 핀·인용·노드 한도·한영 라벨 검사와 Mermaid 렌더러를 사용합니다. 첫 설명 다음에 그림을 붙이고, 번호 절차와 들여쓴 후속 문단은 끊지 않습니다. H3 질문 안의 그림 제목은 H4입니다. 소스 근거는 기준 문서의 실제 발췌에 연결하고, Mermaid 원문은 역할별 페이지의 산출물로 함께 만듭니다. 그림 파일 해시는 발행 manifest의 입력에 포함됩니다.

그림·대상 항목·근거가 없거나 오래되었으면 `visuals.on_stale: omit`이어도 발행을 중단하고 직전 정상 사이트를 보존합니다. 설정을 제거하여 그림이 사라지는 변경도 최종 항목별 시각화 검토에서 다시 판정해야 합니다. 소스 연결 검사는 의미 승인·사람 승인·기기 실행 검증이 아니며, 현재 한영 항목의 그림 적절성과 생략 사유를 별도로 검토합니다.
