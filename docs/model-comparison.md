# 같은 근거로 생성 모델 비교하기

**2026-10-01 공개 libcamera 비교에서는 9B로 기본 모델을 바꾸지 않기로 했습니다.** 4B와 9B 모두 설명에 오류나 필수 조건 누락이 남았습니다. 사내 HAL이나 사내 모델을 검증한 결과는 아닙니다.

## 결과와 적용 결정

각 모델에 같은 세 질문을 두 번씩 전달했습니다. 실패한 표본도 모두 보존했습니다.

| 항목 | qwen3.5:4b | qwen3.5:9b |
|---|---|---|
| 자동 검사 통과 | 최초 4/6건, 템플릿 인용 수정 후 5/6건입니다. | 최초와 수정 후 모두 2/6건입니다. |
| 요청·버퍼 수명 | 두 표본 모두 fence 이전 대상을 요청으로 잘못 설명했습니다. | 재사용은 설명했지만 fence 이전 대상과 성공·실패 조건이 빠졌습니다. |
| 오류·종료 | 블로킹 정지를 설명했지만 오류 코드나 복귀 상태가 빠졌고, ‘무작위 노오퍼’라는 표현이 나왔습니다. | 대괄호 인용, 중국어 혼입, ‘중독 호출’이라는 표현과 조건 누락이 있었습니다. |
| IPA 실행 경계 | 직접 호출·블로킹 호출·큐 호출의 예외를 충분히 구분하지 못했습니다. | 동기 호출을 IPC 경로로 일반화하거나 입력에 없는 줄 번호를 인용했습니다. |
| 게시 판단 | 여섯 건 모두 내용 재검토가 필요합니다. | 여섯 건 모두 내용 재검토가 필요합니다. |

자동 통과율은 설명 정확도가 아닙니다. 4B의 잘못된 fence 소유권 설명은 자동 검사를 통과했습니다. 9B도 일부 책임을 명확하게 설명했지만 질문에 빠짐없이 정확하게 답한다는 근거를 확보하지 못했습니다. **기본 모델을 유지하고 비교 원고를 운영 문서로 채택하지 않습니다.** 공개 문서는 소스 근거에 연결한 설명과 추출 사실을 유지합니다.

[소스 대조 기록](../examples/libcamera/validation/model-comparison-20261001/source-review.json)은 에이전트가 모든 표본을 제공된 소스와 비교한 정성 평가입니다. 사람의 승인이나 통계적인 모델 순위가 아닙니다. 소스와의 일치, 조건·책임·경계 설명, 질문의 누락과 근거 없는 단정을 검토했습니다.

## 고정한 조건

소스 커밋은 `d48b72e710fb1a72b0d291b912c179c93619e1d8`입니다. 기존 검증 facts를 재사용하고 같은 커밋에서 근거를 다시 수집했습니다. 질문은 `camera-model/lifetime`, `camera-model/shutdown`, `ipa/execution`입니다. 과거 이슈의 `279d355e` 원고와는 입력이 다르므로, 같은 새 입력으로 4B 기준 표본도 다시 생성했습니다. 별도 공개 사이트 갱신은 더 새 upstream 커밋을 사용합니다.

두 모델 모두 Ollama, temperature 0.1, context 16,384, 출력 한도 1,500토큰, thinking 비활성화, 입력 예산 18,000자를 사용했습니다. 오류 교정 재시도는 0회이며 두 번째 반복에서는 모델 순서를 뒤집었습니다. 입력 facts·발췌 포함 facts·프롬프트의 SHA-256과 모델 digest는 [실행 기록](../examples/libcamera/validation/model-comparison-20261001/result.json)에 있습니다. 모든 응답은 `stop`으로 종료했고 근거 생략은 없었습니다.

기존 설명이나 평가용 정답은 모델에 전달하지 않았습니다. 현재 프롬프트의 두 문단 제한도 유지했습니다. 이 제한이 세부 조건 설명에 충분한지는 별도 실험 대상이며 모델 크기만으로 결과를 설명하지 않습니다. 시간에는 로딩·캐시 차이가 포함되므로 속도 순위로 사용하지 않습니다.

## 비교 중 수정한 결함

인용 검사기가 `.tmpl` 근거를 인식하지 못했습니다. 해당 확장자를 추가하고, 정상 인용 옆의 잘못된 템플릿 인용도 검출하는 회귀 검사를 추가했습니다. 모델을 다시 호출하지 않고 저장된 응답 12개를 재검사했습니다. [재검사 기록](../examples/libcamera/validation/model-comparison-20261001/recheck-result.json)은 최초 결과와 별도로 보관합니다. 새로 통과한 4B IPA 표본도 내용 재검토는 필요합니다.

## 재사용 방법

승인된 엔드포인트를 설정한 `sdd.yaml`과 같은 커밋의 facts·소스 저장소를 준비합니다. 한 번의 비교에서는 같은 Ollama 또는 OpenAI 호환 엔드포인트에서 모델 이름만 바꿉니다. Ollama는 설치된 모델 digest를 기록하며, 다른 엔드포인트의 모델 버전 고정은 별도 확인이 필요합니다.

```bash
python -m sdd.evaluate --config <설정>/sdd.yaml \
  --model <기준-모델> --model <후보-모델> \
  --case camera-model/lifetime --case camera-model/shutdown \
  --case ipa/execution --repeats 2 --out <새-비교-디렉터리>
```

사내에서는 `--case`를 실제 `섹션ID/설계주제ID`로 바꿉니다. 근거 누락·변경·생략은 모델 호출 전에 실패합니다. 기존 출력은 덮어쓰지 않으며 프롬프트가 달라지면 비교를 중단합니다. 통신 오류가 나면 실패를 기록하고 나머지를 계속하며 종료 코드 2를 반환합니다. 종료 코드 0은 비교 실행 완료이며 품질 합격이 아닙니다.

출력에는 facts, 프롬프트, 원본 응답과 서버 메타데이터, 처리 후 본문, 검사 결과가 포함됩니다. 비교 명령은 운영 원고·승인 장부·사이트를 변경하지 않습니다. 사내 산출물은 내부에 보관합니다. 이번 공개 자료는 공개 libcamera 입력만 사용했습니다.

후속 코드 리뷰에서 응답 시간 초과·연결 중단·응답 디코딩 오류도 실패 표본으로 기록하도록 수정했습니다. 인증이 필요한 Ollama의 모델 목록 조회에도 `SDD_AGENT_API_KEY`와 설정한 제한 시간을 적용합니다. 오류 종류만 결과에 기록하며 엔드포인트·토큰·서버 오류 본문은 기록하지 않습니다. 보관 파일을 쓸 수 없는 경우에는 결과 유실을 피하도록 전체 비교를 중단합니다. 이 수정은 위에서 보존한 12개 정상 수신 응답의 비교 결과를 바꾸지 않습니다.

사내 모델 비교는 이번 4B/9B 실험과 별도의 환경 검증입니다. 다음 단계: [사내 적용 절차](inhouse-adoption.md)에서 실제 빌드 입력과 모델 연결 정보를 준비합니다.
