함수 이동의 경우 생성기는 이전 원고의 커밋과 현재 facts 커밋에서 같은 범위의 원문을 다시 읽습니다. 두 범위의 원문이 일치하면 이전 줄 번호로 계산한 입력 지문을 저장된 지문과 대조합니다. 일치하는 기존 답변은 현재 근거와 기존 검증을 통과한 뒤 재사용합니다. 새 원고에는 현재 커밋의 위치와 지문을 기록합니다. 원문을 바꾼 경우와 어느 한쪽 Git 원문을 읽을 수 없는 경우를 회귀 테스트에 포함했습니다.

## 검증 범위와 재실행 절차

1. 각 base와 head를 독립 체크아웃하고 Meson 1.10.1 및 Clang 21로 compile DB와 분석용 헤더를 준비합니다. 이 시험은 `camera.cpp`, `pipeline_handler.cpp`, `request.cpp`, `framebuffer.cpp`, `pipeline/rkisp1/rkisp1.cpp`의 번역 단위와 인용에 필요한 헤더로 범위를 좁혔습니다. 여섯 libclang 추출 모두 파싱 오류 0개였습니다.
2. 기존 `sdd extract`로 두 facts를 만듭니다. 부모 facts에 `sdd generate`를 실행해 기준 원고를 만들고, 원고 복사본을 보존합니다. 독자 질문과 소스 범위는 두 커밋에 같은 설정을 사용합니다. 최신 공개 원고를 과거 코드의 기준 원고로 쓰지 않습니다.
3. head 사실 파일을 사용하는 설정에서 `sdd impact --base <base> --head <head> --base-facts <base-facts.json>`과 `sdd generate --from-impact`를 실행합니다. 동일한 명령을 한 번 더 실행해 원고 본문과 그림의 SHA-256을 비교합니다. 기존 CLI와 영향 보고서의 형식은 그대로입니다.
4. `impact-review.md`에 함수 이동 4개, RKISP1 6개, 공통 정지 3개의 범위 판정이 남았습니다. 이 표본이 선택한 번역 단위와 독자 질문 밖의 같은 파일 심볼입니다. 승인 장부를 변경하지 않았습니다.

생성 및 별도 근거 대조 프로필은 Codex CLI `gpt-6.1-terra`, reasoning effort `high`입니다. 공개 소스와 생성 원고를 대조했습니다. 이 시험에는 장치 관측, 실제 독자 평가, 사람 승인, 사내 HAL 적용이 포함되지 않습니다.
