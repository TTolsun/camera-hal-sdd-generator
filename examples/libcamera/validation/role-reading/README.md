# 역할별 읽기 시험과 생성기의 수정 위치

2026-11-23에 공개 libcamera 소스 `adfa719f8ed67d18fd8a0739fc088a1f8b9e7252`, [배포 커밋](https://github.com/TTolsun/libcamera-sdd/tree/2d323a7cfb446900eabc01ec24956ae949eaf61b/docs), 빌드 `3ac04cb848b7bc188053b46f5f6a156449d59d2a934ee39a6e215585e5c62ff4`를 고정했다. 각 과제는 작성 대화를 공유하지 않은 에이전트 한 명이 해당 역할의 첫 HTML에서 시작해 내부 링크와 소스 발췌만 따라가며 수행했다. 정답표와 다른 역할의 과제는 전달하지 않았다. 자동 판독 결과이며 실제 사람의 이해도나 실기기 지원 여부는 미측정이다.

| 역할과 과제 | 독자가 실제로 찾은 답 | 막힌 위치와 조치 |
| --- | --- | --- |
| 시작하기에서 앱의 카메라와 보드 장치의 관계를 설명하고 첫 촬영 시험을 찾는다. | Architecture의 `#discovery`에서 핸들러의 장치 확보와 카메라 등록을 찾았다. ForVendor에서 장치 연동의 `#first-capture`로 이동해 요청·버퍼 상태와 저장한 센서 영상을 확인해야 한다고 답했다. | 첫 그림에서 등록 시점은 알 수 없었으나 Architecture에서 해결했다. 첫 페이지에 상세 설명을 중복 추가할 필요가 없었다. |
| ForVendor에서 정상 촬영과 미완료 요청 정지 시험을 계획한다. | 요청 제출 회차별 콜백 수와 요청·버퍼 상태를 제시했다. 늦은 콜백과 취소 판정, 정상 요청과 개별 버퍼 오류, 가상 카메라 기록과 고객 보드 실측을 구분했다. | `#adoption-check`에서 첫 촬영·정지 시험과 요청 수명 발췌까지 따라갔다. 과제를 막는 누락을 발견하지 못했다. |
| ForDeveloper에서 스트림 구성 오류가 공통 계층과 장치 구현 중 어디에서 발생했는지 좁힌다. | `#configure`에서 시작해 `troubleshooting.html#configuration-failure`와 발췌를 열었다. 접근 오류, `validate()`의 `Valid` 이외 결과, 구체적 핸들러의 반환값과 스트림 연결 검사를 구분했다. | ‘실패 위치별 확인 순서’를 구성 오류의 후속 절로 이해했다. 본문이 요청 제출 단계로 넘어가자 구성 진단으로 되돌아왔다. 정답 여부만 채점하면 이 우회가 드러나지 않는다. |

개발자 시험 초기에 로컬 복제에서 링크 대상인 시나리오 발췌 파일이 빠졌다. 같은 공개 커밋에서 해당 파일을 보충해 manifest 해시를 확인하고 시험을 이어갔다. 읽기 시험에 사용한 한국어 HTML 31개의 해시가 모두 일치했다.

원본 질문은 요청 제출 실패와 완료 누락을 다룬다. 독자판에서 진단 항목을 한 페이지에 모으면서 범위가 넓은 원본 제목을 같은 수준에 놓은 것이 우회의 원인이었다. 생성기 예제 설정의 `failure-location` 절에 한영 제목을 지정해 목차와 본문에서 증상을 식별하게 했다. 독립 Codex CLI `gpt-6.1-terra` high는 공개된 두 언어의 원문과 새 제목을 대조했고, 양쪽 모두 제출 오류와 완료 통지 누락을 다룬다고 판정했다.

## 같은 과제로 다시 읽은 결과

새 에이전트 세 명에게 이전 답과 수정 내용을 알려 주지 않고 같은 과제를 제시했다. 시작하기 독자는 Architecture의 탐색 절과 첫 촬영 시험에 도달했고, 벤더 독자는 정지 시 미관찰과 취소를 구별했다. 개발자 독자는 구성 진단에서 실제 핸들러의 반환 지점까지 찾았다. 요청 제출 진단으로 우회한 기록은 없었다. 다만 `Adjusted`가 같은 구성 호출에서 수락되는지 잠시 헷갈렸고, 진단 그림과 `Valid` 비교식으로 해소했다. 처음 두 역할은 전후 모두 과제에 성공했다. 개발자 역시 전후 모두 정답으로, 관찰한 차이는 탐색 경로다. 역할별 한 번씩의 시험이므로 이해도나 소요 시간 개선율은 추정하지 않는다.

## 실제 Luna CLI 원고 작성

독자판에 본문을 제공하는 `team-overview`를 같은 공개 소스에서 Codex CLI `gpt-6-luna` high로 새로 작성했다. 응답을 받아도 평가 도구가 CLI 체크포인트와 다른 디렉터리에 실행 영수증을 기록해 원고가 나오지 않는 문제가 재현됐다. 최초 접근 권한 실패와 입력 파일 변경으로 중단된 별도 생성 시도도 있었다.

평가 도구의 CLI 기록 경로를 정상 생성 경로와 일치시킨 뒤 새 출력에서 다시 실행했다. 실제 호출 22회, 원고 1개, SHA-256 `f925b691b504491a3f7566a0444e278a07b3afa7d012a3b230691e05183ef4ed`이며 자동 검사를 통과했다. 독립 Terra High 검토는 네 주제의 핵심 사실이 대체로 맞다고 보았으나, 앱의 설정이 장치로 전달되는 순서, 카메라 제어 독점과 영상 스트림 공유의 차이, IPA가 필요한 조건의 보완을 지적했다. 이 원고는 작성 시험 결과로 보존한다. 공개판에 반영할 변경은 읽기 시험으로 확인한 진단 절 제목이며, 사람 승인과 사내 HAL 검증은 별도다.
