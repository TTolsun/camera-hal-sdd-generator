# 공개 계약 미판정 항목을 보완하기

공개 계약 보고서의 미판정 네 건을 실제 근거와 대조합니다. 한영 중복을 합치면 세 질문 영역입니다. `queueRequest`의 앞선 오류 반환과 분기 도달 조건, 일반 완료와 취소의 호출 의무, 미실시 조사 계획과 코드 사실을 구분합니다. 정답 판정이나 보고서를 수동으로 고치지 않습니다.

`repair_units.py`는 지정된 기존 질문 단위만 Codex CLI / `gpt-6.1-terra` / high로 생성·근거 대조합니다. `--targets` JSON은 `section`, `topic`, `part`를 갖는 객체 목록입니다. 공개 예제용 실행 절차이며 사내 CLI 선택을 강제하지 않습니다.

```powershell
python examples/libcamera/validation/contract-uncertainties/repair_units.py `
  --config <작업 설정.yaml> --targets <선택 단위.json> --out <새 실행 디렉터리>
```

질문의 실제 소스 창과 현재 원고를 먼저 검증합니다. 새 응답은 공통 `_request_unit`의 검증·근거 대조를 통과하고, 공통 체크포인트가 원본 CLI 요청·응답·영수증을 확인해야 합니다. 정상 경로로 재검증한 기존 완료 체크포인트와 신규 호출을 구분합니다. 선택한 CLI가 실패하면 다른 CLI·직접 API·저장 응답을 새 실행으로 대체하지 않습니다.

각 대상은 원래 답변 하나와 정확히 대응해야 합니다. 선택하지 않은 답변과 순서는 보존합니다. 과거 topic 입력 식별자와 생성자는 역사적 값으로 유지하고, 수정 단위는 실제 네이티브 체크포인트·영수증·새 실행 설정에 따로 연결합니다. 새 페이지의 `grounding_review: not-run`은 페이지 전체를 새로 검토했다는 승격을 막습니다. 수정 단위의 근거 대조는 `partial_revision`에 범위를 명시하며, 원래 페이지의 검토 상태는 해시로 묶인 과거 기록에 보관합니다.

원고는 별도 디렉터리에서 조립하고 검증한 뒤 교체합니다. 실패 시 원본과 완료된 네이티브 기록을 보존합니다. 일부 시도의 완료 응답이나 체크포인트 재검증을 전체 새 생성 성공으로 세지 않습니다. 임시 조립물과 과거 시도는 배포 원고가 아닙니다.

변경된 세 페이지는 현재 집필 규칙으로 전체 설명을 별도 검토하고, 영어 변경은 기존 번역 경로로 처리합니다. 현재 입력의 정상 계약 감사·발행 선행 검사·반복 export·사이트 검증을 모두 거칩니다. 독립 역할 평가에는 고정된 사이트와 과제만 제공하고 작성 맥락·설정·정답표는 제공하지 않습니다.

실제 사람·임원 평가와 사내 HAL 적용은 미검증입니다. 자동 미판정 감소는 사람 승인·실기기 성공·개발 기간 단축·ROI의 증거가 아닙니다. 이 절차는 짧은 실행 순서와 원본 참조로 충분하므로 별도 그림을 생략합니다.
